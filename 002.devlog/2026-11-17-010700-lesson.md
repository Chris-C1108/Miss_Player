# 经验教训沉淀 (Lesson Learned): 废弃 UI 开关必须同步收敛读写与同步层自愈 (`v5.7.118-beta.054`)

- **记录时间**: `2026-11-17 01:07:00`
- **关联版本**: `v5.7.118-beta.054`

---

## 核心教训：删除设置项 UI 开关 ≠ 配置已失效

当从设置界面移除某个显隐控制开关（例如 `showProgressBar`、`showLoopControlRow`、`showPlaybackControlRow`、`showSeekControlRow`）使其成为“常驻内置能力”时，如果只删除 UI 控件而未收敛底层状态机与同步链路，会产生不可逆的用户界面丢失（幽灵死锁）：

1. **老用户持久化陷阱**：曾在旧版本将该配置保存为 `false` 的用户，升级后视图渲染代码依然读取该 `false` 并隐藏核心 DOM，导致用户看到“控件凭空消失”，且新版设置面板已无任何入口能重新开启。
2. **跨设备 WebDAV 备份回流陷阱**：即便本地存储修复，若 `SyncManager` 的 `gatherLocalData` / `mergeData` / `applyDataToLocal` 未对该字段做归真拦截，另一台设备或历史云端备份中的 `false` 仍会回流覆盖当前设备。

### 反模式与标准范式

- `FORBIDDEN`: 从设置面板删除某个开关后，只清理 UI 组件代码而保留 `PlayerState` / `UIManager` / `SettingsManager` / `SyncManager` 中的旧配置读取与 `.is-hidden` 切换逻辑。
- `USE`: 下线任何隐式开关时，必须同步执行**四端收敛**：
  1. **读取自愈**：在 `PlayerState.loadSettings()` 与兜底 `SettingsManager.loadSettings()` 中检测到历史非预期值时立即反向 `setValue(..., true)` 自愈；
  2. **视图解除门控**：在 `UIManager` 与 `SettingsManager` 的可见性方法中无条件 `classList.remove('is-hidden')`；
  3. **同步阻断污染**：在 `SyncManager` 的采集、合并、落盘三处统一归真，禁止旧云端快照回写旧状态；
  4. **自动化测试锁死**：在 `tests/player-fixes-verification.test.mjs` 增加静态契约断言，并用 Playwright 预先注入脏 `false` 配置验证端到端自愈。
