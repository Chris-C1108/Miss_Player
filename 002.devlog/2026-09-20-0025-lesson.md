## 1. 平台合规与危机公关经验教训 (GreasyFork Compliance & Crisis PR)

### 踩坑 1.1: 侥幸心理与“虚晃一枪”带来的信誉崩塌
* **教训**：在 5.5 版本中被举报追踪后，曾在讨论区公开承诺“添加默认关闭的开关，并剔除不必要的数据收集”。但在实际代码中，不仅默认值仍为 `true`，且依然保留了 Canvas 设备指纹抓取、番号历史记录并上传到外部服务器。举报者正是抓住这一承诺未兑现的证据再次定点举报。
* **准则**：在成人站点与油猴脚本生态中，**用户对个人隐私具有极高的敏感性与戒心**。对于工具类脚本，任何形式的遥测（即使提供开关）都是一颗随时会引爆的定时炸弹。**“彻底清零并永久停用”是唯一能让审核人员与社区信服的最高解法**。

### 踩坑 1.2: 危机公关核心纪律——行动即公关
* **教训**：技术社区与平台管理员只看代码事实，绝不接受“动机解释”或“情怀小作文”。
* **准则**：遇到举报时，必须严格遵守以下四步 SOP：
  1. **绝对不要在未修改代码前去申诉区争辩**；
  2. **本地彻底清除涉事代码并发布**（推送到 GitHub 触发自动同步更新）；
  3. **携带全新版本号与 Commit 记录**，前往申诉区以清晰客观的英文罗列“整改事实、清除清单、代码开源链接”；
  4. **礼貌申请管理员结案**。

## 2. 构建与语法隐藏深坑 (Build & Syntax Gotchas)

### 踩坑 2.1: 严格模式无分号 ASI 语法灾难
* **现象**：构建产物在浏览器中载入时直接抛出：
  `TypeError: "use strict" is not a function`，脚本首行即崩溃。
* **原因**：`vite-plugin-monkey` 或 Rollup 模板在注入严格模式声明时若输出为：
  ```javascript
  (function() {
      "use strict"(function() { ... })();
  })();
  ```
  在 JavaScript 语法规范中，字符串字面量紧跟 `(` 时，**引擎绝不会进行自动分号补全（ASI）**，而是直接判定为“将字符串当作函数调用”！
* **解决**：在 `vite.config.mjs` 的 `closeBundle` 钩子中增加自动正则修复：
  `code.replace('"use strict"(function', '"use strict";\n(function')`。

### 踩坑 2.2: 泛子域名与根域名匹配盲区
* **现象**：用户在 `https://missav.ai/cn/mism-442-...` 页面无论如何刷新，油猴扩展都不执行脚本，浮动按钮完全消失。
* **原因**：元数据头此前只声明了 `// @match *://*.missav.ai/*`。根据 Tampermonkey 与 Chrome 匹配规范，**带星号的子域名匹配只对二级/多级子域名生效，绝不匹配根域名本身**！
* **解决**：所有站点必须成对声明根域名与泛子域名：
  ```javascript
  // @match *://missav.ai/*
  // @match *://*.missav.ai/*
  ```

### 踩坑 2.3: Babel ES5 降级产生的伪混淆报警
* **现象**：管理员关闭举报时特别附言：*“Note that your script still has some minified variables from the polyfills that are unnecessary in any reasonably modern browser”*。
* **原因**：Babel 默认向 ES5 语法降级，在全局注入了大量类继承辅助函数（`_classCallCheck`、`_typeof`、`_defineProperties`）。这些辅助函数由 Babel 官方编写，内置了单字母变量（`a, e, r, t, o`），极易被平台的代码审计机器人判定为“混淆代码”。
* **解决**：现代油猴扩展均运行在近几年的现代浏览器上，必须将编译目标升级锁定为 **`es2020`**，直接输出原生 ES6+ `class` 与箭头函数，体积暴减 36% 且代码完全通透可读。

### 踩坑 2.4: Node.js VM 沙箱中的定时器挂起与方法缺失
* **现象**：GitHub Actions 跑 CI 时，测试步骤挂起超过 3 分钟最终失败。
* **原因**：
  1. 脚本在初始化时启动了后台保活定时器 `setInterval(..., 30000)`，由于 Node 事件循环持有活动定时器句柄，且脚本末尾未调用 `process.exit(0)`，导致 Node 进程永久等待；
  2. 沙箱中只 mock 了 `log/warn/error`，脚本调用 `console.debug` 时抛出 `TypeError`。
* **解决**：CI 沙箱中 mock `setInterval` 防止创建活动句柄，补齐完整 `console` 方法（含 `debug`、`info`、`trace`），并在所有门禁跑完后显式调用 `process.exit(0)`。

## 3. 微前端与 Shadow DOM 样式强隔离实战 (Shadow DOM Lessons)

### 踩坑 3.1: 样式全量收敛导致 Light DOM 悬浮按钮坠落
* **现象**：重构到 Shadow DOM 后，虽然播放器内部非常完美，但呼出播放器前的常驻悬浮按钮却消失不见。
* **原因**：检查 DOM 发现浮动按钮实际上已被创建，但因为样式表全部通过 `adoptedStyleSheets` 注入到了 Shadow DOM 内部，挂载在 `document.body`（Light DOM）上的浮动按钮丢失了 `position: fixed` 规则，退化为 `position: static`，被原网页内容挤压到了 **`Y = 2915px`（页面最底端）**。
* **解决**：明确 Light DOM 与 Shadow DOM 的边界。对于必须挂载在外部页面的入口元素，通过 `GM_addStyle` 将固定定位（`position: fixed !important; bottom: 30px; left: 50%;`）作为基础骨架注入全局。

### 踩坑 3.2: 播放器重开时的多实例 DOM 叠加
* **现象**：用户多次点击悬浮球打开、关闭、再打开播放器时，画面变黑或设置面板层级错乱。
* **原因**：每次初始化创建了新的播放器实例，如果之前的 `.tm-player-container` 或 `<miss-player-root>` 没有连根拔除，页面上会留存多个暗色遮罩层，层级重叠导致穿透失效。
* **解决**：在核心 `PlayerCore.init()` 第一时间执行严格的单例清理：
  ```javascript
  const existingRoots = document.querySelectorAll('miss-player-root, .tm-video-overlay');
  existingRoots.forEach(r => { try { r.remove(); } catch (_) {} });
  ```

### 踩坑 3.3: CSS 变量在 Shadow DOM 中的渗透
* **教训**：在常规 CSS 中，变量定义在 `:root` 下。但进入 Shadow Root 之后，内部元素并不直接继承外部的 `:root`，导致某些颜色和圆角 fallback 为空。
* **解决**：样式表中必须统一定义为 `:root, :host { --brand-pink: ... }`，宿主和阴影根内部均可无缝读取。

## 4. 架构进化沉淀总结 (Architectural Evolution)

| 阶段 | 传统油猴开发做法 (Anti-Patterns) | 现代化微前端演进标准 (Modern Standards) |
| :--- | :--- | :--- |
| **构建体系** | Webpack 5 + Babel 单体打包，耗时 10s+，无热更 | **Vite + `vite-plugin-monkey`**，耗时 0.7s，极速 HMR |
| **外部依赖** | 盲目 npm install，三方库内联导致产物体积 > 1.3 MB | **原生 Web API 替代（如 Web Audio）**，0 运行时依赖，体积 < 800 KB |
| **界面隔离** | 裸 DOM 注入，靠 `!important` 和高 `z-index` 权重大战 | **Web Component + Shadow DOM + `adoptedStyleSheets`** 双向防火墙 |
| **数据通信** | 等待页面加载后用 DOM 选择器或正则爬取媒体流 | **ES6 Proxy 拦截 `fetch` 与 `XHR`** 底层流媒体嗅探 (MediaSniffer) |
| **状态持久化** | 散落的 `GM_setValue`，多标签页状态各自为政 | **`GM_addValueChangeListener` + Proxy 响应式 Store** 跨窗口热同步 |
| **发版管理** | 本地打包 push 即自动全网发布，推错直接翻车 | **AST 静态合规门禁 + GitHub Actions 标签化 (Tag) 隔离发布** |
