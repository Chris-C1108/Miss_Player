## 💡 核心教训与反模式警示

### 1. 模板字符串内嵌 style 的隐蔽蔓延与治理策略
- **问题表象**：
  在早期的业务快速迭代中（尤其在 `CommentPanel.js` 内部的多状态分支，如 `loading`、`unreachable`、`cf_shield`、`modal`），开发者常常为了方便直接在 JS 模板字面量里写入 `style="display: flex; gap: 5px; padding: 16px; ..."`。
  这不仅绕过了 Shadow DOM 和样式表管理，还使得样式无法通过媒体查询自适应，破坏了动静分离契约。
- **根本解法**：
  必须在 CI 合规门禁（`scripts/compliance-lint.js`）中建立**硬性配额守卫**。通过正则与 AST 双重核验 `style="..."` 的出现频次，将工程基准线严格锁死（当前 ≤ 20 处，主要为真动态数学/颜色插值），杜绝新增，逼迫新增 UI 一律建立纯净语义类。

### 2. 静态 AST 工具链的零额外依赖优势
- **问题表象**：
  最初考虑引入大型 Stylelint 全套规则包，但大型工具链常伴随数十个庞大依赖（`stylelint-config-standard`, `postcss-syntax` 等），极易引入 Node.js 版本兼容性问题（如特定版本缺少 `styleText` 等）并导致 npm install 膨胀。
- **根本解法**：
  本项目本就具备现代构建环境已有的 `postcss` 与 `@babel/parser`。直接使用 `postcss.parse` 遍历 AST，十几行原生代码即可精确测量选择器后代深度与 `!important` 数量，耗时仅数毫秒，零引入外部依赖，稳健且可完全定制。

### 3. 去技术黑话对用户认知负荷（Cognitive Load）的断崖式降低
- **文案反模式**：
  开发者在给用户呈现功能时，往往潜意识地输出自己架构里的抽象名词。例如：
  - 叫“时间胶囊”：用户满头问号，“胶囊”是什么？能吃吗？
  - 叫“纠正时序”：用户需要推理“什么叫纠正？现在是正还是反？点了会怎样？”
  - 叫“快速预览 / 精彩重温”：词语偏虚，缺少对动作结果的明确预期。
- **苹果设计哲学方案**：
  - “时间胶囊” ➔ **高光 / 片段**（直击核心价值）；
  - “纠正时序 / 还原时序” ➔ **转为正序 / 显示倒数**（直接描述操作产生的确定状态）；
  - “快速预览 / 正常模式 / 精彩重温” ➔ **快览 / 正常 / 连播**（强动词驱动，极简有力）。
  全界面文案收敛至 2~4 字，大幅降低了认知阻力，实现真正的《Don't Make Me Think》。

### 4. Node.js 版本运行环境适配认知
- **现象**：
  现代打包器（如 Rolldown / 新版 Vite）在部分打包输出或 CLI 格式化中使用了较新 Node.js 内置特性的 API（如 `node:util` 中的 `styleText`，需要 Node v20.17+ 或 Node v24+）。
- **对策**：
  开发与 CI 执行环境中应优先使用当前 LTS/Active 版本（如 Node v24+），保证现代构建管道畅通无阻。
