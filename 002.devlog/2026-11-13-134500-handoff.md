## 🎯 核心问题与全局调查修复总结

用户在真机实测中反馈三大关键体验缺陷（拒绝 case-by-case 堆砌补丁，执行全局体系化重构）：
1. **BUG 1：section 评论列表未自动加载；懒加载时整个 section 被刷新，导致已展开的长评论瞬间被折叠还原**；
2. **BUG 2：左右滑动 section 切源时呈现空白，必须上下轻微滑动才能唤醒评论展示**；
3. **BUG 3：section 左右边距过大，评论行文本与顶部 Tab 分段栏参考线严重脱节错位**。

### 根因与综合解决方案拓扑

| 问题分类 | 缺陷根本原因 | 架构级修复方案 |
| :--- | :--- | :--- |
| **懒加载折叠还原** | 1. 评论条目升级为 `.jc-stream-row` 后，长评论展开点击中 `closest('.jc-card')` 返回 `null`，导致展开的 ID 从未被 `expandedCommentIds` 记录；<br>2. `patchSectionContent()` 中使用 `.jc-card[data-id]` 查找现有卡片恒返回空，导致增量判定全部失败，退化为 `renderCommentsList()` 全量 innerHTML 重绘；<br>3. `triggerLoadMore` 仍包含失效的 `site.collapsed` 阻断。 | 1. 全局统一使用 `.jc-stream-row, .jc-card` 双向兼容选择器，确保点击时即刻落盘进入 `expandedCommentIds`；<br>2. `patchSectionContent` 正确识别 `.jc-stream-row[data-id]`，通过 `DocumentFragment` 仅增量追加新卡片（`bodyEl.appendChild(fragment)`），**零重绘、零刷新、零滚动跳动，长评论展开状态 100% 完好保留**；<br>3. `triggerLoadMore` 与 `checkViewportFill` 清除过期手风琴折叠阻断，统一由当前激活源驱动。 |
| **切源空白与卡顿** | 1. `setActiveSource(siteKey)` 切换到尚未加载过的源（`status: 'idle'`）时，从未触发 `loadSiteComments`；<br>2. 切源时未复位 `scrollTop`，旧源若滚在 2000px 外，新源内容在顶部 0 处，造成内容在视口外的“假空白”；<br>3. 手势释放时包含 200ms 延迟动画。 | 1. `setActiveSource` 中增加目标源状态自愈检查，若为 `idle` 立即触发 `this.loadSiteComments(siteKey, 1)`；<br>2. 切源时强制执行 `this.commentsList.scrollTop = 0`，保证内容顶格展示；<br>3. `CommentCardRenderer.js` 中为初始未加载态注入 `.tm-comment-loader-graphic` 兜底动画，切源即刻呈现三点跳跃加载，绝不白屏；<br>4. 手势达标后即刻切换归位。 |
| **边距过大与对齐失准** | 外层 `.tm-comments-panel-list.tm-comments-list` 声明了 `padding: 8px 16px 0px 16px;`，而子项 `.jc-stream-row` 自身声明了 `padding: 13px 16px;`，两层叠加导致边距膨胀为 32px；而顶部 `.tm-comment-nav-bar` 仅为 16px 边距，导致上下对齐线严重错位。 | 1. 在 `_comments.css` 与 `_landscape.css` 中将外层滚动列表左右 padding 彻底归零（`padding: 0 0 24px 0` / PC 端 `padding: 8px 0px 0px 0px`）；<br>2. 内容完全由 `.jc-stream-row` 的 16px 内边距与顶部 Tab 的 16px 边线物理共线，实现真正的严格垂直对齐。 |
