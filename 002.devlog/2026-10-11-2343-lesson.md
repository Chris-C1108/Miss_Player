## 🎯 核心问题与设计反思

### 1. 容器包裹重构时的 CSS 包含块 (Containing Block) 陷阱
- **陷阱**：在为 `.tm-control-buttons` 新增父容器 `.tm-control-panel` 时，如果父容器默认设置了 `position: absolute; bottom: 0; left: 0; width: 100%;` 但未声明 `top: 0` 或 `height: 100%`，其内部绝对定位子元素的包含块基准将变成屏幕底部的 0 高度框。此时 PC 端悬浮窗口拖拽计算的绝对坐标（`top: Y px`）将会以屏幕底部为起点偏移，导致面板直接漂移出视口边界。
- **最佳实践**：
  - 在大屏与桌面模式下，外层透明事件穿透容器 `.tm-control-panel` 必须保持 `top: 0; left: 0; width: 100%; height: 100%;`（与主容器同形同域），确保绝对定位子元素的坐标系无缝保持一致；
  - 仅在移动端竖屏媒体查询中，将其转为贴底的块级/自适应高底板（`top: auto !important; bottom: 0 !important; height: auto !important;`）。

### 2. 重构时旧样式表的绝对定位冲突
- **陷阱**：在早期的临时实现中，不同子元素可能分散写在不同的子样式表（如 `_controls.css` 与 `_player.css`）中，且大量使用了带 `!important` 的绝对坐标（如 `left`、`right`、`width`）。在引入 Flexbox 布局进行组件包裹后，旧规则若未被及时清理，就会强行覆盖 Flex 排版属性，导致视觉上的不对称错位或宽度挤压。
- **最佳实践**：
  - 新旧样式交接时，必须以全局 `rg` 检查相关类名的所有样式规则；
  - 一旦布局模型从“各自绝对定位”演进为“父容器 Flexbox 统一排版”，子元素上原有的 `left`、`right`、`position: absolute`、`transform` 等属性必须果断收敛剔除。

### 3. 事件委托与击穿防御同步更新
- **陷阱**：在播放器核心架构中，`UIManager` 为了防止控制栏上的触控事件冒泡至视频层而误触发视频手势（如单机暂停、长按倍速），在事件流最前端使用了 `e.target.closest(...)` 拦截白名单。新增父级组件或辅助立柱时，若漏加新容器名，点击新立柱的空白区域或边缘会直接冒泡到视频包装器，造成“点一下单手切换面板，视频暂停了”的体验 Bug。
- **最佳实践**：
  - 任何新增的外层 UI 容器（如 `.tm-control-panel`）或交互控件，必须立即同步到 `handlePointerDown`、click 判断以及 `mouseenter`/`mouseleave` 事件委托白名单中。
