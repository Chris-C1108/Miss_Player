## 🧠 核心技术陷阱与解决经验

### 1. 评论区时间胶囊的复合交互嵌套与事件冒泡隔离
- **陷阱**：时间胶囊本身绑定了点击事件（跳转视频进度并在控制栏生成草稿），而右上角的加号角标必须支持独立点击（将其直接保存为正式标记）。若加号按钮未阻止冒泡，点击加号会连带触发胶囊本身的跳转逻辑，破坏用户意图。
- **正解**：
  - 角标点击处理中使用 e.stopPropagation() 与 e.preventDefault() 阻断事件向上冒泡；
  - 胶囊采用 position: relative 与 overflow: visible，允许右上角徽标以 top: -7px; right: -7px 溢出显示，避免任何裁剪问题；
  - PC 端采用 @media (hover: hover) 与 :hover 精确触发；移动端通过 350ms 长按定时器赋予 .show-add-badge 显式类名，并在点击非胶囊区域时全局收起。

### 2. 倒数时间与正向时间的双向无损状态流转
- **陷阱**：在对时间区间进行倒数转换时（正向 = duration - 倒数秒数），如果直接覆盖了原始时间戳对象中的数值，用户再次点击按钮想要还原，或者视频时长在元数据加载后发生更精确的修正时，原始数据已经丢失，导致不可逆的换算漂移。
- **正解**：
  - 设计纯函数 applyCommentCountdown(timestamps, videoDuration, enable)，明确区分 rawSeconds（原始识别秒数）与 seconds（当前生效秒数）；
  - 无论在初次解析、自动识别、还是用户手动 Toggle 时，原始秒数始终完好保存在 rawSeconds 中；
  - 当视频真实 duration 就绪触发 reprocessComments 时，先读取上次的切换状态，基于纯净的 rawText 和真实时长重新计算，彻底杜绝数据漂移。

### 3. 从大到小降序时间区间的智能正反序校准
- **陷阱**：倒数区间从大到小（如 27:13 - 15:25，27分13秒为开始，15分25秒为结束）。换算为正向时间后：start = duration - 1633, end = duration - 925。因为 1633 > 925，所以转换后的起始时间必然小于结束时间。如果错误地直接把大值当起点，会导致生成的正向区间变成倒流。
- **正解**：
  - 统一计算：forwardStart = Math.max(0, videoDuration - Math.max(s1, s2))，forwardEnd = Math.max(0, videoDuration - Math.min(s1, s2))；
  - 无论用户输入的倒数区间写法如何，转换后始终保证 forwardStart <= forwardEnd，完美符合正向播放时序。

### 4. 调试语料收集的平台合规红线与私有化闭环
- **陷阱**：为了分析优化时间戳算法，开发者往往容易引入公共收集接口（如 Sentry、Google Analytics 或私有 API），这会直接触犯 GreasyFork / SleazyFork 的“禁止未经披露的负面功能/后门”红线，导致脚本面临下架危机。
- **正解**：
  - 严格依托用户自主配置的私有 WebDAV 服务器，所有语料仅写入用户自己的网盘；
  - 实施严格的双重门禁：必须同时开启设置中的 DEBUG 开关且存在 WebDAV 配置；
  - 物理隔离：使用独立文件 miss_player_comments_debug.json 与 miss_player_countdown_samples.json，与常规配置打点同步文件完全分开；
  - 采用 12 秒防抖缓冲池与两级字典去重，不占用前台主线程，零多余网络请求。
