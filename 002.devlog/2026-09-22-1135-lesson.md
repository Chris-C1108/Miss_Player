## 🧠 核心技术陷阱与解决经验

### 1. 评论区时间胶囊的复合交互嵌套与事件冒泡隔离
- **陷阱**：时间胶囊本身绑定了点击事件（跳转视频进度并在控制栏生成草稿），而右上角的加号角标必须支持独立点击（将其直接保存为正式标记）。若加号按钮未阻止冒泡，点击加号会连带触发胶囊本身的跳转逻辑，破坏用户意图。
- **正解**：
  - 角标点击处理中使用 e.stopPropagation() 与 e.preventDefault() 阻断事件向上冒泡；
  - 胶囊采用 position: relative 与 overflow: visible，允许右上角徽标以 top: -7px; right: -7px 溢出显示，避免任何裁剪问题；
  - PC 端采用 @media (hover: hover) 与 :hover 精确触发；移动端通过 350ms 长按定时器赋予 .show-add-badge 显式类名，并在点击非胶囊区域时全局收起。

### 2. 倒数时间与正向时间的双向无损状态流转
- **陷阱**：在对时间区间进行倒数转换时（正向 = duration - 倒数秒数），如果直接覆盖了原始时间戳对象中的数值，用户再次点击按钮想要还原，或者视频时长在元数据加载后发生更精确的修正时，原始数据已经丢失，导致不可逆的换算漂移。
- **正解**：
  - 设计纯函数 applyCommentCountdown(timestamps, videoDuration, enable)，明确区分 rawSeconds（原始识别秒数）与 seconds（当前生效秒数）；
  - 无论在初次解析、自动识别、还是用户手动 Toggle 时，原始秒数始终完好保存在 rawSeconds 中；
  - 当视频真实 duration 就绪触发 reprocessComments 时，先读取上次的切换状态，基于纯净的 rawText 和真实时长重新计算，彻底杜绝数据漂移。

### 3. 从大到小降序时间区间的智能正反序校准
- **陷阱**：倒数区间从大到小（如 27:13 - 15:25，27分13秒为开始，15分25秒为结束）。换算为正向时间后：start = duration - 1633, end = duration - 925。因为 1633 > 925，所以转换后的起始时间必然小于结束时间。如果错误地直接把大值当起点，会导致生成的正向区间变成倒流。
- **正解**：
  - 统一计算：forwardStart = Math.max(0, videoDuration - Math.max(s1, s2))，forwardEnd = Math.max(0, videoDuration - Math.min(s1, s2))；
  - 无论用户输入的倒数区间写法如何，转换后始终保证 forwardStart <= forwardEnd，完美符合正向播放时序。

### 4. 调试语料收集的平台合规红线与私有化闭环
- **陷阱**：为了分析优化时间戳算法，开发者往往容易引入公共收集接口（如 Sentry、Google Analytics 或私有 API），这会直接触犯 GreasyFork / SleazyFork 的“禁止未经披露的负面功能/后门”红线，导致脚本面临下架危机。
- **正解**：
  - 严格依托用户自主配置的私有 WebDAV 服务器，所有语料仅写入用户自己的网盘；
  - 实施严格的双重门禁：必须同时开启设置中的 DEBUG 开关且存在 WebDAV 配置；
  - 物理隔离：使用独立文件 miss_player_comments_debug.json 与 miss_player_countdown_samples.json，与常规配置打点同步文件完全分开；
  - 采用 12 秒防抖缓冲池与两级字典去重，不占用前台主线程，零多余网络请求。

### 5. 无限滚动列表的局部增量缓存与页码级防重设计 (Page-Aware Feed Cache)
- **陷阱**：如果不记录已加载的“页码集”，仅记录“当前最大页数”，在网络抖动、快速来回滚动、或者用户重开播放器时，极易因异步竞态发起对相同页码的并发请求，造成数据重复或分页跳跃混乱。
- **正解**：
  - 借鉴 React Query / SWR 的 InfiniteQuery 架构思想，引入 collectedPages: Set<number>；
  - 任何发往网络的分页请求必须先过 site.collectedPages.has(page) 门禁；
  - 每次打开播放器优先通过 L1 内存缓存全量瞬时渲染已采集的内容；滚动加载更多时无缝衔接未采集的 currentPage + 1 页，合并后同步刷新缓存，既保障了秒开体验，又完美保留了无限流的增量探索能力。

### 6. 移动端长按抬手误触 Click 与角标悬浮热区断联陷阱
- **陷阱**：在移动端长按唤出角标后，用户手指抬起 (touchend) 会被浏览器自动派发一个原生的 click 事件，导致长按结束后误触时间胶囊自身的跳转逻辑；另外在 PC 端，角标若悬浮在胶囊边界外，鼠标移向加号的途中若经过边界缝隙会导致父元素 hover 丢失，加号瞬间闪退消失。
- **正解**：
  - 在触摸流程中引入 `isLongPressTriggered` 标志位，350ms 长按触发后置 true，在后续的 click 处理器中捕获并精准拦截该次点击，重置标志位，完美保留角标且不误触播放跳转；
  - 彻底移除对带有环境判断误差的 `@media (hover: hover)` 依赖；
  - 为加号角标提供 `::before` 伪元素扩展 6px 透明热区，确保鼠标从文字平滑移至角标的过程中 hover 状态持续稳定。

### 7. 评论缓存为什么绝对不能使用油猴 GM_setValue/storage
- **陷阱**：油猴脚本管理器的 GM_setValue 依赖浏览器扩展的后台进程进行跨页面同步与持久化，通过消息 IPC 强占主进程 SQLite。当评论数量庞大、包含长文本 HTML 与大量番号语料时，高频序列化和 IPC 传输会直接导致油猴扩展进程 CPU 占满崩溃，页面剧烈卡死假死。
- **正解**：
  - 彻底解耦油猴 storage，采用纯浏览器原生异步非阻塞的 IndexedDB 作为持久化底层；
  - 启动时加入自愈检测，发现油猴 storage 中遗留的历史评论键，将其内容安全迁移导入至 IndexedDB，并立即调用 GM_deleteValue 彻底删除旧键释放空间；
  - 搭配 L1 内存 Map 保持页面内零反序列化秒开，彻底消除扩展卡死隐患。

### 8. WebDAV 云端 JSON 脏写/网络截断的自愈防御
- **陷阱**：在多端并发同步或网络突然中断时，云端存储的 JSON 文件偶尔会发生末尾部分截断，直接导致 JSON.parse 抛出 SyntaxError 并彻底锁死同步流程。
- **正解**：在 WebDavClient 中引入截断闭合自愈策略，尝试提取至最后一个有效闭合花括号并重新解析，若结构完备则安全放行并提示，防止全局同步永久卡死。

### 9. 智能括号栈截断修复与多端同步破损恢复
- **陷阱**：在 WebDAV 备份文件达到 1MB（1,048,576 字节）或被服务端/传输层强行截断时，简单的 lastIndexOf('}') 无法修复外层未闭合的嵌套括号，导致连续抛出 SyntaxError，且使客户端陷入无法上传新数据也无法下载旧数据的永久死锁。
- **正解**：
  - 编写基于词法扫描的 tryRepairTruncatedJson，统计未闭合的引号与括号栈，自动补齐闭合标记完成救援；
  - 若数据损毁无法修复，SyncManager 主动触发自愈机制，使用本地健康配置重写云端基线，彻底终结死锁。

### 10. new Set 在对象合并中的指数级雪崩陷阱与自愈防线
- **陷阱**：在多端配置合并时，如果将含有引用类型（如空对象 {}）的数组传入 new Set([...local, ...remote])，由于每次字面量对象的引用不同，Set 无法对对象去重，每一次同步数据量便翻一倍（2^n），几十次同步即可产生近百万个空对象，导致备份膨胀为 8.7MB 并彻底卡死单线程主循环。
- **正解**：
  - 对所有简单数组配置（如步进、标签键名）强制实施白名单校验器，剔除非合法基元类型；
  - 设置硬性安全上限（如 slice(0, 30)）；
  - 对下载到的异常大文件在 JSON.parse 之前做正则流式剔除，并在合并时自动将健康基线写回云端完成自愈。
