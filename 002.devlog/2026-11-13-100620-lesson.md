## 1. 致命反模式：Flex 子项高度循环依赖致 WebKit 高度归零 (WebKit Min-Content Zero Lock)

### 🚨 历史反模式 (FORBIDDEN)
- **现象**：展开评论区分区后，只能看见 header 标题栏，下面的评论条目完全看不见，仿佛空空如也。
- **成因**：
  在父元素未固定绝对像素高度（或者父元素自身是 `overflow-y: auto` 的 Flex 容器）时，将子容器设为 `flex: 0 1 auto; max-height: 100%`，并在孙元素上声明 `flex: 1; min-height: 0; overflow-y: auto;`。
  - 父元素高度依赖子元素内容撑开；
  - 子元素 `flex: 1` 依赖父元素分配空间；
  - WebKit 对带有 `overflow-y: auto` 且 `min-height: 0` 的容器判定其最小内容高度为 0；
  - 这种循环依赖直接导致孙容器的高度被计算为 0px！数千字评论全部被藏在 0px 高度的暗区里！

### 🛡️ 最佳实践与工业级准则 (USE)
- **外层单一滚动条模型 (Single Outer Scrollport Pattern)**：
  - 外层容器 `.tm-comments-list` 既然已经是拥有弹性滚动与安全区内边距的滚动视口，内部子项一律不要创建嵌套滚动容器；
  - 展开的分区内部 `.tm-comment-section-body` 必须声明为：
    `display: flex; flex-direction: column; width: 100%; height: auto; min-height: 0;`；
  - 评论卡片自然流式向下撑开，高度完全由卡片内容决定，由外层统一承载原生流畅滚动，彻底消灭高度为 0 风险与嵌套滚动冲突！

## 2. 致命反模式：Flex 容器缺乏最小高度防压死保护导致折叠成“一条细线” (Flex Zero-Collapse Strip Bug)

### 🚨 历史反模式 (FORBIDDEN)
- **现象**：折叠某分区后，整个卡片连文字都消失了，被压成 0 像素高、仅剩 3px 边框的彩色细线。
- **成因**：
  在父 Flex 容器中，给 `.tm-comment-section` 设置了 `min-height: 0; flex-shrink: 1; overflow: hidden;`，同时 header 自身未锁定高度。当外层 Flex 容器需要分配空间时，由于 `flex-shrink: 1` 且无最小高度阻挡，折叠卡片被无情压缩至 0px，`overflow: hidden` 裁剪掉所有文字！

### 🛡️ 最佳实践与工业级准则 (USE)
- **固定防压死高度与绝对不可收缩 (Rigid Header Defense)**：
  - 任何手风琴卡片根容器必须显式声明：
    `flex: 0 0 auto; flex-shrink: 0; min-height: 38px;`；
  - 卡片头部 `.tm-comment-section-hdr` 必须显式声明：
    `min-height: 36px; height: 36px; flex-shrink: 0;`；
  - 无论父容器 Flex 空间如何挤压，头部始终具有 36px 的不可动摇靶心，标题、图标、徽标永远 100% 完整可见！

## 3. 致命反模式：手风琴全折叠死锁与暴力 innerHTML 重绘 (Accordion All-Collapsed Deadlock & InnerHTML Thrashing)

### 🚨 历史反模式 (FORBIDDEN)
- **现象**：用户在某些场景下打开评论区，所有数据源全部处于折叠状态；点击折叠/展开时，界面发生剧烈闪跳与滚动条重置。
- **成因**：
  1. 将各个数据源的折叠状态独立保存在 localStorage，当某些影片无评论或被连续折叠时，所有源的状态均变为 `'true'`。初始化代码只处理了“全展开”，未处理“全折叠”，导致死锁；
  2. 点击 header 展开时调用 `renderCommentsList()` 暴力重写整个 DOM，导致已有的 DOM 状态被抹除、滚动跳动，并重新触发 `checkViewportFill` 误判。

### 🛡️ 最佳实践与工业级准则 (USE)
- **全折叠自愈与声明式 Class 调度 (Auto-Healing & Class-Only Accordion)**：
  1. 引入 `ensureAtLeastOneSectionExpanded()`：进入评论区时若检测到所有源均处于折叠态，立即按照“有内容者优先（Jable ➔ JavDB ➔ JavLibrary）”的兜底规则激活展开首个可用源，杜绝死锁；
  2. 手风琴展开与折叠一律通过 `classList.toggle('is-collapsed')` 进行纯 CSS 调度，零 DOM 重建、零闪烁、保持原有滚动位置。

## 4. 致命反模式：视口检测对小高度与折叠态无防御导致狂刷请求 (Unbounded Viewport Fill Loop)

### 🚨 历史反模式 (FORBIDDEN)
- **现象**：录屏中 JavDB 评论条数从 153+ 连续暴涨至 213+，无任何用户操作却在后台持续疯狂触发分页请求。
- **成因**：
  `checkViewportFill` 判断 `body.scrollHeight <= body.clientHeight + 10`。在组件刚挂载或高度被压缩异常时，`clientHeight` 极小，该不等式永远成立，形成 `triggerLoadMore -> render -> checkViewportFill -> triggerLoadMore` 的恶性死循环！

### 🛡️ 最佳实践与工业级准则 (USE)
- **三道硬熔断防御 (Triple Viewport Guard)**：
  1. `if (container.clientHeight < 100) return;`：容器未完成真实渲染或视口不可见时，绝对禁止自动触发加载；
  2. `if (container.scrollHeight > container.clientHeight + 20) return;`：只要外层列表已出现滚动条（内容已填满视口），立即退出，严禁提前贪婪预拉取；
  3. `if (!activeSection || activeSection.classList.contains('is-collapsed')) return;`：折叠分区严禁触发加载。
