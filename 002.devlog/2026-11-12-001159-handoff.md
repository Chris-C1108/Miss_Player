## 🎯 本阶段已达成核心成果

1. **真实故障诊断 (`IMG_4752.png` @ `v5.7.118-beta.007`)**：
   - 双端点（`https://dav.loadingi.fnos.net:443` 与 `http://192.168.2.250:5005`）网络实际均已打通且均真实返回 `PROPFIND /backup_configs/MissPlayer/ -> 404` + `MKCOL -> 405`。
   - 结合飞牛 fnOS 官方技术确认与大量实测案例，确立真机常见四大 WebDAV 协议深水隐患：
     1. **fnOS WebDAV 根目录规则与可见范围归零 BUG**：fnOS 严禁在根目录 `/` `MKCOL` 一级文件夹（必定返回 `405`），且升级/重启后会发生「可见文件夹范围」勾选重置，导致前一天可同步的路径次日突变为 `404 + 405`；用户数据实际经常位于 `/我的文件/...` 或特定共享挂载根下；
     2. **协议守卫覆盖不均**：`downloadBackup`、`uploadFile`、`checkFileExists` 原先直调 `request()`，遇路由器 200 HTML 或 502/302 时不会切换 `lanUrl`；
     3. **高并发限频掐断**：`SyncManager`、`HeatmapManager`、`CommentPanel`、`UIManager` 初始化同瞬向 fnOS FN Connect 并发轰炸易触发假性 `401/405`；
     4. **非 ASCII 路径编码盲区**：Safari / Stay 对 `/我的文件/...` 未百分比编码的路径易静默失败；
     5. **`PeachService` / `PeachSection` 校验遗漏**：两处仍直判 `syncWebDav.url`，导致仅配置 `lanUrl` 时降级失灵。

2. **全局底层架构升级 (`src/sync/WebDavClient.js`)**：
   - 新增统一协议守卫 **`_davRequest(options, { throwOn403 })`**：覆盖 `checkDirectoryExists`、`testConnection`、`downloadBackup`、`uploadBackup`、`uploadFile`、`checkFileExists` 全部 WebDAV 子功能，全局识破 HTML 劫持、3xx 重定向与 5xx 网关异常并触发无缝切换；
   - 新增每 Origin 并发队列限流 **`_runWithOriginLimit`** (`MAX_CONCURRENT_PER_ORIGIN = 2`)；
   - 新增 **`_encodePathSegments`** 安全 UTF-8 百分比编码与 **`_parseWebDavChildDirs` / `_listDirectoryDirs` / `_diagnoseDirectoryFailure`**：当 `MKCOL` 无法创建目录时发起 `PROPFIND / Depth: 1` 自检服务器真实可见根目录，智能识别「可见范围为空/已重置」、「实为 `/我的文件/` 子目录」、「大小写不匹配」或「只读权限」；
   - 新增无末尾斜杠 `PROPFIND` 207 容错、`clearEndpointLease()` 及双端同源错误去重汇总。

3. **全库收口与防御加固**：
   - `src/services/PeachService.js` 与 `src/player/managers/settings/sections/PeachSection.js` 补全 `WebDavClient.hasValidEndpoint(syncWebDav)` 收口；
   - `src/sync/SyncManager.js` 与 `PeachService.saveConfig` 在端点或用户名变更时自动调用 `WebDavClient.clearEndpointLease()`；
   - `src/player/managers/SettingsManager.js` 状态条改用纯节点 `replaceChildren` 消除 DOM 注入风险。
