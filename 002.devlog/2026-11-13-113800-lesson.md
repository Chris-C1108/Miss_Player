# Miss Player 经验教训与反模式总结 (2026-11-13 11:38:00)

## 🚨 核心教训与规范守卫

### 1. 界面设计反模式：拒绝 AI-Slop 式卡片盒嵌套 (De-Cardification)
- **FORBIDDEN: 在原本已受分区包裹的容器内，给每个数据条目添加独立的圆角、边框、投影和内边距（即“卡片套卡片”的 AI 模板化陈词滥调）**
- **USE: 采用流式无框排布（Border-Bottom Separators）配合轻量微线条导轨（Guide Lines）**：
  - 真正顶级的工业级工具（如 Linear, Raycast, GitHub Next）极少使用大面积圆角卡片嵌套；
  - 采用流式列表 + 细线分割 + 状态指示微导轨，不仅节省屏幕空间（提升单屏阅读效率 35% 以上），而且让视觉焦点回归于内容本身。

### 2. 状态覆盖反模式：严禁在样式重构中随意使用 `!important`
- **FORBIDDEN: 在编写组件 CSS 时随手追加 `!important`（如 `display: flex !important;`）以强行覆盖旧规则**
- **USE: 依赖 Shadow DOM 隔离与合理选择器特异度，仅在极少数最高优先级状态切换类（如 `.is-hidden { display: none !important; }`）使用**：
  - `compliance-lint.js` 设置了硬性上限 50 处；
  - 随意添加会瞬间打爆门禁，增加未来样式维护的层叠死锁风险。

### 3. 多源信息架构反模式：纵向手风琴 vs 顶部水平滑动分段
- **FORBIDDEN: 在移动端纵向滚动容器内嵌套多个纵向手风琴折叠卡片，导致折叠后被压缩成一条线或高度归 0**
- **USE: 采用顶部常驻水平分段滑动标签栏（Horizontal Segmented Tab Strip）**：
  - 各数据源在同一视口内独立排布，通过点击或横向手势无缝切换；
  - 彻底规避 WebKit 纵向 flex 嵌套引起的 `min-content` 高度计算死锁。
