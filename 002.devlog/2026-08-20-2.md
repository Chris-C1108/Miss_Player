## 1. 核心任务与重构工作概览

本阶段围绕 **Miss Player** 播放器核心的模块化重构、移动端极端交互与多端排版适配，完成了全方位的深度治理：

### 1.1 架构解耦与工厂化重构 (Codebase Architecture Improvement)
1. **纯 DOM 构建工厂提取 (`src/player/ui/_uiFactories.js`)**：
   - 将 `UIManager.js` 中数百行凌乱的纯 DOM 构建逻辑（遮罩层、视频容器、主播放器容器、拖动手柄、标题栏、设置面板）完整解耦为纯函数/工厂函数，极大提升了 `UIManager.js` 的可读性与单测可行性。
2. **打点抽屉与模态逻辑解耦 (`src/player/managers/MarkerBottomSheet.js`)**：
   - 将原散落在 `LoopManager.js` 中的打点列表抽屉（Bottom Sheet）、片段管理模态框、DOM 绑定及历史打点渲染逻辑独立成专门的 `MarkerBottomSheet` 管理类。

   - 将原 `CommentPanel.js` 中繁重的评论发表表单、多选打点标签注入（Tag Picker）、时间戳插值校验、多平台登录弹窗与快捷发表交互彻底剥离为独立的 `CommentComposer`。

## 3. 核心踩坑教训与实战经验总结 (Lessons & Best Practices)

### 3.1 【踩坑 1】iOS Safari WebKit 的「16px 字号自动放大」强行规则
* **现象**：
  在 iPhone Safari 上点击输入框（如打点备注、评论），整个网页瞬间被放大，且由于播放器拦截了默认触摸手势（`touch-action: none` / `pan-y`），用户双指捏合无法还原，UI 彻底被毁坏。
* **教训**：
  * iOS Safari 存在硬编码逻辑：只要 `<input>` / `<textarea>` 的计算字号 **小于 16px**（如 12px、13px、0.82rem），Safari 便强行触发自动视口居中放大。
* **终极避坑经验**：
  * 在移动端/触控媒介查询（`@media (max-width: 1024px), (pointer: coarse)`）下，**所有输入控件的 `font-size` 必须一律声明为 `16px !important;`**。
  * 16px 符合 iOS 人机交互指南（HIG），且能 100% 免疫 WebKit 聚焦自动缩放。

### 3.2 【踩坑 2】`touchstart` 阶段调用 `preventDefault()` 导致事件链断裂
* **现象**：
  为了实现点击评论区收起播放控制面板，在评论面板的 `touchstart` 处理器中执行了 `e.preventDefault()`，结果导致点击评论输入框无法聚焦、点击加号按钮无法触发点击事件。
* **教训**：
  * 移动端浏览器中，`touchstart` 处于原生手势最顶端。一旦在 `touchstart` 调用 `preventDefault()`，WebKit 将直接扼杀后续派发的 `focus`、`click`、`mousedown` 等一系列事件。
* **终极避坑经验**：
  * 在手势拦截前，**务必对交互型子控件（`input`, `textarea`, `button`, modal）进行白名单豁免**；
  * 对表单交互区域放行原生事件，仅在纯背景区域执行 `preventDefault`。

### 3.3 【踩坑 3】`body` 宿主未完全隐形导致软键盘弹起时光标居中滚动露底
* **现象**：
  播放器本身是全屏固定定位（`position: fixed`），但当虚拟键盘打开触发原生居中滚动时，背景原站的 `h1`、正文等内容被意外推入视野。
* **教训**：
  * 仅隐藏原站的 `header` 和 `navbar` 是远远不够的。在 iOS 上，只要 `body` 还有其他子节点存在于渲染树中，视口滚动就会导致宿主内容在 fixed 层边缘缝隙或重排过程中瞬间露底。
* **终极避坑经验**：
  * 当播放器激活（`body.tm-player-active`）时，通过深度选择器：
    ```css
    body.tm-player-active > *:not(.tm-video-overlay):not(.tm-player-container):not(.tm-floating-button):not(script):not(style):not(#tm-hide-scrollbar-style) {
        display: none !important;
    }
    ```
    物理隐藏宿主 DOM 树上的所有其他兄弟节点，彻底根除露底隐患。

### 3.4 【踩坑 4】移动端固定高度容器与虚拟键盘重叠冲突
* **现象**：
  竖屏下视频容器由 JS 设定了 `550px` 高度，而 iPhone 可视区在键盘弹出后仅剩 `500px` 左右，导致视频容器占满了全部剩余高度，将底部的评论输入栏挤压或遮盖。
* **终极避坑经验**：
  * 借助 `window.visualViewport` 动态计算 `--keyboard-height`；
  * 配合 CSS `flex-shrink: 1` 与 `max-height: calc(100dvh - var(--keyboard-height, 0px) - 130px) !important;` 实现视频画面的弹性自动缩减，给输入栏保底留出视口空间。

### 3.5 【踩坑 5】多层定位组件的 Z-Index 体系混乱
* **终极体系规范**：
  * **底图与容器**：`.tm-video-overlay` (2000000000) -> `.tm-player-container` (2000000001)
  * **视频与手柄**：`.tm-video-container` (9985) -> `.tm-handle-container` (9986)
  * **评论与列表**：`.tm-comments-panel` (9990) -> `.tm-comments-panel::after` (9993)
  * **控制与交互**：`.tm-control-buttons` (9997) -> `.tm-comment-tag-select-modal` / `.tm-inline-remark-popover` (9998)
  * **全局顶层模态**：`.tm-floating-comment-panel` / `.tm-settings-modal` (10000+) -> `.tm-button-container` (99999)
