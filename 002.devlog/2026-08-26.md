# 开发日记 — 2026年8月26日

## Miss Player WebDAV 多端 CRDT 智能同步引擎构建、Safari 全屏劫持与 Chrome DevTools 性能全链路调优

---

## 1. 核心任务与架构演进概览

本阶段围绕 **Miss Player** 的云端跨端配置同步（WebDAV CRDT 引擎）、Safari 移动端原生交互漏洞攻坚、广告弹窗拦截体系以及基于 **Chrome DevTools Performance Trace** 的全链路渲染性能调优，完成了重大架构演进与版本迭代（`v5.6.0` -> `v5.6.7`）：

### 1.1 WebDAV 多端分布式 CRDT 智能合并同步引擎 (`src/sync/`)
1. **Schema v2 规范与 LWW 冲突解决**：
   - 设计并落地基于 **LWW-Element-Set (Last-Write-Wins)** 的分布式数据合并机制，支持字段级时间戳合并；
   - 引入 **30 天墓碑机制 (Tombstones)**：记录用户删除打点（`markers`）、自定义步进（`customUserSeekSteps`）以及已清空视频的删除时间戳，彻底根除了“设备 A 删除了打点，设备 B 同步时又将打点复活回流”的经典多端同步冲突。
2. **多形态终端布局独立隔离 (Device Form-Factor Isolation)**：
   - 区分 `desktop`、`mobile`、`tablet` 终端形态，将侧边栏停靠方向（`sidebarPosition`）与收起状态（`sidebarHidden`）按设备类型独立保存，实现“PC 端展开右侧栏，手机端保持精简单手模式”互不干扰。
3. **全自动无感同步与实时刷新 (`mp_sync_applied`)**：
   - **数据变更防抖同步**（3s debounce）；
   - **页面唤醒与焦点切回同步**（`visibilitychange` / `window.focus`）；
   - **后台 25 秒轻量心跳轮询 (`startPeriodicSync`)**：两端同时播放同一视频时，25 秒内自动拉取合并远端打点，并派发全局事件驱动进度条与标签药丸实时热重载。
4. **WebDAV 直连协议客户端 (`WebDavClient.js`)**：
   - 彻底废除脆弱且易在部分 WebDAV 服务端（坚果云、Alist、Nginx WebDAV）挂起的复杂 `PROPFIND` 递归；
   - 采用标准 `GET` 下载、`PUT` 上传与 404/409 目录自愈创建机制；
   - 全链路接入 12 秒严格超时熔断、`onabort` 监听与全量 `try...catch` 保护。

### 1.2 Chrome DevTools 性能全链路调优 (Performance & INP / LCP Optimization)
1. **非关键增强功能空闲化调度 (`requestIdleCallback`)**：
   - 将 `DetailExpander.autoExpandDetails()` 与 `QualityManager.setupAutoHighestQuality()` 全面改造为 `requestIdleCallback`（带 3.5s 保底 timeout）调度，彻底移出关键渲染路径（Critical Rendering Path），杜绝阻塞视频封面海报（LCP 元素）渲染。
2. **DOM 批量清理与选择器合并**：
   - 在 `AdBlocker.domCleaner` 中将十余个离散的 CSS 选择器合并为单次 `querySelectorAll(combinedSelector)`，减少 90% 的 JS -> C++ DOM 跨边界遍历开销。
   - 去除原先每 2 秒一次的高频全页面 `setInterval` 轮询，改由 `MutationObserver` 事件驱动 + `requestIdleCallback` 低优先级兜底。
3. **主线程初始化链路解耦**：
   - 将 `initAutoLogin` 从同步 `await` 拆解为非阻塞 Promise 异步并发，避免阻塞后续微任务队列。

## 2. 核心缺陷排查与攻坚矩阵

| 缺陷模块 / 场景 | 现象与根因 | 状态 | 关键解决技术 |
| :--- | :--- | :---: | :--- |
| **首屏渲染延迟阻塞 (LCP 2610ms)** | `startScript` 同步执行 `autoExpandDetails` 触发 `a.click()`，导致 130ms+ 强制样式重算与布局抖动 | ✅ **已解决** | 将详情展开与画质设置移入 `requestIdleCallback`，避让关键渲染帧 |
| **WebDAV 4 按钮卡在执行中** | 底层 `GM_xmlhttpRequest` 缺少 `onabort` 与异常捕获，且 `PROPFIND` 无 Body 导致部分服务端挂起 | ✅ **已解决** | 直连 `GET`/`PUT`、12s 超时熔断、`onabort` 捕获及 `_lastWebDavStatus` 状态徽标持久化 |
| **双端同时播放无法实时同步** | B 端播放时若不刷新页面或切后台，没有后台定时器检测云端更新 | ✅ **已解决** | 引入 `startPeriodicSync` 25s 轻量心跳轮询，配合 `mp_sync_applied` 事件实现实时热更新 |
| **Safari 启动视频弹广告** | `FloatingButton.js` 中 `hostPlayBtn.click()` 触发了 MissAV 挂在原生 Plyr 按钮上的广告劫持监听 | ✅ **已解决** | 彻底移除宿主按钮点击，仅调用底层 `video.play()`，并在 `document-start` 极早劫持 `window.open` 与 `<a>.click` |
| **Safari 退出重进自动全屏** | 退出播放器时移除 `playsinline` 属性，导致二次点击浮钮调用 `play()` 时触发 iOS Safari 系统强制全屏规则 | ✅ **已解决** | 退出时永久锁定 `playsinline="true"` 与 `playsInline=true`，并在起播与挂载时加入 `webkitExitFullscreen()` 守卫 |
| **多端删除打点后再次复活** | 合并数据时仅做 `Union` 并集，一端删除的数据在另一端被识别为新增并写回 | ✅ **已解决** | 建立 Schema v2 墓碑机制（Tombstones），记录 30 天删除元数据并在合并阶段严格过滤 |
| **空 WebDAV 服务端写入失败** | 初次配置 WebDAV 时目标目录尚未创建，直接 PUT 返回 404/409 报错 | ✅ **已解决** | 在 `uploadBackup` 遇到 404/409 时自动触发 `MKCOL` 递归补建目录并二次重试 |
| **浮动模式下视频点击无法暂停** | `UIManager.js` 的 `videoWrapper` 点击处理中存在 `if (isFloating) return;` 误判阻断 | ✅ **已解决** | 移除阻断判断，统一通过内部 `togglePlayPause()` 同步控制栏状态与自动隐藏计时器 |

## 3. 经验总结与踩坑教训 (Lessons Learned)

### 3.1 【性能教训】首屏初始化严禁在关键路径上触发可能引起 Forced Reflow 的 DOM 操作
* **现象与 Trace 数据**：
  Chrome DevTools Performance Trace 发现页面 LCP（最大内容绘制，即视频海报）耗时 2,610ms，其中 **84.7% (2,211ms)** 为 Render Delay。Trace 调用栈精确定位到一个耗时 158ms 的长任务：`startScript` -> `autoExpandDetails` -> `HTMLAnchorElement.click()`。
* **深层根因**：
  在页面刚加载、浏览器正在解析 DOM 和等待图片渲染时，脚本同步调用了宿主折叠面板的 `click()`。该点击触发了宿主页面的 Alpine.js/Vue 监听器，执行了大量的 DOM 展开计算，引发了耗时 26.3ms 的 `Recalculate Style` 和 101.2ms 的 `Layout` 强制重排（Forced Reflow），直接推迟了 LCP 绘制与用户交互响应（INP）。
* **终极经验**：
  * **非核心视觉功能一律延迟到浏览器空闲期（`requestIdleCallback`）**；
  * 在页面加载关键帧期间（`DOMContentLoaded` 前后），严禁模拟触发宿主任何包含动画或大面积 DOM 展开的 `click()` 事件。

### 3.2 【踩坑 2】iOS Safari 的「无 playsinline 播放必全屏」强制规则
* **现象**：
  退出 Miss Player 影院模式后再次点击浮动按钮，播放器 UI 虽然加载出来了，但 iOS Safari 会强制跳进黑底白字的系统原生全屏播放器界面。
* **深层根因**：
  在 `restoreOriginalPlayer()` 中，为了“恢复原始状态”，代码清除了 `<video>` 的 `playsinline` 属性并重置 `video.playsInline = false`。  
  **WebKit 原则**：在真实用户手势上下文（User Gesture）中，如果对一个未声明 `playsinline` 的 `<video>` 调用 `video.play()`，**iOS Safari 判定用户意图为全屏观看，立即触发系统的 `webkitEnterFullscreen()`**。
* **终极经验**：
  * 在移动端网页中，**永远不要从 `<video>` 上移除 `playsinline` 属性**；
  * 在浮钮点击起播与播放器初始化前，必须先强制设置 `playsinline="true"`、`webkit-playsinline="true"` 及 `video.playsInline = true`，并主动调用 `webkitExitFullscreen()` 消除全屏残留。

### 3.3 【踩坑 3】在真实手势栈中触发宿主原生 DOM `.click()` 的严重连带灾难
* **现象**：
  在 MissAV 站点击浮钮播放视频时，Safari 每次都会无情弹出一个新的广告标签页。
* **深层根因**：
  为了“预热视频加载”，浮钮点击事件中执行了 `hostPlayBtn.click()`（即点击了原站的 `.plyr__control--overlaid`）。  
  由于浮钮点击本身处于合法的用户交互手势链（User Activation Stack）中，`hostPlayBtn.click()` 会被 Safari 认定为“用户亲自点击了该播放按钮”，从而合法触发了第三方广告联盟挂载在该按钮上的 `window.open` 弹窗。
* **终极经验**：
  * **严禁在自研播放器逻辑中调用任何宿主原站 DOM 元素的 `.click()` 方法**；
  * 若要起播或预热，直接且仅能操作底层 HTML5 `<video>` 元素的 API（如 `video.play()`、`video.load()`）。

### 3.4 【踩坑 4】分布式多端同步中的「数据复活 (Data Resuscitation)」与 CRDT 墓碑
* **现象**：
  设备 A 删除了某个视频的时间轴打点，设备 B 同步后非但没有删除，反而把该打点重新同步回了设备 A。
* **深层根因**：
  简单的对象合并（如 `Object.assign` 或 `Array.from(new Set(...))`）只能处理“新增”和“修改”，无法表达“删除”。在分布式无中心架构中，**缺失（Absence）不等于删除**，缺失会被判定为“该设备尚未拉取到这条数据”，从而导致旧数据不断复活。
* **终极经验**：
  * 必须引入 **CRDT Tombstone（墓碑）** 机制：删除操作在本地转化为带删除时间戳的墓碑记录 `{ id, deletedAt }`；
  * 合并时，候选数据的更新时间若小于或等于墓碑时间，则一律作为已删除数据过滤抛弃；
  * 设置 30 天自动垃圾回收（GC），防止墓碑无节制膨胀。
