# 开发日记 — 2026年8月26日

## Miss Player WebDAV 多端 CRDT 智能同步引擎构建、Safari 全屏劫持与 Chrome DevTools 性能全链路终极调优

## 1. 核心任务与架构演进概览

本阶段围绕 **Miss Player** 的云端跨端配置同步（WebDAV CRDT 引擎）、Safari 移动端原生交互漏洞攻坚、广告弹窗拦截体系以及基于 **Chrome DevTools Performance Trace**（三轮实测追踪分析）的全链路渲染、交互与布局偏移调优，完成了重大架构演进与版本迭代（`v5.6.0` -> `v5.6.9`）：

### 1.1 WebDAV 多端分布式 CRDT 智能合并同步引擎 (`src/sync/`)
1. **Schema v2 规范与 LWW 冲突解决**：
   - 设计并落地基于 **LWW-Element-Set (Last-Write-Wins)** 的分布式数据合并机制，支持字段级时间戳合并；
   - 引入 **30 天墓碑机制 (Tombstones)**：记录用户删除打点（`markers`）、自定义步进（`customUserSeekSteps`）以及已清空视频的删除时间戳，彻底根除了“设备 A 删除了打点，设备 B 同步时又将打点复活回流”的经典多端同步冲突。
2. **多形态终端布局独立隔离 (Device Form-Factor Isolation)**：
   - 区分 `desktop`、`mobile`、`tablet` 终端形态，将侧边栏停靠方向（`sidebarPosition`）与收起状态（`sidebarHidden`）按设备类型独立保存，实现“PC 端展开右侧栏，手机端保持精简单手模式”互不干扰。
3. **全自动无感同步与实时刷新 (`mp_sync_applied`)**：
   - **数据变更防抖同步**（3s debounce）；
   - **页面唤醒与焦点切回同步**（`visibilitychange` / `window.focus`）；
   - **后台 25 秒轻量心跳轮询 (`startPeriodicSync`)**：两端同时播放同一视频时，25 秒内自动拉取合并远端打点，并派发全局事件驱动进度条与标签药丸实时热重载。
4. **WebDAV 直连协议客户端 (`WebDavClient.js`)**：
   - 彻底废除脆弱且易在部分 WebDAV 服务端（坚果云、Alist、Nginx WebDAV）挂起的复杂 `PROPFIND` 递归；
   - 采用标准 `GET` 下载、`PUT` 上传与 404/409 目录自愈创建机制；
   - 全链路接入 12 秒严格超时熔断、`onabort` 监听与全量 `try...catch` 保护。

### 1.2 Chrome DevTools 性能三阶段调优 (LCP, INP, CLS & Forced Reflow)
1. **第一阶段 (LCP 2610ms -> 1086ms, 降幅 58%)**：
   - 将 `autoExpandDetails()` 与 `QualityManager` 移出关键渲染路径，改由 `requestIdleCallback` 空闲调度；
   - 将 DOM 广告清理合并为单次 `querySelectorAll(combinedSelector)` 并去除 2 秒一次的盲目轮询；
   - 解耦 `initAutoLogin` 同步等待为异步非阻塞 Promise。
2. **第二阶段 (INP 356ms -> 260ms -> 极速交互)**：
   - **浮钮点击拆解与 rAF 组装 (`FloatingButton.js`)**：保留手势起播与浮钮即时隐藏（< 2ms），将播放器构建递延至 `requestAnimationFrame`；
   - **安全区域静态化缓存 (`src/utils/device.js`)**：`getSafeAreaInsets` 建立静态缓存，彻底废除 `getComputedStyle(document.documentElement)` 强行样式重算；
   - **浮钮纯 CSS 原生适配**：采用 `max(20px, env(safe-area-inset-bottom))` 进行纯 CSS 定位。
3. **第三阶段 (Forced Reflow 彻底清零 & CLS 0.32 -> 0.00 根除)**：
   - **滑动约束 rAF 防抖合并 (`videoSwipeManager.js`)**：`_updateConstraints()` 接入 `_constraintsRafPending`，将 `_updateVideoDimensions` 的 28ms 强制布局合并为单帧 rAF 执行；
   - **设置面板 DOM 懒加载 (`SettingsManager.js`)**：`init()` 阶段不再预先渲染数十个设置项 DOM，仅在用户点击设置按钮或空闲时构建，初装耗时下降 70%；
   - **原位占位符消除 CLS (`PlayerCore.js`)**：视频元素移入播放器浮层时，在宿主原位插入透明 `tm-video-placeholder` 保持宽高比与高度，彻底防止原网页容器塌陷引起的累计布局偏移（CLS）。

| **设置面板构建阻塞初装** | 播放器挂载时即时生成全部 WebDAV 卡片与设置项 DOM | ✅ **已解决** | 将 `createSettingsPanel` 移至首次打开或 `requestIdleCallback` 懒加载 |

| **WebDAV 4 按钮卡在执行中** | 底层 `GM_xmlhttpRequest` 缺少 `onabort` 与异常捕获，且 `PROPFIND` 无 Body 挂起 | ✅ **已解决** | 直连 `GET`/`PUT`、12s 超时熔断、`onabort` 捕获及 `_lastWebDavStatus` 状态徽标持久化 |
| **双端同时播放无法实时同步** | B 端播放时若不刷新页面或切后台，没有后台定时器检测云端更新 | ✅ **已解决** | 引入 `startPeriodicSync` 25s 轻量心跳轮询，配合 `mp_sync_applied` 事件实现实时热更新 |

| **Safari 退出重进自动全屏** | 退出播放器时移除 `playsinline` 导致二次点击浮钮调用 `play()` 触发系统全屏 | ✅ **已解决** | 退出时永久锁定 `playsinline="true"` 与 `playsInline=true`，并在起播/挂载设立全屏退出守卫 |
| **多端删除打点后再次复活** | 合并数据时仅做并集，一端删除的数据在另一端被识别为新增并写回 | ✅ **已解决** | 建立 Schema v2 墓碑机制（Tombstones），记录 30 天删除元数据并在合并阶段严格过滤 |

## 3. 经验总结与踩坑教训 (Lessons Learned)

### 3.1 【性能教训 1】宿主 DOM 节点提取必须安置 Placeholder 占位符以杜绝 CLS 恶化
* **现象**：
  将原生 `<video>` 从原网页文档流中挪移至播放器 Fullscreen/Fixed 容器后，Core Web Vitals 的 CLS（Cumulative Layout Shift）激增至 0.32（超标严重）。
* **深层根因**：
  原生视频容器在失去了核心 `<video>` 之后，容器高度骤降为 0，下方的大量视频列表、评论和侧边栏整体向上跳跃，造成大面积视口布局偏移。
* **终极经验**：
  * **在将任何大体积 DOM 元素抽离原父节点之前，务必在原地插入一个尺寸对齐且 `visibility: hidden` 的占位容器 (`Placeholder`)**；
  * 当还原或销毁时，使用 `replaceChild` 将原元素放回，彻底保障原网页布局 0 偏移。

### 3.2 【性能教训 2】高频几何计算必须加装 rAF 防抖合并器 (Coalescing)
* **现象**：
  `_updateVideoDimensions` 触发了 28ms 的布局开销。
* **深层根因**：
  当视频发生 `loadedmetadata`、`canplay`、窗口旋转及缩放时，浏览器会在极短时间内派发多个事件。如果每个事件回调都立即读取 `offsetWidth` / `offsetHeight`，就会强行打断浏览器的批处理渲染周期。
* **终极经验**：
  * 使用 `_constraintsRafPending` 标志位将连续的布局读取合并至下一渲染帧统一计算，避免帧内多次强制重排。
