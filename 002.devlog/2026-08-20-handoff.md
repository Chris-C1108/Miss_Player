## 2. 核心架构与关键成果沉淀

### 2.1 混合沙箱桥接（Hybrid GM Bridge Loader）
* **运行机制**：
  * `Hls.js` 运行在页面主上下文，无缝挂载页面 DOM `<video>`（彻底规避 MSE 沙箱隔离）；
  * 页面注入 `window.__MissPlayerLoader` 继承 `Hls.DefaultConfig.loader`；
  * `GMBridge` 挂载在 `unsafeWindow.__mpBridge`，负责发起 `GM_xmlhttpRequest` 携带防盗链 Header 下载二进制分片；
  * 通过沙箱内部 `URL.createObjectURL(blob)` 生成 Blob 供页面上下文 `fetch(blobUrl).arrayBuffer()` 交付给 Hls.js。

### 2.2 Jav.sb 坏片物理剔除算法（Pre-Sanitization）
```javascript
// 在向 Hls.js 交付 M3U8 前，先并发探测前 5~6 个切片
// 若返回 404，直接从 M3U8 文本中同时移除 #EXTINF 行与切片 URL 行
const cleanM3u8 = await sanitizeM3u8Playlist(rawM3u8);
const blob = new Blob([cleanM3u8], { type: 'application/vnd.apple.mpegurl' });
hlsInstance.loadSource(URL.createObjectURL(blob));
```
**实测结果**：Jav.sb 从最初的 403 / 404 重试循环彻底变为 0 报错秒开播放。

## 3. SupJav.com 未解问题深入剖析与排查方向

### 3.1 当前现象与日志
在 `https://supjav.com/451391.html` 上：
1. 提取到了 `https://cdn4.turboviplay.com/data3/6a85c8edeb52d/6a85c8edeb52d.m3u8`；
2. 切片在沙箱内下载（如 `https://lh3.googleusercontent.com/d/...` 或 TurboViPlay 切片）返回 200 OK；
3. 控制台报：
   - `Creating a worker from 'blob:<URL>' violates Content Security Policy directive...`（已在 v0.23.0 中通过 `enableWorker: false` 规避）；
   - `HLS 事件通知: mediaError fragParsingError fatal: true`；
   - 视频缓冲停滞或自动降级为等待用户点击。

### 3.2 待验证排查假设（Next Hypotheses）
1. **假设 A：切片响应是否被加密或为伪装类型**
   - 检查 `cdn4.turboviplay.com` 或 `lh3.googleusercontent.com` 返回的 ArrayBuffer 是否为标准 TS 流，还是含有特殊字节偏移（例如类似某些 CDN 在前 128 字节填充了垃圾数据或 PNG 头）；
2. **假设 B：SupJav 的多线路选择（TurboVid vs FC2Stream vs ST Server）**
   - 在 `ref/catch_har/supjav.com.har` 中，除了 `turbovidhls.com`，还有 `fc2stream.tv`（`https://fc2stream.tv/e/qq9f2fj7r9g9`，该源通常为纯标准 HLS 直链，稳定性更高）；
   - 检查 `extractStreamsUniversal` 是否能同时提取 SupJav 页面上的所有线路供用户在模态框右上角自由切换。
