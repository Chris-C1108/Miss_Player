## 🧠 核心技术陷阱与解决经验

### 1. 平台合规与外部接口的零侵入边界 (Zero Antifeatures)
- **陷阱**：在引入外部 API（如 SleazyFork JSON API）时，如果为了“统计”或“识别”而向请求 URL 拼接客户端随机 ID、播放视频编号或来源域名，将直接触犯 SleazyFork / GreasyFork 的严格合规红线，被判定为隐瞒外发或遥测。
- **正解**：
  - 必须保持请求的纯净只读性：固定调用公开的 `https://sleazyfork.org/scripts/{id}.json`，URL 中绝不附加任何私有查询参数；
  - 不通过该请求向任何外部服务器回传任何客户端标识；
  - 遵循用户自治原则，设置面板提供「自动检查更新」开关，由用户完全掌控网络请求。

### 2. 外部 API 节流与防滥用 (Cache TTL & Throttling)
- **陷阱**：油猴脚本在每个匹配的网页加载时都会重新执行。如果每次进入视频详情页都无条件向 SleazyFork 发起 GET 请求，当用户在几分钟内连续翻阅多部视频时，极易触发平台 Cloudflare 盾牌的 429 频控或临时 IP 封锁，且大量消耗用户网络资源。
- **正解**：
  - 引入 12 小时本地节流缓存（TTL）；
  - 静默自动检查时优先读取本地缓存，只有在缓存不存在或超过 12 小时后才真正发起网络请求；
  - 仅在用户于设置面板显式点击「检查更新」按钮时才跳过缓存强刷，并自动更新缓存时间戳。

### 3. 跨运行环境的网络传输适配与降级机制 (`http.js`)
- **陷阱**：油猴跨域请求依赖 `GM_xmlhttpRequest`。但在自动化测试环境（如 Node.js 或 GitHub Actions VM 容器）中，全局并不存在 `GM_xmlhttpRequest`，如果代码硬编码强依赖 GM 接口，会导致 CI 流程抛出 `GM_xmlhttpRequest unavailable` 异常而中断流水线。
- **正解**：
  - 在 `http.js` 中构建双层降级体系：优先使用 `GM_xmlhttpRequest` 绕过浏览器同源策略；
  - 当处于非 GM 纯环境（如 Node CI / 自动化单元测试）且存在原生 `fetch` 时，自动平滑降级至 `fetch`；
  - 彻底解耦了业务逻辑与特定运行沙箱的强依赖，既保证了浏览器端油猴特权，又赋能了全自动单元测试。

### 4. 语义化版本比对的边界健壮性
- **陷阱**：版本字符串可能存在 'v' 前缀（如 `v5.6.24`）、破折号预发布后缀（如 `5.6.24-beta`）或位长不一致（如 `5.6` vs `5.6.0`），简单的字符串对比（如 `'5.6.9' > '5.6.10'` 为 true）会引发灾难性的误判。
- **正解**：
  - 编写标准的 Semver 分段解析算法；
  - 正则清洗前导 'v' 并截断 `-` 预发布标识；
  - 按 `.` 分割后逐位转换整数并对齐长度比对，通过单元测试覆盖各种边界场景。

### 5. Apple 交互哲学：非阻断式徽章提示
- **陷阱**：许多脚本在检测到新版本时喜欢弹全屏 Alert 或强弹窗，打断用户沉浸式观影或浏览，体验极差。
- **正解**：
  - 采用 Apple Design 克制的设计哲学：后台闲时静默检查，发现新版本仅在设置齿轮按钮右上角点亮精致的脉冲红点徽章；
  - 只有当用户主动打开设置面板时，才以高亮卡片形态展示新版本信息、版本日志与一键安装引导，极致优雅且零侵入。
