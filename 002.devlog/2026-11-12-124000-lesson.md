# Miss Player 经验教训与陷阱总结 (Lesson Learned)

- **归档时间戳**：`2026-11-12-124000`
- **关联版本**：`v5.7.118-beta.012`
- **主题**：二元数据主权架构收拢、零牛皮癣极简交互、物理网络硬熔断与 WebDAV 双写保障

## 🚫 踩坑反模式与标准范式 (Anti-Patterns & Best Practices)

### 1. 概念分散与技术黑话牛皮癣导致用户理解与配置门槛激增
* **反模式 (FORBIDDEN)**：
  - 将云端与边缘架构的内部概念（如 Supabase REST API、Cloudflare Anycast 边缘缓存网关、RPC 增量合并、全网互惠等）直接暴露在面向用户的设置面板上；
  - 提供一大堆需要用户自行填写的 API Endpoint、API Key 密码框及分散的各类子开关，让用户感到困惑和隐私不安全。
* **标准范式 (USE)**：
  - **基于 Apple HIG 的二元主权数据架构 (Binary Data Sovereignty)**：
    1. 彻底收拢为单一 Apple 双态分段选择器：`【 社区共享 】` vs `【 本地私有 】`；
    2. 文案直击收益与隐私界限（共享：呈现全网波峰热评并匿名回馈；私有：断开公共通信，足迹全本地）；
    3. 脚本内部固化官方高速边缘通道，免除用户任何参数填写负担。

### 2. 本地私有模式下残留弱逻辑导致潜在网络通信泄露
* **反模式 (FORBIDDEN)**：
  - 仅在 UI 层隐藏或禁用按钮，而底层 Service 仍会在特定兜底逻辑下向默认服务端发起查询或健康检查；
  - 缺乏防御性拦截导致用户在隐私模式下仍有网络指纹外泄风险。
* **标准范式 (USE)**：
  - **物理级硬熔断 (Physical Hard Circuit Breaker)**：
    1. 在 `SupabaseService.js` 所有对公接口的最开头，统一插入第一行：
       `if (!this.isSharedMode() || !videoCode) return ...;`
    2. 一旦处于「本地私有」模式，0 延迟瞬间返回空值或 false，绝对禁止产生任何 `GM_xmlhttpRequest` 或 `fetch` 网络调用；
    3. 在自动化测试中（如 `tests/heatmap.test.mjs` 测试 #10）进行严格的网络侦听断言，确保 0 请求。

### 3. 公共共享模式排斥或忽略私有云盘备份
* **反模式 (FORBIDDEN)**：
  - 将“公共云”与“私有 WebDAV”对立化，认为用户选了全网共享就只写公共端点，导致私有 NAS/网盘备份被闲置；
  - 用户换设备或离线时无法从私有源完整漫游数据。
* **标准范式 (USE)**：
  - **公私双轨并存，数据写 2 份保障 (Guaranteed Dual-Write Pipeline)**：
    1. 只要用户配置了 WebDAV，无论处于哪种数据模式，播放离散结算时均**强制同步写入 WebDAV 独立文件**；
    2. 「社区共享」模式只是额外激活了 120 字节对数纯增量向公共云端的上报，绝不牺牲私有备份；
    3. 读取时优先取本地 IndexedDB，再尝试公共缓存/底轨，再通过 WebDAV 漫游合并（Element-wise Max 并集），真正兼顾公私两全。
