## 🎯 核心问题与设计反思

### 1. Shadow DOM 隔离下的 DOM 查询反模式
- **陷阱**：在微前端模块化重构中，当整个播放器挂载至 `ShadowRoot` 内部后，业务代码中若残留 `document.querySelector('.tm-control-buttons')`，将永远返回 `null`，导致相关悬浮弹窗或组件挂载静默失败。
- **最佳实践**：
  - 核心模块间必须使用依赖注入（如 `LoopManager` 构造函数中注入 `controlManager`），直接持有已实例化的 DOM 引用（如 `controlManager.controlButtonsContainer`）；
  - 兜底 DOM 查找时，优先利用已有子节点向外溯源（如 `this.tabScrollContainer?.closest('.tm-control-buttons')`），或在目标 `ShadowRoot` 上调用 `querySelector`，严禁仅寄希望于全局 `document.querySelector`。

### 2. API 伪造 (Mock/Monkey Patching) 的对称性与自反陷阱
- **教训**：在设计“允许后台播放”这类需要伪造 `document.hidden` 的功能时，如果直接用 `Object.defineProperty` 覆写了 `document` 属性，并且没有保留原生的 `get` 访问器，后续脚本内部自己的诊断和状态机也只能读到伪造后的假值。更严重的是，三元运算符写错（`cond ? false : false`）会导致属性永久固化为假，从而反向欺骗了自身的可见性检测，导致失焦判定彻底瘫痪并引发异常自动恢复起播。
- **最佳实践**：
  - 任何针对宿主底层 API（如 `document.hidden`, `document.visibilityState`, `document.hasFocus`）的猴子补丁（Monkey Patching），**必须在打补丁前保存原生 PropertyDescriptor 与原型函数**；
  - 模块内部状态判断一律调用内部穿透方法（如 `getRealHidden()`），绝不可直接读取已被污染的公共属性；
  - 严格校验开关分支：只有在特定反向模式（如关闭失焦暂停）时才伪造假数据，正常模式必须 100% 忠实透明转发原生状态。
