# Lesson Learned: WebDAV 全链路协议守卫、NAS 根目录限制与并发限流 (2026-11-12)

- **归档时间**: `2026-11-12 00:11:59`
- **关联版本**: `v5.7.118-beta.008` (Commit `a1e0c51`)

---

## 🚨 核心反模式禁令 (FORBIDDEN -> USE)

### 1. 禁止只在 `testConnection` 里写 HTML/3xx/5xx 拦截补丁
- **FORBIDDEN**: 仅在 `checkDirectoryExists` 和 `testConnection` 中局部判断 `_isHtmlResponse()` 或 `>= 500`，而让 `downloadBackup`、`uploadBackup`、`uploadFile`、`checkFileExists` 各自裸调 `request()` 并在遇到 200 HTML 劫持页或 502 时吞错或误判失败。
- **USE**: 所有 WebDAV HTTP 动作必须**统一收敛经过协议守卫方法 `_davRequest()`**；由单一守卫集中识别 HTML 网页劫持（无论 HTTP 200/401/403/404）、3xx 重定向与 5xx 异常并上抛可转移网络错误，确保任意业务线的第一次请求都能驱动双地址无缝 failover。

### 2. 禁止在初始化瞬间向 NAS / 内网穿透网关无节制并发轰炸
- **FORBIDDEN**: 启动播放器后同时放任 `SyncManager`、`HeatmapManager`、`CommentPanel`、`UIManager` 发出 4+ 路并发 WebDAV 请求，导致 fnOS FN Connect / Alist 等轻量化网关触发限频熔断，进而假报 401/405。
- **USE**: 在 `WebDavClient.request` 底层入口处**对单个 Origin 强制执行并发槽位队列（`MAX_CONCURRENT_PER_ORIGIN = 2`）**，从通信最底层无感削峰排队。

### 3. 禁止遇到 `MKCOL HTTP 405` 时笼统甩锅“请手动创建目录”
- **FORBIDDEN**: 许多现代 NAS（特别是飞牛 fnOS、群晖）在协议层物理禁止客户端在 WebDAV 根目录 `/` 创建一级共享目录（必返 405），或会在系统更新后丢失「可见文件夹范围」勾选；若前端只机械提示“无法自动创建”，用户无法定位到底是路径写错了、少前缀 `/我的文件/`、还是权限/可见范围没勾。
- **USE**: 当 `_ensureDirectoryInternal` 探测与建目录最终失败时，主动发送 `PROPFIND / (Depth: 1)` 拉取服务器真实可见顶层目录清单，精准诊断「可见范围为空」、「大小写不匹配」、「实际位于 `/我的文件/` 下」或「只读权限」，直接给出可复制修正路径。

### 4. 禁止把未百分比编码的非 ASCII 路径直接塞给 Safari / Stay XHR
- **FORBIDDEN**: 把含中文目录（如 `/我的文件/backup_configs/`）的原始字符串直接拼入 URL 发往 iOS WebKit / Stay `GM_xmlhttpRequest`，极易被底层转换器丢弃或乱码返回 404。
- **USE**: 在 `normalizeUrl` 对每个路径段执行解编码归并后再 `encodeURIComponent`（避免二次编码 `%XX`），做到 ASCII 零改动、非 ASCII 全兼容。

### 5. 禁止保存了新端点配置后还残留旧端点 2h 租约缓存
- **FORBIDDEN**: 用户在设置页刚改完 `url` / `lanUrl` / `user` 并立即点击「测试连接」，底层却仍命中旧配置生成的缓存跳回旧地址。
- **USE**: 在 `SyncManager.saveWebDavConfig` 与 `PeachService.saveConfig` 检测到端点/用户名变更时，立即调用 `WebDavClient.clearEndpointLease()` 清空内存与持久化租约。

### 6. 禁止全局校验留后门（局部遗漏直判 `.url`）
- **FORBIDDEN**: 部分业务判定使用了 `WebDavClient.hasValidEndpoint(cfg)`，却在边缘模块（如 `PeachService`、`PeachSection`）遗留 `Boolean(cfg.url && cfg.user)`，导致只填备用地址时被错误降级。
- **USE**: 全局任何一处判断 WebDAV 是否配置完整，100% 统一调用唯一权威入口 `WebDavClient.hasValidEndpoint(config)`。
