# Session Lessons & Anti-Patterns: 移动端评论折叠死留白消除与 iOS WebKit 透明击穿软键盘防御

- Date & Time: 2026-11-11 17:27:11
- Focus Module: `src/player/ui/styles/_comments.css` & `src/player/controls/CommentPanel.js`

## 1. PROBLEMS ENCOUNTERED (遇到的核心问题与故障)
- **现象 1 (死留白空洞)**：
  移动端竖屏查看评论时，当某个源（如 JavDB）只有少量几条评论（共 3 条），列表在 `-end-` 结束标记之后留下了长达数百像素的巨大黑色空白，下方折叠的数据源（Jable.tv）被强行挤到屏幕最底端，视觉极不协调。
- **现象 2 (误唤起虚拟键盘)**：
  用户手指触摸或点击该大块黑色空白区域时，系统莫名其妙自动弹出了 iOS 原生虚拟软键盘，仿佛“穿透了控制面板和评论区直接点到了底层网页”。

## 2. ROOT CAUSE ANALYSIS (根本原因剖析)
1. **Flex 弹性伸展模型误用导致内容被暴力拉大**：
   - 样式中 `.tm-comment-section:not(.is-collapsed)` 被赋予了 `flex: 1;`（即 `flex-grow: 1`）；
   - 在 Flexbox 规范中，`flex-grow: 1` 会强制占据父容器分配的**所有剩余可用空间**；
   - 即使内容实际只有 120px，容器也会被强制拉伸到 500px+，把后续节点全数推至底部，产生巨幅死留白。
2. **`pointer-events: none` 与透明背景引发 iOS WebKit Hit-Testing 击穿 (Tap-Through)**：
   - `.tm-comments-panel` 历史遗留了 `pointer-events: none; background-color: transparent;` 注释以为可以“让点击穿透到视频”，但实际上竖屏下评论区位于视频下方；
   - 在 iOS Safari 渲染引擎中，透明像素且声明为 `pointer-events: none` 的容器，WebKit 的 Hit-Testing 判定其在 Compositor（合成器）层树上**没有实体绘制层（Opaque Backing Store）**；
   - 触碰事件会直接穿透 Shadow DOM 边界，打在底层宿主网页（`missav.ai`）位于该物理坐标上的原生元素；
   - `missav.ai` 在视频下方正好布局有其网页的搜索框与评论输入框（`<input>` / `<textarea>`）；
   - iOS Safari 在接收到宿主 `<input>` 的触摸事件后，判定用户正在聚焦文本框，瞬间唤起了系统原生虚拟软键盘！

## 3. PROVEN SOLUTION (验证有效的解决方案)
1. **Flexbox Hugs-Content 内容自适应收缩规范**：
   将展开分区调整为：
   ```css
   .tm-comment-section:not(.is-collapsed) {
       flex: 0 1 auto;   /* 拒绝主动索取剩余空间，高度随内容紧凑包裹 */
       max-height: 100%; /* 超长内容时严格限制在父视口内，由内部 overflow-y: auto 优雅滚动 */
   }
   ```
2. **Compositor 物理实体图层防穿透**：
   将容器改为实体背景与显式接管事件：
   ```css
   .tm-comments-panel {
       background-color: #0b0b0e; /* 极夜纯黑实体图层，消灭 iOS WebKit 击穿条件 */
       pointer-events: auto;      /* 显式声明接收并消化事件，坚决禁止穿透到底层宿主页面 */
   }
   .tm-comments-panel-list.tm-comments-list {
       background-color: #0b0b0e;
   }
   ```
3. **Touch 事件黑洞吸收**：
   在 `CommentPanel.js` 的 `handleCommentTouchStart` 中：
   ```javascript
   const isInteractive = !!e.target.closest('a, button, input, textarea, select, .jc-time-link, .jc-code-link, .jc-toggle-expand-btn, .tm-comment-retry-btn, .jc-report-btn, .jc-countdown-btn, .tm-comment-section-hdr');
   if (!isInteractive && !isSubmitBar) {
       e.stopPropagation(); // 阻断向宿主冒泡，不调用 preventDefault 保留原生惯性滚动
   }
   ```

## 4. PITFALLS & ANTI-PATTERNS (避坑指南与反模式禁令)
- **FORBIDDEN: 在手风琴列表的展开分区中使用 `flex: 1` 强行拉伸** ➔
  **USE: 必须采用 `flex: 0 1 auto; max-height: 100%;`**，内容少时紧凑包裹（Hugs Content），消除空洞死留白；内容多时内部滚动。
- **FORBIDDEN: 在非全屏透明遮罩的业务内容容器上声明 `pointer-events: none` 或纯透明背景** ➔
  **USE: 必须声明实体背景色（如 `#0b0b0e`）与 `pointer-events: auto`**，构建绝对不透明的物理 Backing Store，杜绝 iOS WebKit Hit-Testing 穿透 Shadow DOM 激活宿主输入框或链接。
- **FORBIDDEN: 在移动端触摸拦截中对普通点击/滑动使用 `e.preventDefault()` 破坏原生滚动** ➔
  **USE: 仅使用 `e.stopPropagation()` 阻断向宿主冒泡**，在消灭击穿的同时百分之百保留 Safari 的惯性平滑滚动与物理回弹手感。

## 5. SCALING TO AGENTS.MD (全局规则提炼)
- 提炼原子规则 1 (CSS 治理)：
  `RULE: 手风琴折叠列表展开分区严禁使用 flex: 1 强行撑开父容器，必须采用 flex: 0 1 auto; max-height: 100%; 自适应收缩包裹，彻底消除死留白空洞。 (FORBIDDEN: .section:not(.is-collapsed) { flex: 1; } -> USE: { flex: 0 1 auto; max-height: 100%; })`
- 提炼原子规则 2 (手势与安全隔离)：
  `RULE: 浮层与非遮罩容器必须具备实体背景与 pointer-events: auto，且在非交互区域阻断 touchstart 冒泡，严禁因透明与 pointer-events: none 引发 iOS WebKit 穿透命中宿主底层输入框误唤醒软键盘。 (FORBIDDEN: container { pointer-events: none; background: transparent; } -> USE: container { pointer-events: auto; background: #0b0b0e; } + e.stopPropagation())`
