# Lesson — 字段命名契约漂移是跨站点串源的真正凶手 (2026-11-17)

- 关联版本：`v5.7.118-beta.055`
- 关联交接：[2026-11-17-180006-handoff.md](./2026-11-17-180006-handoff.md)

## 一、反模式清单（成对禁令）

1. **FORBIDDEN: 多生产者对同一语义字段使用不同键名（`site` / `source` / `source_site` 混用）→ USE: 读取侧必须多键兼容 + 以不可伪造的 ID 前缀作为最终裁决。**
   - Provider 写 `site`，DebugCollector 读 `source`，Supabase 写 `source_site` —— 三者从未对齐，静默运行了数月。
2. **FORBIDDEN: 用「来源标签字段」作为分桶唯一依据 → USE: 来源字段 + 评论 ID 前缀双证据，冲突时以 ID 为准。**
   - `javdb-api-*` / `javlib-*` / 纯数字 三类 ID 命名空间是硬约束；`source_site` 是可变、可被历史 BUG 污染的软标签。
3. **FORBIDDEN: 分桶键参与哈希指纹计算却不做归一 → USE: 指纹输入必须使用归一化站点键。**
   - `md5(source + id + content)` 让同一条评论产生两个指纹，服务端 `distinct on (hash_fingerprint)` 无法去重 → 5,288 条双写。
4. **FORBIDDEN: 「重解析后整桶回写云端」→ USE: 回写前先 `_normalizeSiteBuckets()`，且只上传 `inferSiteKey(c) === siteKey` 的评论。**
   - 这是污染从本地扩散到全网的放大器。
5. **FORBIDDEN: 假定 `processComment()` 会回填 `text` → USE: 合并远端评论时显式 `processed.text = processed.rawText`，`reprocess` 读取时用 `c.rawText || c.text || c.content_raw` 容错。**
   - 否则 `processComment(undefined)` 抛 `TypeError: Cannot read properties of undefined (reading 'includes')`，且被 `catch(_){}` 静默吞掉。
6. **FORBIDDEN: Playwright 的 `GM_xmlhttpRequest` mock 里 `respond(对象)` → USE: `respond(JSON.stringify(对象))`。**
   - 本次排查中因 mock 直接传对象，`JSON.parse('[object Object]')` 抛错并静默降级，导致误判「远端的污染数据没进来」。
7. **FORBIDDEN: 用 `indexOf('method(')` 定位方法定义 → USE: `indexOf('\n    method(')`（带缩进）或 `lastIndexOf`。**
   - 静态测试曾命中调用点而非定义点，产生假绿/假红。

## 二、方法论沉淀

- **「渲染层干净」不等于「数据干净」**：先用 mock 三站 HTML 证明渲染隔离成立，再把矛头转向持久化层，一步省掉了大量无效排查。
- **统计比单条复现更有力**：`site_comment_id` 前缀 × `source_site` 交叉表一眼看出 5,288 条错标；`Jaccard == 1` 的 22 个 bundle 直接对应「内容完全相同」的用户描述。
- **修复要覆盖三个时间维度**：① 未来写入（Service 守卫 + 分桶推断）；② 本地存量（`_normalizeSiteBuckets` + 缓存自愈）；③ 云端存量（SQL 归一迁移）。缺任何一环都会复发。
- **以 ID 命名空间做权威**是这类「多源评论聚合」系统的通用解法：命名空间不可伪造，标签字段永远会被历史 BUG、旧备份、第三端脚本污染。
