## 🧠 核心技术陷阱与解决经验

### 1. 现代 CSS 框架（Tailwind CSS）下 DOM 语义类名消失陷阱
- **陷阱表现**：在 MissAV 等现代化前端站点上，原本设计用于抓取时长徽章的类名选择器（如 `.duration`, `.time`, `.video-item`）全部静默失效，导致爬虫抓取的关联影片时长一律退化为 0。
- **根因分析**：
  - 现代站点广泛使用 Tailwind CSS 或 Utility-First 样式库，DOM 节点类名全部由原子工具类组成（如 `class="absolute bottom-1 right-1 text-xs text-white bg-black/75 px-1 rounded"`），完全去除了语义化类名；
  - 强依赖类名的选择器在遇上原子化 CSS 时会发生假死，直接返回 `null`。
- **正解实践**：
  - 建立**基于数据形态而非 CSS 类名的结构探测器**（如 `parseDurationFromBadge`）；
  - 从视频锚点向外探测包裹卡片，遍历卡片内的纯文本叶子节点，使用严格的正则表达式匹配时间格式文本（`HH:MM:SS` 或 `MM:SS`）；
  - 增加**业务数据兜底反推**：从抓取到的评论中寻找最大的时间戳（`maxTs`）作为保底物理时长，彻底消除返回 0 的漏洞。

### 2. 多级云端防重机制下的本地测试“清理假死”陷阱
- **陷阱表现**：用户点击了“清空本地评论缓存”，预期是重新拉取测试，但爬虫启动后依然在每一项打印“跳过重复采集”，给用户造成“缓存未清理干净”的假象。
- **根因分析**：
  - 架构设计了四级去重（内存 ➔ 本地 IndexedDB ➔ Supabase 聚合库 ➔ WebDAV 独立文件）；
  - 本地缓存清理操作仅抹除了第二级（IndexedDB），而云端数据库和网盘中的记录依然存在；
  - 爬虫设计初衷是为了在生产中极度节约带宽和防封，在检测到云端已有备份时主动跳过，导致用户在本地无法复测爬虫逻辑。
- **正解实践**：
  - 将**生产防重**与**测试覆盖**解耦，在设置面板中新增显式的「强制覆盖重新采集」(`crazyForceRescrape`) 开关；
  - 在开启强制覆盖时，显式绕过第三级和第四级云端收录校验，对番号重新抓取并更新最新数据；
  - 在 IndexedDB 清理中直接调用 `indexedDB.deleteDatabase` 进行底层物理销毁，杜绝因为连接未关闭导致的清空失败。

### 3. 多页循环采集中的翻页频率与反爬安全平衡
- **陷阱表现**：在支持全量采集后，若翻页过快或单影片请求过多，容易引起源站 429 频控封锁。
- **正解实践**：
  - 设置全量采集安全上限（如 15 页）；
  - 页面之间引入带有随机抖动的安全延时（800ms ~ 1400ms Jitter Delay）；
  - 遇到 429/Cloudflare 挑战时，自动休眠 12 秒并轮换备用镜像域名，保障采集过程的长期健壮性。
