# Miss Player 经验教训与陷阱总结 (Lesson Learned)

- **归档时间戳**：`2026-11-11-205000`
- **关联版本**：`v5.7.118-beta.003`
- **主题**：底层服务与 UI 样式反向解耦、Userscript 动态导入禁用、双轨热度图 120 槽位量化与 WebDAV 漫游防膨胀

---

## 🚫 踩坑反模式与标准范式 (Anti-Patterns & Best Practices)

### 1. 服务层反向依赖 UI 导致 Node.js 测试与沙箱崩溃
* **反模式 (FORBIDDEN)**：
  - 在底层基础设施或网络服务（如 `src/services/SupabaseService.js`）中静态导入上层 UI 组件（如 `import { DebugLogPanel } from '../player/ui/DebugLogPanel.js'`）；
  - `DebugLogPanel.js` 自身引入了 `_debug.css`，导致纯 Node.js 测试环境直接抛出 `TypeError [ERR_UNKNOWN_FILE_EXTENSION]: Unknown file extension ".css"` 阻断全量 CI；
  - 进而为了避开该错误而在调用方使用动态 `import()`，诱发打包器退化。
* **标准范式 (USE)**：
  - **服务层保持 100% 无样式纯逻辑**：底层服务严禁引用任何 UI 控件及 `.css` 资源；
  - **全局弱引用日志调度**：通过 `window.DebugLogPanel?.addLog` 进行可选链安全调用，未挂载时自动静默放行；
  - 确保底层 Services 既能在浏览器环境中零摩擦工作，也能直接被 Node.js / Jest / ESM 单元测试顺畅执行。

### 2. Userscript 单文件打包禁用动态 `import()`
* **反模式 (FORBIDDEN)**：
  - 在单文件 Userscript 源码中书写 `await import('...')` 语法；
  - 油猴打包器（Vite + `vite-plugin-monkey` / Rollup）在单文件 IIFE 模式下无法输出外部异步分块（chunk），会默认将动态导入编译为 `System.register` 并在运行时寻找全局 `System` 加载器，导致沙箱安全启动测试爆出 `System is not defined` 致命崩溃。
* **标准范式 (USE)**：
  - **静态导入自包含**：Userscript 内部所有模块必须采用编译期静态 `import`，由打包器完全平铺内联打入单一产物；
  - 彻底杜绝任何动态代码分割，保持产物为 100% 自包含的闭包 IIFE。

### 3. 跨站点同源隔离导致媒体进度数据失效
* **反模式 (FORBIDDEN)**：
  - 仅仅依赖 `window.indexedDB` 存储播放热度图或用户行为足迹，寄希望于不同域名自动读取；
  - 浏览器的同源策略（Same-Origin Policy）使得 Peach 站（自建/私有域名）与源站（MissAV/Jable）完全隔离，导致换站点播放时波峰瞬间归零成贴底平线。
* **标准范式 (USE)**：
  - **Local-First + WebDAV 独立文件漫游自愈**：
    1. 本地起播先读 IndexedDB，确保 0ms 渲染；
    2. 后台异步从用户 WebDAV 独立文件 `/MissPlayer/heatmaps/[AVCODE].json` 拉取历史；
    3. **Element-wise Max 并集合并**：各分桶取本地与远端最大值，跨站即时无损同步。

### 4. 社区热度数据全量累加上报导致滚雪球膨胀
* **反模式 (FORBIDDEN)**：
  - 用户播放时直接上报本地当前的完整热度桶或累加播放秒数；
  - 用户多次重复播放或循环播放同一段落时，热度值无休止增加，导致个别用户的单一行为污染全网波形。
* **标准范式 (USE)**：
  - **120 分位定长量化**：跨源时长归一化至固定 120 个槽位，单片恒定 120 字节（Base64 160 字符），极大压缩存储；
  - **客户端水位线差分**：本地维护 `watermarkBins`，仅计算提交周期内的纯增量 `Δ`；
  - **45 秒有效门槛 + 服务端对数饱和合并**：单次最多贡献 `+1 ~ +3` 点，满分 255 封顶，彻底免疫刷量与重复上报膨胀。
