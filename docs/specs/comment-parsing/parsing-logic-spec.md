# Miss Player 评论解析逻辑完整技术规范 (`v5.7.118-beta.030`)

> **对应源码**：`src/player/comments/CommentDataPipeline.js`（1,558 行）、`src/player/controls/CommentPanel.js`  
> **核心入口**：`processComment(commentText, contextPrefix, videoDuration = 10800, options = {})`

---

## 1. 调用方参数契约 (Caller Contract)

`processComment` 接收 4 个参数：

| 参数 | 类型 | 语义约束 | 主要调用点 |
| :--- | :--- | :--- | :--- |
| `commentText` | `string` | 评论原文（可含全角符号、BBCode、`[quote]` 块） | 全部评论渲染与采集入口 |
| `contextPrefix` | `string \| null` | 当前页面完整番号或系列前缀（如 `"IPX-811"` 或 `"IPX"`），用于同系列残缺尾号补全 | `CommentPanel.js:1273, 3161, 3225, 3248`、`CrazyScraper.js:292` |
| `videoDuration` | `number` | 当前影片真实物理时长（秒），未获取到时默认 `10800`（3h） | 由 `getVideoDurationSeconds()` 穿透提取 |
| `options` | `object` | `{ publishTime?, sourceSite? }`，预留扩展上下文 | `CommentPanel.js` |

> **历史 Bug 修复**：`CommentPanel.js` 的 `_mergeRemoteComments`（3225 行）与 `_mergeWebdavComments`（3248 行）曾误将 `(item.content_raw, duration, item.published_at)` 传入 `processComment`，导致 `contextPrefix` 收到数字 `duration`、而 `videoDuration` 收到日期字符串产生 `NaN`。现已统一修正为 `(text, this.videoCode, duration)`。

## 2. Stage 0：文本标准化与引用剥离

1. **`normalizeText(text)`**（`CommentDataPipeline.js:110`）：
   - 将全角数字 `０-９`（`U+FF10–U+FF19`）映射为半角 `0-9`；
   - 将全角冒号 `：` 与全角连字符 `－` 分别规范化为 `:` 和 `-`；
   - 将多连续空格压缩为单空格并保留 `\n`。
2. **`[quote]` 引用块剥离**（`CommentDataPipeline.js:1469`）：
   - 对 BBCode 论坛格式评论，剔除 `[quote]...[/quote]` 块后再送入时间戳与番号识别，防止引用楼主的番号或时间在当前楼层重复计数。

## 4. Stage 2：5 级时间戳解析流水线 (`parseTimestamps`)

**源码位置**：`CommentDataPipeline.js:391-965`。

### 4.1 边界保护黑名单掩码 (`maskBlacklist`, line 391)
将明确非时间数字替换为等长下划线或 `_TAG_`（**保持字符索引位置不变**，避免破坏后续高亮对齐）：

1. **核心防护设计 — 左边界否定后顾 `(?<![:：.\d])`**：
   - 严禁量词/评分规则啃食紧邻冒号或小数点右侧的时间尾段。例如 `28:10 本片` 中 `10 本` 因左侧存在 `:` 而被放行，完整保留 `28:10`。
2. **掩码类别**：
   - **画质与规格**：`\d{3,4}[pP]`、`FPS/fps`、`\d+(?:\.\d+)?\s*(?:GB|MB|KB|TB|g|G|cm|mm|厘米|公分)`、`百分之\d+`
   - **完整日期与现实时间**：`2026.8.11` / `2024-02-17` / `\d{1,2}月\d{1,2}[日号]?`、`2.6发推`、`早上5点半`、`2:23am`
   - **评分表达**：`[【\[]\s*\d+(?:\.\d+)?\s*分`、`\d+\s*分\s*(?:半|左右|制|吧|[！!。，,])`、`[给打值评]\s*\d+(?:\.\d+)?\s*分`、`1/1` / `0/1` 比分、多维评分卡（`颜值17（满分20）...总分86`）、`\d+(?:\.\d+)?\s*(?:星|⭐|★)`
   - **数量、年龄、番剧与成语**：`(?<![:：.\d])\d+(?:[.\-~～到]\d+)?\s*(?:发|發|个人|部|本|套|次|岁|歲|楼|樓|年|梯|万|萬|觀看|观看|坪|穴)`、`1秒不落`、`连续\d+秒`、`不足\d+分钟`、`连续被干\d+多分钟`、`3秒3秒快进`、`69式`、`69到射`、`最强00后`、`666`

### 4.2 中文小时映射与 5 级候选提取 (`extractCandidates`, line 470)

| 级别 | 置信度 | 匹配语法形式 | 真实案例 | 解析秒数 |
| :---: | :---: | :--- | :--- | :--- |
| **L1** | `high` | `[-+]?H:M:SS` / `H:MM:SS` / `H:MM.SS` / `H-MM-SS` / `[-+]?MM:SS` | `28:10`、`2:02.34`、`0-44-59`、`40:00-1:1:12`、`-1:53:40` | `1690`、`7354`、`2699`、`3672`、`-6820` |
| **L2** | `medium` | `[-+]?\d{1,2}\.[0-5]\d`（强制两位小数，且受 `hourLimit` 与前后语境消歧） | `13.41`、`1.42`（当 `< hourLimit` 为 `H.MM`）；`预告1.29，1.30秒` | `821`、`6120`；`89, 90` |
| **L3** | `medium` | 中文/英文单位：`一小时40分钟`、`2时45分`、`1h47min30`、`45min`、`19分50`、`2h` | `一小时40分钟`、`1h47min30`、`45min`、`19分50` | `6000`、`6450`、`2700`、`1190` |
| **L4** | `high/med` | 由连接符 `~ - — ～ 到 至` 合并的起止时间区间 | `1:46:00—1:47:45`、`29:30-28:16`、`-1:42:07~-1:42:04` | `[6360, 6465]` |
| **L5** | `low` | 斜杠列表（全元素 `<=10` 丢弃）或孤立 1~3 位数（需经严格上下文锚点校验） | `51/56/100/133/148`、`39 1:40 2:36` | `[3060, ...]`、`2340` |

> **关键设计细节**：
> - `l1Regex` 与 `l1HmsRegex` 拆分为互不重叠规则：支持 `1:1:12` 单数字分钟 `H:M:SS`，同时利用前瞻防止将连写串 `15:5315:53` 错切成 `15:53`。
> - `l2Regex` 强制小数点后为 `[0-5]\d` 两位数字（彻底消灭 `3.5`、`9.7`、`2.6` 等 47/47 个 1 位小数误报）；当出现 `预告/前瞻` 或后缀 `秒` 时，优先按 `MM.SS` 解码（如 `1.30秒` -> `90s`）。
> - `CN_HOUR_DIGIT_MAP` 支持 `一`~`十`/`两` 中文小时（`一小时40分钟` -> `6000s`），同时要求单 `H` 匹配不能后接 `片子/影片/电影/长度/左右`。

### 4.3 去重、区间合并与语义门控 (`resolveOverlaps`, `mergeRanges`, `validateMatch`)

1. **`resolveOverlaps`**（line 691）：按 `confidence 降序 -> 长度降序 -> index 升序` 贪心保留无重叠区间，防止 `1h47min30` 被拆分。
2. **`mergeRanges`**（line 709）：仅当右侧也是合法时间候选时合并为 `L4` 区间；防止 `1.39.00-1尾` 被右边的 `1` 拖入虚假范围。
3. **`validateMatch`**（line 742）：
   - **片长边界**：`validationDuration = Math.max(videoDuration || 10800, 28800)`；
   - **持续时长与评分语义门控**：对 `L3` 的 `分/分钟/秒` 附加前置动作时长修饰词检查（`连续/持续/撑了/不到/不足`）；对 `<= 10` 的 `L3` `X分` 若无跳转锚词（`在/到/第/开始/出来/高潮/看`）直接拒绝；
   - **L5 严格准入**：必须满足 **数值 ≥ 11**（或紧邻高能锚词）、**同条评论中存在其他高置信度时间戳或显式时间句式（`开始/左右/那里/处/高潮`）**、且排除 `评分/百分比/年份/倍速/身高/版本号`。

## 5. Stage 3：倒计时检测与坐标逆向换算

**源码位置**：`CommentDataPipeline.js:765-808, 1244-1275, 1500-1545`。

1. **倒计时判定条件 (`isCountdownComment`)**：满足以下任一条件且**未触发否决条件**时置为 `true`：
   - **显式负号前缀**：存在带 `-` 号的时间戳（如 `-1:53:40`、`-58:06`）；
   - **逆序区间**：存在 `L4` 区间满足 `rawSeconds[0] > rawSeconds[1]`（跨度 ≥ 30s）；
   - **严格降序多点序列**：提取所有 `L1/L2/L3`（排除仅 `H` 小时整点）有效秒数序列，长度 ≥ 2、严格单调递减且首尾跨度 ≥ `30` 秒（避免 `2:29:25 vs 2:29:15` 10s 微小描述差误判）。
2. **一票否决守卫**：
   - 若评论中同时存在任意**正序 `L4` 区间**（如 `1.36-1.43.58`），则否决整条评论的倒计时判定；
   - 若包含 `X小时片子` 等全片总时长评价词，排除其对序列降序的干扰。
3. **负数区间双重反转修复 (`applyCommentCountdown`)**：
   - `validateMatch` 解析负数时间戳（如 `-1:42:07`）时保持 `rawSeconds = Math.abs(sec)`（`6127`），确保开关倒计时切换时执行单次线性映射：
     $$T_{\text{actual}} = \max(0,\ D_{\text{video}} - T_{\text{raw}})$$
   - 对区间数组自动重排序 `[Math.min(a,b), Math.max(a,b)]`，使得 `-1:42:07~-1:42:04`（`D=7200`）开启倒计时后正确映射为 `[1073, 1076]`，关闭后精准还原为 `[6127, 6124]`。

## 6. Stage 4：番号提取与同系列残缺尾号补全 (`extractAVCodes`)

**源码位置**：`CommentDataPipeline.js:1023-1240`。

### 6.1 上下文解析 (`parseSeriesContext`)
将传入的 `contextPrefix`（如 `"IPX-811"` 或 `"3DSVR-1234"`）拆解为：
- `seriesPrefix`：`"IPX"`（彻底杜绝旧版拼出 `IPX-811-1513` 的 BUG）
- `currentNumStr`：`"811"`，`digitLen`：`3`

### 6.2 屏蔽与三层提取流水线
1. **`maskForAvCodeScan(text)`**：预先将 `https?://...`、`magnet:?xt=...`、`{{PERSON_*}}` 匿名占位符与 `[url/img]` BBCode 替换为等长空格，彻底杜绝磁力链十六进制哈希中的数字被误识别为番号。
2. **显式番号提取（优先级高于上下文补全）**：
   - `oRegExp`：标准有码（`IPX-398`、`STARS-256`、`ipx 292`）；
   - `oRegExp_wuma`：无码格式（`FC2-PPV-1234567`、`010123-001`、`HEYDOUGA-4017-123`）；
   - `oRegExp2` / `oRegExp_wuma2`：同前导显式串联（支持 `、`、`和`、`跟`、`与`、`與`、`及`，如 `DDSC-031、036` ➔ `['DDSC-031', 'DDSC-036']`，`SSIS-465與437` ➔ `['SSIS-465', 'SSIS-437']`）。
   - 所有显式命中区间及 `timestampSpans`（时间戳区间）记录入 `occupiedSpans`。
3. **同系列残缺尾号补全**：
   - **纯数字无语义拦截**：若剥离标点空格后没有任何文字，仅放行 `0\d{2}` 形式（如 `"028"`），直接拦截 `"1513，1170，293"` 类多组纯数字刷屏；
   - **区间互锁**：与 `occupiedSpans` 重叠的数字一律跳过（保证 `DDSC-031、036` 中的 `036` 不会被当前页 `MISM` 抢占，`ipx 292` 的 `292` 不会被 `IPZZ` 抢占）；
   - **位数一致性**：要求 `numStr.length === digitLen`（仅当当前番号 `>= 700` 且出现过渡提示时允许 `3 -> 4` 进位至 `<= 1299`），一举拦截 4 位数刷屏与年份；
   - **语义与噪声守卫**：
     - 噪声词典拦截：`STANDALONE_NOISE_SLANG`（`2486`, `2333`, `2301`, `484`, `520`, `1314`, `666`, `250`, `91`, `426`, `401` 等）；
     - 身高/身材守卫（`145..198` 前后含 `身高/普遍/要是/我/她/的身高/厘米/矮男/腹肌`）；
     - 榜单/楼层/编码/分辨率/时间单位守卫（`Top 250`、`楼下283`、`h265`、`1080p`、`24小时`、`16厘米`、`16、7模样`）；
     - 强推荐语境或当前片番号确认：`STANDALONE_AV_CUE_PRE` / `STANDALONE_AV_CUE_POST`（`推荐641`、`不如490`、`上一部433`、`除了534和398`、`008，009，013`）。

## 7. Stage 5：高亮渲染与同系列联动 (`highlightCommentText`)

- **源码位置**：`CommentDataPipeline.js:1320-1460`。
- 时间戳渲染为 `.jc-time-link`（支持 ±5s 几何判重点亮收藏星标 `.is-favorited`）；
- 番号渲染为 `.jc-code-link`（`data-code="AEGE-490"`）；对仅在原文中以尾号形式出现的同系列推荐（如 `"远不如490"`），在避开 HTML 标签、实体和已替换占位符的前提下，直接将 `490` 包裹为 `<span class="jc-code-link" data-code="AEGE-490">490</span>`，点击即可弹窗预览或复制跳转；
- 最终 `processComment` 将同系列/显式命中的番号数字集合从 `L5` 时间戳中二次剔除，避免同一数字既当番号又当时间。
