## 1. PROBLEMS ENCOUNTERED (遇到的核心故障与排错过程)

在本阶段推进 **Peach 联动生态、虚拟 STRM 秒入库与跨站播放接力** 的实操中，我们遭遇了长达 8 项由浅入深、极度隐蔽的跨技术栈复合型故障：

1. **Top Layer 模态层绝对压制故障**：
   - *现象*：点击浮动按钮后控制台显示初始化成功，但在 Peach Web 页面上播放器和浮动按钮完全看不见；
   - *根因*：Peach Web 的作品详情页是一个原生模态 `<dialog id="stage" open>`，处于浏览器的 **Top Layer（顶层图层）**。普通的浮动按钮与播放器容器（`<miss-player-root>`）挂载在 `document.body` 普通文档流中。在 W3C 规范下，**Top Layer 的元素绝对压制普通文档流，无论设置多高的 z-index（哪怕 2147483647）均被死死盖在底层**。
2. **Web Component 与 Shadow DOM 视频探测盲区**：
   - *现象*：页面打开了视频，但浮动按钮判定无视频并自动隐藏（`display: none`），且无法解析番号；
   - *根因*：Peach Web 的播放器采用了 Web Components 架构（`<video-player><media-container><hlsjs-video>`），真实的 `<video>` 封装在 `<hlsjs-video>` 的 `#shadow-root (open)` 内部。传统的 `document.querySelectorAll('video')` 无法跨越 Shadow DOM 边界，导致视频节点漏检。
3. **油猴 `@match` 自定义端口阻断注入**：
   - *现象*：访问 `http://192.168.2.250:8900` 局域网地址时，脚本完全未注入、未执行；
   - *根因*：Tampermonkey / Stay 遵循 Chrome 扩展规范，`@match *://*/*` 默认**只匹配 HTTP 80 端口与 HTTPS 443 端口**，遇到 `:8900` 这类非标端口直接拒止注入。
4. **Chrome 私有网络访问策略 (PNA) 阻断局域网请求**：
   - *现象*：访问 `http://192.168.2.250:8900` 时，同源 `fetch()` 抛出 `Failed to fetch`，报错 `blocked by CORS policy: resource is in more-private address space local`；
   - *根因*：浏览器对非 HTTPS 局域网私有 IP（`192.168.x.x`）实施了 PNA 拦截，即使是页面自身的同源 fetch 也被直接阻断。
5. **油猴 `GM_xmlhttpRequest` 的 `responseType: 'text'` 导致 m3u8 下载 0B 的致命陷阱**：
   - *现象*：现场探针日志清晰打印：`[GMHlsLoader] m3u8 下载完成 (0B)`，导致 Hls.js 面对 0 字节空清单陷入无休止卡顿；
   - *根因*：Tampermonkey / Stay 官方允许的 `responseType` 只有 `arraybuffer, blob, json, stream`，**官方不存在 `text` 枚举**！当代码显式传了 `responseType: 'text'` 时，管理器因类型非法直接清空了 `responseText` 返回了空字符串 `""`！
6. **Web Worker 线程缺失 GM 特权 API 导致 Hls.js 卡死**：
   - *现象*：设置了 `fLoader: GMHlsLoader` 后，Hls.js 启动切片加载整整 8 秒内没有任何事件抛出，无回调无报错，直到看门狗超时；
   - *根因*：配置了 `enableWorker: true`。Hls.js 将切片加载交给后台的 Web Worker 执行，**但在 Web Worker 线程内部根本不存在任何 `GM_*` 特权 API**！Worker 内部抛出 `ReferenceError: GM_xmlhttpRequest is not defined` 并在子线程中被吞掉，导致主线程永远等不到回调。
7. **视频 CDN 强校验 Referer 防盗链抛出 `MEDIA_ERR_SRC_NOT_SUPPORTED`**：
   - *现象*：拿到了 Jable 和 123AV 的真实 m3u8 地址，但一给 `<video>` 起播，浏览器立即报错 `MEDIA_ERR_SRC_NOT_SUPPORTED (code: 4)`；
   - *根因*：这些流媒体 CDN 节点严格校验请求头必须携带对应的播放页 Referer（如 `Referer: https://sadie-shop.site/`）。浏览器原生 `<video>` 发起底层请求时携带的是当前穿透页面的 Referer（如 `fnos.net`），被 CDN 当场以 403 拒绝，`<video>` 收到 403 抛出格式不支持错误。
8. **跨轮次静态黑名单导致全源误杀“假象”**：
   - *现象*：用户实测在浏览器直接访问 3 个站均能播放，但在 Miss Player 探针里全部显示“404 未检索到有效流”；
   - *根因*：代码将上一轮试播超时的有效流放进了静态 `Set` 黑名单。下一次用户重新尝试时，系统在寻源阶段发现 URL 在黑名单里直接跳过，把所有有效源全判为失败。

## 2. PROVEN SOLUTION (验证有效的解决方案)

针对上述 8 大陷阱，我们实施了经过全套真实环境测试验证的工业级破局解法：

### 1. Top Layer 模态层继承挂载机制
在 `FloatingButton.js` 与 `UIManager.assembleDOM()` 中动态检查：
```javascript
const activeTopDialog = document.querySelector('dialog[open], [data-stage-host] dialog');
if (activeTopDialog && activeTopDialog.isConnected) {
    activeTopDialog.appendChild(this.rootHost); // 或 activeDialog.appendChild(this.button)
} else {
    document.body.appendChild(this.rootHost);
}
```
*效果*：浮动按钮与 Miss Player 播放容器天然进入 Top Layer，绝对压制宿主任何模态弹窗，100% 毫无遮挡呈现。

### 2. 递归穿透 Shadow DOM 的全景视频探测
在 `src/utils/dom.js` 中实现 `queryAllVideosDeep`：
```javascript
export function queryAllVideosDeep(root = document, maxDepth = 4) {
    if (!root || maxDepth < 0) return [];
    const videos = [];
    try {
        if (typeof root.querySelectorAll === 'function') {
            videos.push(...Array.from(root.querySelectorAll('video')));
            const elements = root.querySelectorAll('*');
            for (let i = 0; i < elements.length; i++) {
                if (elements[i].shadowRoot) {
                    videos.push(...queryAllVideosDeep(elements[i].shadowRoot, maxDepth - 1));
                }
            }
        }
    } catch (_) {}
    return videos;
}
```

### 3. Userscript Header 补充任意端口 `@include`
在 `vite.config.mjs` 和 `webpack.config.js` 的 Userscript 配置中增加：
```javascript
include: [
    '*',
    'http://*/*',
    'https://*/*',
    'http://*:*/*',
    'https://*:*/*'
]
```

### 4. Chrome PNA 私有网络策略自动降级
在 `src/utils/http.js` 中：同源 `fetch()` 发生异常时，自动平滑降级至 `GM_xmlhttpRequest`，利用油猴扩展特权网络栈穿透 Chrome 私有网络拦截。

### 5. `GMHlsLoader` 杜绝非法 `responseType` 与二进制安全解码
```javascript
// 仅在明确需要二进制切片/密钥时设置 arraybuffer，文本请求绝不传非法 'text'
if (responseType === 'arraybuffer') {
    reqOpts.responseType = 'arraybuffer';
}
// 数据接收时：
let data = '';
if (responseType === 'arraybuffer') {
    data = res.response;
    if (!(data instanceof ArrayBuffer) && data && data.buffer instanceof ArrayBuffer) data = data.buffer;
} else {
    data = res.responseText || '';
    if (!data && res.response) {
        if (typeof res.response === 'string') data = res.response;
        else if (res.response instanceof ArrayBuffer) data = new TextDecoder('utf-8').decode(res.response);
    }
}
```
*实测结果*：m3u8 准确拉取 51928 字节，彻底终结 0B 卡死。

### 6. Hls.js 禁用 Web Worker 确保主线程特权
```javascript
this._hlsInstance = new HlsClass({
    fLoader: GMHlsLoader,
    pLoader: GMHlsLoader,
    enableWorker: false, // 必须为 false！强制在拥有 GM_xmlhttpRequest 的主线程执行！
    lowLatencyMode: true
});
```

### 7. 强注 Referer 彻底消灭 CDN 防盗链 403
通过 `GMHlsLoader`，无论是请求 `.m3u8`、AES-128 解密 Key、还是每个 `.ts` 分片，全部注入 `Referer: streamInfo.referer`，CDN 全绿灯 200 OK 放行。

### 8. 彻底废除跨轮次静态黑名单
将黑名单收敛至单轮次局部 `const roundFailedUrls = new Set()`，单次失败仅在本轮瀑布流内尝试下一个源，绝不跨会话记忆，保证用户每次操作均能重新完整探测所有源。

## 3. PITFALLS & ANTI-PATTERNS (避坑指南与反模式禁令)

- 🔴 **FORBIDDEN**: 在包含原生模态 `<dialog open>` 的现代页面上，盲目将全屏浮层或主视口追加挂载在 `document.body` 上（被 Top Layer 绝对压制）  
  ➔ 🟢 **USE**: 检查页面是否存在处于 Top Layer 的 `dialog[open]`，若存在，动态将组件提升挂载至该 `<dialog>` 内部以继承最高渲染层级。
- 🔴 **FORBIDDEN**: 假设 `<video>` 总是存在于普通主 DOM 树中，仅使用 `document.querySelectorAll('video')` 探测  
  ➔ 🟢 **USE**: 使用 `queryAllVideosDeep` 递归遍历所有挂载了 open `shadowRoot` 的自定义元素（如 `<hlsjs-video>`、`<video-player>`）。
- 🔴 **FORBIDDEN**: 在油猴脚本中仅声明 `@match *://*/*` 却期望其在带有非标准端口（如 `:8900`, `:8000`）的局域网 IP 上生效  
  ➔ 🟢 **USE**: 必须显式声明 `@include http://*:*/*` 与 `@include https://*:*/*`。
- 🔴 **FORBIDDEN**: 在给 Hls.js 编写基于油猴 `GM_xmlhttpRequest` 的自定义 Loader 时开启 `enableWorker: true`  
  ➔ 🟢 **USE**: 必须显式设置 `enableWorker: false`，因为 Web Worker 线程内部根本无法访问主线程沙箱的 `GM_*` 特权 API。
- 🔴 **FORBIDDEN**: 在调用 `GM_xmlhttpRequest` 请求文本内容时传递 `responseType: 'text'`  
  ➔ 🟢 **USE**: 文本请求绝不传 `responseType` 属性，仅在明确请求二进制 `ArrayBuffer` 时才传 `'arraybuffer'`；响应端使用 `res.responseText` 并以 `TextDecoder` 兜底解码。
- 🔴 **FORBIDDEN**: 使用静态持久化的 `Set` 黑名单记录试播失败的流，导致跨轮次全源误杀  
  ➔ 🟢 **USE**: 黑名单仅作用于单次寻源流水线内部（局部变量），每次用户交互重新寻源时拥有完全平等的重试机会。

## 4. SCALING TO AGENTS.MD (全局系统宪法提炼)

提炼原子级核心系统准则，纳入《AGENTS.md》：

```markdown
* **HTML5 Top Layer 模态层穿透挂载准则 (Top Layer Dialog Inheritance)**：
  - 凡需在第三方页面（如 Peach Web 作品舞台、Bootstrap Modal 等）展示全屏浮层、播放器视口或浮动控制按钮时，严禁盲目直接 `document.body.appendChild`；
  - 必须优先检查当前 DOM 是否存在处于激活状态的原生模态 `<dialog open>`，若存在，必须将组件动态提升挂载至该 `<dialog>` 内部以继承 Top Layer 最高渲染层级，彻底杜绝被宿主模态层强制压制遮挡；

* **Web Components 深度穿透探测规范 (Deep Shadow DOM Piercing)**：
  - 探测宿主音视频媒体元素时，严禁依赖单一层级的 `document.querySelectorAll('video')`；
  - 必须采用递归深度遍历算法（`queryAllVideosDeep`），穿透所有开放的 `element.shadowRoot`，彻底解决组件化播放器（如 `<hlsjs-video>`）内部视频元素漏检问题；

* **油猴特权 HLS 切片加载器主线程收敛纪律 (Main-Thread GMHlsLoader Constraint)**：
  - 在使用 `GM_xmlhttpRequest` 自定义 Hls.js 的切片加载器（`fLoader` / `pLoader`）注入防盗链 Referer 时，必须强制设置 `enableWorker: false`；
  - 严禁开启 Web Worker 导致子线程因缺失 `GM_*` API 静默崩溃挂起；文本清单请求严禁传递非法 `responseType: 'text'` 导致返回体被置空为 0B。
```
