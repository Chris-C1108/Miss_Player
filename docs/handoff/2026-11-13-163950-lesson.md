# Lesson Learned: 评论识别正则串扰治理、同系列番号消歧与零停机上报演进

**时间戳**: 2026-11-13 16:39:50  
**关联版本**: `v5.7.118-beta.030`

---

## 1. Masking 黑名单吞噬左邻时间分段的边界陷阱
- **问题现象**：`28:10 本片超经典` 中的 `10 本` 被 `maskBlacklist` 的量词规则 `\d+\s*本` 替换成 `_QUANTITY_`，导致文本变为 `28:_QUANTITY_`，`28` 退化为孤立数字并被 `L5` 拒绝，造成完整时间戳漏抓。
- **反模式禁令**：
  - `FORBIDDEN: 在 maskBlacklist 中编写无左边界约束的 \d+\s*(?:分|本|发|部|套|次|...)` -> `USE: 必须强制添加 (?<![:：.\d]) 左边界否定后顾，杜绝量词/单位黑名单啃食 HH:MM:SS 或 H.MM 的尾段数字`。

## 2. 上下文同系列残缺番号补全的三重污染源
- **问题现象**：直接用 `contextPrefix`（且调用方误传 `IPX-811` 全号而非 `IPX`）扫描独立数字，导致：
  1. 拼出 `IPX-811-1513` 畸形双连字符假番号；
  2. 显式跨系列串联如 `DDSC-031、036`、`SSIS-465與437`、`ipx 292` 的尾号被当前页前缀抢占为 `MISM-036`；
  3. 身高（`170`、`180`）、Top 250、台湾黑话（`2486`）、楼层及 4 位刷屏数字大量误判。
- **反模式禁令**：
  - `FORBIDDEN: 对 comments 中所有 \b\d{2,4}\b 无条件拼接 ${contextPrefix}-${num}` -> `USE: 先解析纯前缀与基准位数 -> 屏蔽 URL/磁链/显式番号区间/时间戳区间 -> 校验同位数与语义上下文守卫 -> 并将已识别番号数字从 L5 孤立数字池排除`。

## 3. Supabase Schema 升级与生产前向兼容
- **问题现象**：旧版 `comment_reports` 仅记录文本和自由备注，不记录 `video_duration`、`parser_snapshot`、`reason_code` 与 `expected_hint`，导致事后复盘必须盲猜当时识别了什么。
- **反模式禁令**：
  - `FORBIDDEN: 客户端硬切新版 RPC 参数而未部署数据库 migration 时直接报错静默丢失用户反馈` -> `USE: 优先请求扩展 RPC v2，失败时自动降级调用原 6 参数 RPC v1 并把结构化诊断快照拼接至 p_user_note`。
- **Caller 契约检查教训**：
  - `CommentPanel.js` 的 `_mergeRemoteComments` 与 `_mergeWebdavComments` 长期误将 `(duration, published_at)` 传给 `processComment(text, contextPrefix, videoDuration)`，导致 `videoDuration` 变成日期字符串 `NaN`；重签名或跨文件调用必须核对全量调用点参数顺序。
