## 🎯 需求出发点与设计初衷 (Origin & Motivation)

1. **传统磁力入库的低效痛点**：
   - 官方 `peach-userscript` 依赖磁力离线云下载：提交番号 ➔ 搜索 BT 磁力 ➔ 推送 115/PikPak 离线下载 ➔ 耗时数十分钟下载几十 GB 原盘落地 ➔ 媒体库刮削；
   - 存在网盘配额耗尽、冷门死链下载停滞、存储空间爆炸、以及第三方挂件（`#peach-jav-action`）z-index 霸屏破坏页面体验等痛点。
2. **核心业务构想（降维打击）**：
   - Miss Player 运行在在线播放页上（Jable / MissAV 等），已掌握视频流直链；
   - 能否在用户看片时，生成仅数十字节的 `.strm` 虚拟视频指针文本，通过 WebDAV 远程直写 NAS 媒体目录，让 Peach 0 秒完成入库与元数据自动刮削？
3. **真实网络与播放痛点（深入深水区）**：
   - 在线站的 m3u8 普遍存在 **AES-128 加密**、**短期动态 Token（2~6小时过期）** 与 **上游 CDN Referer 严格防盗链 (403)**，静态写死流地址必然沦为死链；
   - 必须实现“Miss Player 双端接力架构”：在 Peach Web 端识别虚拟视频，现场动态按番号重新寻源拉取当期新鲜流，通过 GM 栈伪造 Referer 破除防盗链起播，并双向回写 Peach 观看进度与续播状态；
   - 彻底消灭复杂的配对 JSON 复制粘贴流程，实现访问 Peach Web 时的零门槛自动配对与多 Origin（公网/局域网IP/Tailscale/localhost）智能地址池化自愈。

## 💡 方案思路演进 (Architecture & Evolution)

```
[ 源站播放页 (Jable / MissAV) ]
  │
  ├─► 1. MediaSniffer 毫秒级捕获当前 m3u8
  ├─► 2. StrmIngestPipeline 构造标准化 [AVCODE].strm (首行流地址 + 元数据注释)
  ├─► 3. WebDavClient 远程原子 PUT 至用户 NAS 的 Peach 媒体目录 (/Media/STRM/)
  └─► 4. PeachService 调用 POST /api/resource-sync/scan 触发对账刮削
        │
        ▼ (Peach 0秒自动刮削封面、女优与标签)
[ Peach Web 管理中心 (自托管实例) ]
  │
  ├─► 5. 访问自适应：自动纳管多 Origin (局域网 192.168.x.x、公网域名、mDNS)，零输入自动配对
  ├─► 6. 媒体源巡检：检测 WebDAV STRM 目录是否加入 Peach 媒体库，提供 Apple 风格挂载引导卡片
  ├─► 7. 播放视口接管：穿透 Shadow DOM 捕获 <video>，动态提升至 Top Layer 模态层消除遮挡
  ├─► 8. 多源瀑布流寻源：Jable ➔ 123AV (免盾免死链) ➔ 自建独立采集端 ➔ MissAV
  ├─► 9. GMHlsLoader 引擎：主线程强注 Referer，利用 Web Cryptography API 完成 AES-128 硬件解密起播
  └─► 10. 双向进度回写：每 10s 同步 POST /api/activity 与 localStorage 续播键，Peach 账本实时推进
```
