# Session Lessons & Anti-Patterns: 双功能手柄状态割裂、手势源头白名单隔离、动态约束实时重算与视口平滑过渡

- Date & Time: 2026-11-04 19:08:55
- Focus Module: SingleHandManager, DragManager, VideoSwipeManager, VolumeController, PlaybackController

## 1. PROBLEMS ENCOUNTERED (遇到的核心问题与故障)
1. **控制面板多行手势串扰与误触左右手单手模式**：
   - 现象：用户在底部切换播放模式（快览/正常/连播）或在进度条上滑动调时间时，频繁误触发左右手单手模式切换，控制栏瞬间发生水平移位与镜像变形。
   - 触发条件：手指在 `.tm-playback-control-row` 或 `.tm-progress-row` 进行水平轻扫。
2. **多功能手柄（Dual-Purpose Handle）状态割裂导致 Minimap 偶尔不显示**：
   - 现象：拖动视频区域下方手柄调整视频大小时，角落下方的微缩全景图（Minimap）有时显示、有时完全不显示，或者拖动 400ms 后突然凭空消失。
   - 触发条件：视频从较小高度（如收缩态或矮画幅）开始向下拖拽拉伸，或在触摸屏设备上持续拖动超过 400ms。
3. **收缩态视口调整大小发生瞬间闪跳 (Viewport Jump on Resize)**：
   - 现象：在移动端评论区视口自动收缩态（210px）下，按住手柄调整大小时，画面瞬间猛烈跳变回历史大尺寸（如 380px），随后的拉伸也是从 380px 开始，视觉体验极不流畅。
   - 触发条件：处于 `is-collapsed-ratio` 态时触发 `startHandleDrag`。
4. **倍速设置每次进入播放器重置为 1.0x (Speed Reset Bug)**：
   - 现象：用户明明之前调到了 1.2x 或 1.5x，但换个视频或刷新网页后，播放速度必定重置回 1.0x。
   - 触发条件：重新打开播放器，或宿主站点在 `loadedmetadata` 时强制重置了 `<video>.playbackRate`。
5. **默认静音策略长期静默失效**：
   - 现象：设计上有 5 分钟超时恢复默认静音的机制，但实际上新用户或日常使用中从不生效，进入播放器直接外放声音。
   - 触发条件：未去设置页手动开启 `defaultMuted` 开关。

## 2. ROOT CAUSE ANALYSIS (根本原因剖析)
1. **盲目扩大手势监听容器，缺乏源头白名单约束**：
   - `SingleHandManager` 将手势监听挂载在整个控制面板顶层容器上，仅简单排除了进度滑块，导致底部模式切换栏和进度条全区域的触摸事件冒泡后全部被单手手势拦截器接管。
2. **多管理器共用单一 DOM 手柄时的生命周期与状态孤岛**：
   - 视频下方手柄（`.tm-resize-handle`）同时承载了垂直拉伸（`DragManager`）与水平平移/微缩图（`VideoSwipeManager`）两个职责；
   - `DragManager` 在垂直拉伸高度改变容器尺寸时，从未通知 `VideoSwipeManager`；
   - `VideoSwipeManager` 的 `_handleHandlePointerDown` 依赖旧的静态 `maxOffset`，若拖拽前视频无溢出（`maxOffset <= 0`），则根本不会添加 `.is-swiping` 类；且 400ms 延迟淡出定时器只检测自身拖动状态，不知道 `DragManager` 正在进行拉伸，导致 Minimap 被强行提前杀死。
3. **唤醒控制栏时的状态机重入副作用**：
   - `DragManager.startHandleDrag` 检测到收起态时调用了 `showControls()`，而 `showControls()` 内部自动调用 `updatePortraitVideoHeight()`，后者强制将行内高度覆盖为 `expandedHeight`，导致几何基准瞬间突变。
4. **存储键名分裂与宿主元数据重置攻击**：
   - `PlaybackController` 写入的是 `preferredPlaybackRate`，而 `PlayerCore.restoreVideoState` 读取的是 `playbackRate`，因读出空值导致永远回退到 1.0x；且宿主站点加载视频流时原生事件会将 video 属性重置。
5. **关键特性默认开关配置反转**：
   - `PlayerState.js` 和 `storage.js` 将 `defaultMuted` 设为 `false`，导致核心超时重置逻辑的前置判断 `if (!defaultMuted) return false;` 永远短路返回。

## 3. PROVEN SOLUTION (验证有效的解决方案)
1. **手势源头白名单与多行独立放行**：
   ```javascript
   // 明确限制左右手切换仅源自快速跳转行
   this._isFromSeekRow = Boolean(target?.closest?.('.tm-seek-control-row'));
   // 胶囊行与模式切换行放行原生水平滑动
   if (this._isFromCapsuleScroll || this._isFromPlaybackRow) {
       if (Math.abs(dx) >= Math.abs(dy)) return; // 坚决不拦截水平原生滑动
   }
   if (this._isFromSeekRow !== undefined && !this._isFromSeekRow) {
       return; // 严禁非快速跳转行触发左右手切换
   }
   ```
2. **手柄管理器双向协同联动与 Minimap 尺寸前置固化**：
   - 无论是否存在水平溢出，只要视频比例就绪，`VideoSwipeManager` 无条件前置计算固化 Minimap 物理尺寸；
   - 在按压手柄时同步执行 `_doUpdateConstraints()` 刷新最新约束；
   - `DragManager` 在拖拽开始、拖拽移动中动态驱动 `swipeManager._doUpdateConstraints()`，溢出时激活 `.is-swiping` 并同步视口，并在释放后统一延迟淡出；
   - `VideoSwipeManager` 400ms 定时器加入 `!dragManager.isDraggingHandle` 守卫，杜绝误杀。
3. **收缩态拖拽以实际当前可见高度为基准**：
   ```javascript
   if (isCollapsed && currentVisibleHeight > 0) {
       this.startHeight = currentVisibleHeight;
       this.uiManager.customHeightPortrait = `${currentVisibleHeight}px`;
       this.container.classList.remove('is-collapsed-ratio');
       this.container.style.height = `${currentVisibleHeight}px`;
   }
   //并在 UIManager.updatePortraitVideoHeight 中加入 isDraggingHandle 拦截守卫
   ```
4. **倍速键名权威统一与元数据防篡改保卫**：
   - 全链路统一使用 `preferredPlaybackRate`，并在倍速按钮点击时同步通知 `playerState.updateSetting`；
   - 在 `loadedmetadata` 和 `canplay` 时增加主动保卫，若被宿主置为 1.0x 则立刻纠偏恢复。

## 4. FORBIDDEN & ANTI-PATTERNS (避坑禁令与反模式)
- `FORBIDDEN: 在多层复用手柄 (Dual-Purpose Handle) 上各管理器各自监听事件且状态完全割裂 -> USE: 垂直拉伸管理器 (DragManager) 与水平平移微缩指示管理器 (VideoSwipeManager) 在拖拽开始、移动、释放各阶段深度双向协同联动与生命周期互锁`
- `FORBIDDEN: 依赖手势按下前的静态/过时几何约束 (maxOffset) 决定是否渲染辅助浮层 (Minimap) -> USE: 手势交互开始时同步立即重算约束 (recompute constraints on interaction)，并在连续拉伸中动态自适应触发显隐`
- `FORBIDDEN: 在收缩态视口唤醒控制层时盲目还原历史舒展高度导致视口瞬间跳跃 -> USE: 优先捕获当前用户实际可见物理高度 (currentVisibleHeight) 作为基准开始拉伸，并在拖拽生命周期内锁定自动覆盖`
- `FORBIDDEN: 在多个组件间使用不一致的存储键名 (如 preferredPlaybackRate vs playbackRate) 导致配置静默还原默认值 -> USE: 严格保持读写键名单一权威源，并在 loadedmetadata/canplay 事件中增加宿主脚本重置拦截保卫`
- `FORBIDDEN: 假设全局容器滑动事件能自动正确识别业务区域 -> USE: 采用严格的白名单选择器隔离手势 (如仅 tm-seek-control-row 允许切换单手模式，其余横向滚动/模式切换区域完全放行)`

## 5. CANDIDATE RULE FOR AGENTS.MD (准则提炼建议)
在 `AGENTS.md` 的 UI/UX 与状态机交互规范中补充：
- **多功能复合手柄双向联动准则 (Dual-Purpose Handle Synchronization)**：
  当单一手柄同时承载视口物理尺寸拉伸与画面微缩指示器（Minimap）显示时，拉伸管理器必须在手势开始、移动与释放全生命周期主动驱动微缩图管理器的几何约束重算与显隐状态，并在淡出定时器中实现多管理器互锁，杜绝由于状态孤岛导致辅助指示器偶尔丢失或闪烁。
