## 1. 核心成果拓扑与修复全景

针对录屏揭露出的三大恶性交互缺陷，实施了从 CSS 几何架构、手风琴状态机到视口防刷机制的闭环重构：

### 1.1 CSS 几何防压扁与流式自适应排布
- **根因**：
  1. `_comments_sections.css` 中 `.tm-comment-section:not(.is-collapsed)` 设置 `flex: 0 1 auto; max-height: 100%`，而子元素 `.tm-comment-section-body` 设置 `flex: 1; min-height: 0; overflow-y: auto`。在外层 `.tm-comments-list` 为未定高可滚动 Flex 容器时，WebKit 判定子容器最小内容高度（min-content）为 0，导致 body 高度直接归零被裁剪，**展开看不见评论条目**；
  2. `_landscape.css` 中声明 `.tm-comment-section { min-height: 0; flex-shrink: 1; overflow: hidden; }`，在 Flex 容器挤压下把折叠状态的 section 压缩至 0px，加上 `overflow: hidden` 导致标题文字全部被裁切，**只剩 3px 边框变成一条细线**。
- **治理**：
  - `.tm-comment-section`：强制声明 `flex: 0 0 auto; flex-shrink: 0; min-height: 38px;`，彻底移除破坏性的 `transition: flex`；
  - `.tm-comment-section-hdr`：显式声明 `min-height: 36px; height: 36px; flex-shrink: 0;`，确保折叠态下标题与徽标 100% 完整可见，并引入 Apple 风格展开箭头（`::after`，展开时向下旋转 45°，折叠时向右旋转 -45°）；
  - 展开态 `.tm-comment-section-body`：移除 `flex: 1` 循环死锁依赖，设为自然流式 `height: auto; min-height: 0;`，外层滚动条统一承载惯性滚动，消灭嵌套滚动冲突；
  - `_landscape.css`：彻底移除对 `.tm-comment-section` 的破坏性覆盖。

### 1.2 手风琴状态机全折叠死锁自愈 (Accordion Deadlock Healing)
- **根因**：`CommentPanel.js` 从 localStorage 读取折叠状态，当所有源均为 `collapsed = true` 时，初始化与加载链路缺乏兜底展开逻辑，导致评论区陷入“全黑全折叠”死锁。
- **治理**：
  - 新增 `ensureAtLeastOneSectionExpanded()` 兜底策略：检测到所有源均折叠时，按照“有内容者优先（Jable ➔ JavDB ➔ JavLibrary）”的原则自动恢复至少一个可用分区为展开态，并同步更新 localStorage；
  - 新增 `toggleSectionCollapse(siteKey)`：实现手风琴互斥展开机制，展开当前源的同时折叠其余源；直接操作 DOM `classList.toggle('is-collapsed')`，**彻底杜绝重绘 innerHTML 导致的卡顿闪烁与视口重排**。

### 1.3 `checkViewportFill` 视口守卫与防死循环狂刷 (Loop-Free Viewport Filling)
- **根因**：原 `checkViewportFill` 检查 `body.scrollHeight <= body.clientHeight + 10`，在异常小高度或未展开时误判视口未填满，触发 `triggerLoadMoreJavdb()`，导致录屏中评论数从 153+ 连续暴涨至 213+ 的恶性死循环。
- **治理**：
  - 引入外层滚动容器判定：`if (container.clientHeight < 100) return;`（视口过小或未就绪时立即阻断）；
  - `if (container.scrollHeight > container.clientHeight + 20) return;`（只要外层列表已出现滚动条，说明内容已填满，立即退出）；
  - 统一外层滚动事件与 touchmove 触底监听，平滑触发当前展开分区的下一页懒加载。
