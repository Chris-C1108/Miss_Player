# 经验教训总账 (2026-11-13-141500)

## 🚨 核心反模式与治理规范 (FORBIDDEN -> USE)

### 1. 顶部指示器与异步采集状态机脱节反模式
- 🔴 **FORBIDDEN**: 在异步多步骤数据流（初次请求、分页增量追加、错误重试）中，仅在组件初始化阶段计算一次顶部指示器或统计数值（如高能现场评论数），导致数据到达后顶部指示器处于冻结态。
- 🟢 **USE**: 将指示器重算收敛为全局幂等方法（`updateTabBar()`），并在数据流终点生命周期守卫处（如 `loadSiteComments` 的 `finally` 块及 `patchSectionContent` 的追加成功分支）无死角显式调用；数据获取层采用防御性回退（优先 `filteredComments`，回退至 `comments`），杜绝统计死锁。

### 2. 动静态元素混排导致几何漂移反模式
- 🔴 **FORBIDDEN**: 将条件展示的交互按钮（转为正序、转存、上报）与常驻静态元数据（时间、评分）混杂在同一 Flex 容器且无固定次序，导致按钮出现或消失时，最关键的评分徽章在整行横向左右晃动。
- 🟢 **USE**: 实行“动静分区架构”——将动态交互按钮封装在 `.jc-row-actions`，静态元数据封装在 `.jc-row-meta`，通过自然 DOM 物理顺序让 `.jc-row-meta`（评分）始终锚定在头部最右侧；操作按钮的显隐仅在自身容器内做平滑微位移与淡入淡出（`translate3d(4px, 0, 0)` -> `translate3d(0, 0, 0)`），不引起任何兄弟元素的几何抖动。

### 3. 操作控件全量铺满引发视觉杂讯反模式
- 🔴 **FORBIDDEN**: 在每一条信息流条目中无条件常驻显示低频操作按钮（如转存、上报等），造成密集排版下的严重视觉疲劳与误触。
- 🟢 **USE**: 引入“按需唤醒微胶囊体系”：默认状态下 `opacity: 0; pointer-events: none` 隐形；PC 桌面端利用 `@media (hover: hover)` 由原生 `:hover` 与 `:focus-within` 零 JS 极速唤起；移动端通过轻触单行激活 `.is-active-row`，多行互斥排他，并在列表滚动时静默收起，兼顾沉浸式阅读与随手可用。
