# Session Lessons & Anti-Patterns: 视频手柄双重写入竞态、流媒体内存驱逐、事件假阳性与ShadowDOM捕获断层

- Date & Time: 2026-10-31 07:52:41
- Focus Module: `videoSwipeManager.js`, `ProgressManager.js`, `PlayerCore.js`, `BlurPlaybackManager.js`

## 1. PROBLEMS ENCOUNTERED (遇到的核心问题与故障)
1. **手柄在拖拽拉伸高度时左右疯狂闪动 (Jitter/Oscillation)**：
   - 现象：按住手柄向下拖拽放大视频时，手柄在左右几像素之间以 60Hz 频率剧烈横跳闪动，一松手瞬间静止不闪。
2. **手柄轴向排他锁死陷阱 (Axis Lockout)**：
   - 现象：按住手柄后，若稍微先上下移动了一点，后续无法再斜向左右平移，必须抬手松开重新按压。
3. **开播期点击暂停后缓冲完成仍自动偷跑播放**：
   - 现象：一进入播放器即点击暂停，居中胶囊显示暂停三角，但几秒后视频流缓冲完成，视频依然自动播放。
4. **进度条触摸展开时把热度图向上挤压进时间文字**：
   - 现象：手指一按进度条，热度图向上突跳 5px，波峰直接穿插进时间文字中。
5. **正常顺畅播放中进度条底槽误报条纹动画**：
   - 现象：视频播放完全顺畅毫无卡顿，进度条底槽却突然冒出卡顿流动条纹且不再消失。

## 2. ROOT CAUSE ANALYSIS (根本原因剖析)
1. **双重异源写入并发竞态 (Dual-Write Race Condition)**：
   - 进程 A（手势线程）：`pointermove` 每秒 60 次根据微小的手指水平抖动更新 `newHandleX`；
   - 进程 B（重绘线程）：`DragManager` 拉伸高度导致容器变大，高频触发 `ResizeObserver` ➔ `_updateConstraints` ➔ `_updateHandlePosition`，每一帧又强行将手柄拉回 `centerX`；
   - 两个异源指令每秒交替互搏 60 次，导致手柄剧烈左右闪动。
2. **事件监听器自杀式销毁**：
   - 旧代码在检测到 $\Delta Y > \Delta X$ 时，错误地主动调用了 `_handleHandlePointerUp` 将移动监听器从 DOM 移除，导致该手势后续的 X 轴链路彻底死亡。
3. **Shadow DOM 事件隔离导致状态判定断层**：
   - 播放器 UI 按键位于 `<miss-player-root>` Shadow DOM 内部并调用了 `e.stopPropagation()`，导致宿主 `document` 上的交互监听未收到事件，`BlurPlaybackManager` 误以为“用户没有点击”，把暂停误判为网络卡顿停滞（`BUFFER_STALL`），进而在 `canplay` 时强行调用 `play()` 自动拉起！
4. **HTML5 `stalled` 事件的致命假阳性误区**：
   - `stalled` 在 W3C 规范中仅代表网络下载线程暂时休眠等待，流媒体 HLS 下载完前向切片后进入正常休眠即会派发 `stalled`，与视频是否卡顿完全无关。旧代码监听 `stalled` 导致顺播误报卡顿条纹。
5. **流媒体物理内存驱逐与不可控常规缓冲层**：
   - 移动端 HLS 在用户发生 Seek 跳转时，会自动调用 `sourceBuffer.remove()` 驱逐旧切片以释放内存；试图在长片中维持全量静态缓冲条与现实底层相违背。

## 3. PROVEN SOLUTION (验证有效的解决方案)
1. **中心锚定 + 拖拽态阻断异源重绘**：
   - 手柄在 CSS 与数学上基准锚定在中心 `left: 50%; top: 50%; transform: translate3d(-50%, -50%, 0)`；
   - 在 `isHandleDragging` 拖拽活动态期间，`_updateHandlePosition` 坚决跳过异步覆盖；当 `maxOffset <= 0` 时硬编码锁死居中。
2. **双轴独立解耦 (Dual-Axis Freedom)**：
   - 彻底删除排他性注销代码，手势监听统一委托 `window`，$\Delta X$ 平移与 $\Delta Y$ 高度拉伸正交并行，支持斜向任意连续操作。
3. **全局暂停意图权威锁 (Global Pause Lock)**：
   - `PlayerCore.userPauseIntent` 原子置位，`PlayerCore.attemptPlay`、`onReadyToPlay` 以及 `BlurPlaybackManager.attemptAutoResume` 必须第一行先行校验该锁，只要用户主动暂停，任何自动起播与恢复尝试瞬间熔断。
4. **物理停滞判据 + 播放头前进看门狗**：
   - 彻底剔除 `stalled` 监听；引入 180ms 防抖 + `readyState < 3` 确认真正物理卡顿；在每秒 4 次的 `timeupdate` 中注入看门狗，只要播放时间前进瞬间熄灭条纹动效。
5. **热度图底边物理基准线锁死**：
   - 热度图 `bottom` 锁死在固定 9px，高度收敛为 15px，时间文字外边距拉宽至 9px，彻底根绝展开时的挤压跳动。

## 4. PITFALLS & ANTI-PATTERNS (避坑指南与反模式禁令)
- FORBIDDEN: 监听 HTML5 媒体的 `stalled` 事件来判定播放卡顿 -> USE: 严格以“物理播放头是否停止前进 + `readyState < 3`”作为物理停滞的唯一判定依据，并在 `timeupdate` 中加入心跳灭火守卫。
- FORBIDDEN: 在手势处于活动拖拽（`isDragging`）期间允许 ResizeObserver 或外部定时器异步覆写组件物理坐标 -> USE: 拖拽期间建立单向手势控制锁，屏蔽任何外部异源位置篡改，杜绝 60Hz 左右疯狂抽搐闪动。
- FORBIDDEN: 在多方向手势（如手柄拉伸与平移）中因某一轴向优先位移而粗暴注销另一轴向事件监听器 -> USE: 保持双轴（X/Y）正交解耦独立计算，委托 `window` 捕获完整手势生命周期，支持斜向自由连续滑移。
- FORBIDDEN: 在宿主页面 `document` 上监听交互来推断 Shadow DOM 内部组件的点击状态 -> USE: 建立全局状态机权威锁（如 `playerCore.userPauseIntent`），通过显式函数调用通知跨层级管理器，杜绝事件穿透失败引发的误判自动起播。
- FORBIDDEN: 尝试在移动端流媒体（HLS / MSE）长片上维持脆弱且易被浏览器底层内存机制强制驱逐的常规静态缓冲条 -> USE: 放弃常规静态缓冲层，改为仅在卡顿等待时呈现流体对角条纹动效，明确向用户传达“正在缓冲中、绝非假死”。
