# Lessons Learned — 2026-11-13 19:17:00

## 1. 提取层与渲染层边界正则必须端到端同测 (`textHtml` 断言不可缺位)
- **FORBIDDEN**: 仅在单元测试中校验 `extractAVCodes` / `processComment` 的结构化数组输出（如 `avcodes = ['STARS-145','STARS-232','STARS-256']`），忽略校验渲染层 `textHtml`；当 `highlightCommentText` 的 `safeScanRegex` 边界字符集误包含 `/` 时，结构化测试全绿但真机界面完全无高亮 -> **USE**: 对斜杠/特殊分隔符语法糖，单元测试与黄金集必须同时断言 `textHtml` 产出预期的 `.jc-code-link` / `.jc-time-link` DOM 胶囊。

## 2. 高噪单小时表达必须要求定位锚点或时间共现
- **FORBIDDEN**: 无条件将独立出现的 `一小时` / `两小时` / `2h` 视为跳转时间点（在 31,685 条评论实测中 70.6% 为 `全片两小时`、`猛烈冲击近两小时`、`一小时前` 等片长/耗时/相对发布时间误报） -> **USE**: 对 `isSingleHour` 仅在存在明确定位锚点（`的时候/前后/附近/后的` 等）或同条评论伴随其他时间点时放行，并屏蔽 `全片/整片/近/冲击/看了/前` 等片长语境。

## 3. 区间右端纯分钟必须支持小时继承
- **FORBIDDEN**: 将 `1h47m到50m` 中的 `50m` 当作 `00:50:00 (3000s)` 与 `1h47m (6420s)` 比较，导致 `6420 > 3000` 误触发全评倒计时反转 -> **USE**: 在 `mergeRanges` 中检测 `小时时间 ~ 纯分钟 (<60)` 且 `nextMin > curMin` 时自动继承左端小时基数（`1h50m = 6600s`）。
