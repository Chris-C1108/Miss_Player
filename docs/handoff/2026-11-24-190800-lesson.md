# Session Lessons & Anti-Patterns: 自动收藏与手动收藏优先级分裂及跨端同步倒挂陷阱 (v5.7.121)

- Date & Time: 2026-11-24 19:08:00
- Focus Module: `src/player/subtitles/SubtitleManager.js`, `src/player/subtitles/SubtitleRepository.js`

## 1. PROBLEMS ENCOUNTERED (遇到的核心问题与故障)
- **潜在优先权漂移**：引入偏好语言「自动选优收藏」后，若不区分条目的收藏来源（手动 vs 自动），会出现四类优先权倒挂风险：
  1. 自动收藏字幕评分高于用户后手动收藏的字幕时，列表排序与默认激活逻辑无法保证手动收藏置顶并胜出；
  2. `bundle.favoriteId` 若仍残留旧的自动收藏 ID，`_autoApplyBest()` 使用 `items.find(i => i.id === bundle.favoriteId)` 会优先选中自动字幕而忽略手动收藏；
  3. 用户已手动选择或导入正在播放的字幕时，后台触发自动选优若无条件调用 `_applyItem()` 会抢占当前画面字幕；
  4. 跨端 WebDAV 合并（`SubtitleRepository._merge()`）按 `localBundle.favoriteId || remoteIndex.favoriteId` 或单靠 `addedAt` 覆盖，会导致「设备 A 的高时间戳自动收藏」压过「设备 B 的手动收藏」。
- **测试虚拟番号误撞黑名单**：在单元测试中使用占位符 `TEST-001` 验证 `_isRelevant()` 时，被 `videoCode.js` 全局黑名单拦截，导致候选被全部过滤、无触发下载。

## 2. ROOT CAUSE ANALYSIS (根本原因剖析)
- **L1 · 布尔态 `favorite` 信息熵不足**：单一 `favorite: boolean` 无法表达「用户主动意图（Manual）」与「系统代理决策（Auto）」之间的权威等级差，导致所有排序与同步合并只能退化为 ID 命中或时间戳比较。
- **L2 · 多处各自手写“选最优”比较器**：`_autoApplyBest()`、`_visibleRows()` 与 `SubtitleRepository._merge()` 各自读取 `favoriteId` 与 `rating`，缺乏统一的权重 Tier 定义。

## 3. PROVEN SOLUTION (验证有效的解决方案)
- 显式区分子来源字段 `autoSaved` / `favoriteSource`（`'manual' | 'auto'`），兼容无标记的存量收藏一律视为 `'manual'`，防止老用户数据降级。
- 建立统一三级权重函数 `getSubtitleFavoriteTier(item)`（手动收藏 `2` > 自动收藏 `1` > 未收藏 `0`）与 `selectBestBundleItem(bundle)`，统一驱动 `_autoApplyBest()` 与 `_visibleRows()`。
- 在 `SubtitleRepository._merge()` 中强制实施 **Manual Wins Over Auto**：即使自动收藏 `addedAt` 更新，同一 ID 与手动项合并后保持 `manual`，且 `favoriteId` 仲裁中远端手动收藏可覆盖本地自动收藏。
- 单元测试涉及番号比对管线时使用合法格式番号（如 `IPX-343`）验证真实过滤路径。

## 4. PITFALLS & ANTI-PATTERNS (避坑指南与反模式禁令)
- FORBIDDEN (禁止做法)：将系统自动收藏与用户手动收藏混用同一布尔值 `favorite`，在默认挑选或跨端合并时仅凭 `favoriteId` 先到先得或 `addedAt` 新者胜裁决。
- USE (正规做法)：显式标注来源等级（`manual > auto`），并让本地激活、列表排序与远端三路/双向合并共享同一优先权不变量（用户手动意图永远高于系统自动化决策）。
