# Handoff — 评论多站点跨站串源根治 (v5.7.118-beta.055)

- **时间戳**：2026-11-17-180006
- **版本**：`v5.7.118-beta.055`
- **分支**：`dev`
- **触发问题**：用户反馈「评论采集站点串了，不同站点采集的评论 section 内评论是相同的」

## 一、根因（实证结论）

真实数据审计：`video_comments_bundle` 共 1,464 个 bundle / 31,685 条评论。

| 指标 | 数值 | 含义 |
| :--- | :--- | :--- |
| `site_comment_id` 纯数字 (Jable) | 18,344 | 正常 |
| `javdb-api-*` 且 `source_site='javdb'` | 8,053 | 正常 |
| `javdb-api-*` 但 `source_site='jable'` | **5,288** | **错标双写（65.7%）** |
| 多站点 bundle 中 jable/javdb 集合完全一致 | **22 / 153** | 用户看到的「内容相同」 |
| Jaccard ≥ 0.8 的多站点 bundle | 23 | 高度重合 |

**污染链（5 步）**

1. `src/player/comments/providers/*` 在评论对象上写的是 `site: 'javdb'`（Javlib 为 `site='javlib-review'`），**从不写 `source`**。
2. `src/player/comments/CommentDebugCollector.js` `collectComments()` 只读 `c.source`（undefined）→ 兜底 `'jable'`，把所有 JavDB 评论以 `source: 'jable'` 写入 WebDAV `/MissPlayer/comments/[AVCODE].json`。
3. `CommentPanel._mergeWebdavComments()` 按 `item.source` 分桶 → 全部落入 jable 桶。
4. `CommentPanel.reprocessComments()`（`loadedmetadata` 触发）把 jable 桶整桶回写 Supabase（`uploadComments(code, 'jable', ...)`）。
5. `upsert_comment_bundle` 的 `hash_fingerprint = md5(source + '_' + id + '_' + content)` 因 source 不同 → 同一条评论两个指纹并存，此后所有客户端读到的 jable 段都含 JavDB 评论。

> 反证：Playwright 干净环境（mock 三站 HTML）三站完全隔离，证明串源来自**持久化污染**而非渲染层。

## 二、修复（4 文件 + 1 迁移 + 1 测试）

### 1. `src/player/controls/CommentPanel.js`
- 新增 `static inferSiteKey(rawSource, commentId)` —— 三级优先级：
  1. 带命名空间的评论 ID 前缀（`javdb*`→javdb、`javlib*`→javlib）为**唯一不可伪造硬证据**；
  2. 显式来源字段（`javlibrary`/`javlib*`→javlib、`javdb*`→javdb、`jable*`→jable）；
  3. 纯数字 ID → jable；兜底 jable。
- 新增 `_inferCommentSite(comment)`（读 `source_site || source || site` + `site_comment_id || id`）。
- `_resolveMergeSiteKey(rawSource, commentId)` 改为调用 `inferSiteKey`。
- 新增 `_normalizeSiteBuckets()`：把错桶评论搬回真实站点（按 id / text 去重），回填 `status='loaded'`、`totalCount`。
- `_restoreSitesFromCache()` 末尾自愈旧 IndexedDB 脏缓存。
- `reprocessComments()` 先归一化，且只上传 `_inferCommentSite(c) === sKey` 的评论。
- `_mergeRemoteComments` / `_mergeWebdavComments` 传「来源字段 + 评论 ID」双通道；补齐 `processed.text`（`processComment` 不回填 `text`，缺失会导致后续 `reprocess` 抛 `Cannot read properties of undefined (reading 'includes')`）。
- 源站采集 `processed` map 显式标注 `source_site: siteKey`。

### 2. `src/player/comments/CommentDebugCollector.js`
- `rawSite = c.source_site || c.site || c.source` 归一为 `siteKey`；去重键 `${siteKey}_${id}`；item 同时写 `source_site` 与 `source`。

### 3. `src/services/SupabaseService.js` `uploadComments()`
- `normalizedSite` 归一；逐评论按 `siteId` 前缀推断归属，跨站点直接 `continue` 丢弃；
- `hash_fingerprint = md5(normalizedSite + '_' + siteId + '_' + content)`；
- `rows[].source_site`、RPC `p_source`、降级直写 `last_source` 全部用 `normalizedSite`。

### 4. `supabase/migrations/20261117000000_normalize_comment_source_site.sql`（新）
- 函数 `normalize_bundle_comment_sources()`：按 `site_comment_id` 前缀 `jsonb_set(value,'{source_site}',...)` 重标 → `distinct on (site_comment_id|hash_fingerprint|content_raw)` 去重 → 回写 `comments/total_count/has_timestamps_count/updated_at`；幂等，可重复执行；仅 `service_role` 可执行。
- 上线后需手动执行一次：`select public.normalize_bundle_comment_sources();`

### 5. `tests/comment-site-isolation.test.mjs`（新，CI 步骤 4.26）
7 项断言：`inferSiteKey` 规则回归、分桶自愈、双通道分桶、采集标注、Service 串源守卫、DebugCollector 归一、迁移存在性与去重逻辑。
