# Miss Player Settings v2 并存重构经验教训

- **日期时间**: 2026-11-14 18:16:45
- **关联版本**: `v5.7.118-beta.044`

---

## 核心反模式与避坑指南

1. **互斥浮层同源触发器互切时的 380ms 冷却陷阱**
   - `FORBIDDEN`: 在新旧双设置按钮并存场景下，capture 阶段 `overlayClickHandler` 仅豁免自身触发按钮，导致点击另一套设置按钮时先触发 `close()` -> `UISurfaceMachine.deactivate()` 激活 380ms 全局冷却（`.is-overlay-cooldown`），直接吞噬用户点击另一按钮的意图，无法 1 次点击切换。
   - `USE`: 互斥同级入口的 `overlayClickHandler` 必须同时豁免互补入口按钮（`SettingsV2Manager` 豁免 `.tm-settings-button`，`SettingsManager` 豁免 `.tm-settings-v2-button`），把切换权直接交给 `EventManager` + `UISurfaceMachine.activate()`。

2. **CSS 文件 `!important` 静态门禁上限（50/50）与注释误判**
   - `FORBIDDEN`: 在新增样式模块中引入哪怕 1 处 `!important`，或在测试正则检查 `!important` 时未剥离 `/* ... */` 注释。
   - `USE`: 新模块 `_settings_v2.css` 严格采用扁平化层级（选择器深度 `<= 3`）和 `.is-hidden` 状态类做到 **0 `!important`**；静态校验正则先 `.replace(/\/\*[\s\S]*?\*\//g, '')` 再检测，避免误伤注释说明。

3. **避免 `window.prompt()` / `window.confirm()` 阻塞 iOS 全屏与测试自动化**
   - `FORBIDDEN`: 在自定义跳转步长或清缓存/覆盖备份等高频交互中调用原生 `window.prompt()` 或 `window.confirm()`。
   - `USE`: 使用内联输入芯片组（点击 `+ 自定义` 原地展开输入与 `✓` 按钮，支持 IME `isImeConfirmEnter`）和 3 秒自复位二次确认按钮（`bindTwoStepConfirm`）。

4. **双语言混用与多余二级副标题视觉噪音**
   - `FORBIDDEN`: 新建模块混用硬编码中文与旧词典中英混合 Key（如 `Quick Seek` / `Button Sounds` 夹杂中文），或在每个自解释开关下重复堆砌冗余副标题。
   - `USE`: 在 `src/constants/i18n.js` 补全一致的 `s2*` 多语言词条，严控二级文案仅保留在真正需要范围/风险提示的行内，保持界面留白克制。
