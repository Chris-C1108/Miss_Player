## 1. 调用外部 Service 前必须核验真实导出方法签名，严禁凭记忆猜名
* **现象**：在精简重构 `SettingsManager.js` 时写成了 `SleazyForkService.checkForUpdates(...)` 并判断 `!res.error`，但 `SleazyForkService.js` 实际暴露的是静态方法 `SleazyForkService.checkUpdate(forceRefresh, channel)` 且成功字段为 `res.success`；导致“检查更新”与静默查更在运行时静默抛错，触发 `S2AdvancedSection` 中捕获失败。
* **准则**：
  * **FORBIDDEN**: 在重构或精简已有管理器时凭印象手写跨模块静态方法名（如 `checkForUpdates`）或返回字段名（`!res.error`） -> **USE**: 修改任何跨模块调用前，先用 `read` 或 `ffgrep` 核对目标 Service 的真实导出签名与返回结构体，并用真实浏览器自动化（Playwright）点击触发对应操作验证状态变化。

## 2. 注意力友好 UI 原则：有更新时，让主动作按钮成为唯一强光焦点
* **现象**：最初让 `检查更新` 常驻 `--primary` 蓝底、并在 `hasUpdate === true` 时给 `更新/安装` 再加上 `.is-update-available` 蓝底发光，导致两个蓝色按钮并排竞争视线，削弱了“发现新版本只需点击更新”的直觉性。
* **准则**：
  * **FORBIDDEN**: 在同一操作组内同时使用多个 `--primary` 强色按钮，或叠加文字版本横幅 + 顶栏红点 + 按钮高亮等多重提示 -> **USE**: 版本号在入口处只出现一次；当存在新版本时，仅让「更新/安装」激活 `.is-update-available` 主色呼吸发光，将「检查更新」自动退让为中性按钮，实现零文字干扰的单点动作聚焦。

## 3. 删除旧面板与重构状态管理后，同步审查辅助配置与隐藏依赖
* **现象**：删除旧版 `SettingsManager` DOM 面板时，一并误删了构造函数向 `this.playerCore` / `this.controlManager` 的绑定、以及 `init()` 中的 `DebugLogPanel.updateDebugState`、`CrazyScraper.isEnabled()` 自动采集启动与 `updateChannel` 在 `loadSettings`/`saveSettings` 中的双端存取，触发 Test 26 与运行时通道同步缺陷。
* **准则**：
  * **FORBIDDEN**: 将旧版设置类直接“一把删空”只留空壳 -> **USE**: 将 UI 与业务逻辑拆离后，逐项核对 `constructor`、`init()`、`loadSettings()`、`saveSettings()`、`cleanup()` 与 `tests/player-fixes-verification.test.mjs` 契约，保留全部非 UI 生命周期职责并保持方法签名向后兼容。

## 4. Playwright 选择器必须与 DOM 组件原语源码一一对照
* **现象**：验证脚本最初使用 `.mp-s2-acc` 查找手风琴元素导致空指针，实际 `S2Primitives.js` 输出类名为 `.mp-s2-accordion` / `.mp-s2-accordion-trigger`。
* **准则**：
  * **FORBIDDEN**: 在验证脚本中猜测自定义组件类名 -> **USE**: 先查阅组件原语（如 `S2Primitives.js`）确认真实 DOM 结构与 `aria-expanded` / 类名，再编写交互验证脚本并结合截图人工复核。
