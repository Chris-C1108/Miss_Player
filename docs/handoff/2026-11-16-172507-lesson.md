# 经验教训与避坑记录 (2026-11-16 17:25:07)

## 1. 移除设置项开关时必须同步清理模板默认 class 与内部死代码
- **反模式**：`FORBIDDEN: 仅从 UI 渲染中删除设置行，却在子容器 className 中保留旧配置读取（如 S2PlaybackSection.js 中残留 showSeekControlRow !== false ? '' : 'is-hidden'）或残留死 getter（SingleHandManager.isBetaEnabled）。`
- **正确做法**：`USE: 删除设置开关时，必须同时检查所有子容器初始显隐 class、初始化门控（如 autoCheckUpdate）、以及状态管理器残留读取，并用自动化测试断言源代码中不再存在已剔除的配置键。`

## 2. DOM 动态更新选择器必须与基元组件的真实类名完全一致
- **反模式**：`FORBIDDEN: 在 Section 回调中凭印象查询 .mp-s2-row-subtext 等非基元真实类名（S2Primitives 实际使用 .mp-s2-row-sub），导致切换分段器后辅助说明文本静默不更新。`
- **正确做法**：`USE: 基元组件暴露状态更新句柄或统一使用 .mp-s2-row-sub 等真实类名，并在 Playwright 真机探测中同时校验文本变化与视觉截图。`

## 3. 多选一分段器 + 较长说明文案的防挤压排版法则
- **反模式**：`FORBIDDEN: 对带有 20 字以上双状态说明的 SegmentedRow 使用水平并排（stacked: false），导致右侧控件将左侧说明挤成 4 行窄栏。`
- **正确做法**：`USE: 带有动态长说明的 SegmentedRow 统一设置 stacked: true，让说明文字独占全宽 1–2 行，下方平铺等宽分段胶囊。`

## 4. 条件依赖开关的跨模块实时联动与无死角状态机
- **反模式**：`FORBIDDEN: 将“疯狂采集”等需要云端/WebDAV 依赖的功能与调试日志开关（debugMode）强行绑定，或仅在页面打开时判定一次可用性，导致用户在配置好 WebDAV 或切换社区共享后仍需刷新才能启用。`
- **正确做法**：`USE: 将准入条件收口为静态纯函数（CrazyScraper.canEnable()），并在 WebDAV 保存、Beta 总开关及数据模式变更时统一触发 refreshCrazyAvailability() 实时解锁/置灰并附带清晰前置提示。`
