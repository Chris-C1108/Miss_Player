# Lesson — 字幕子系统五条硬教训 + 跳转反馈三次返工的完整反模式清单 (v5.7.119-beta.017)

- **时间戳**：2026-11-19-151051
- **版本**：`v5.7.119-beta.017`
- **适用范围**：全局（任何 Shadow DOM 内运行的用户脚本）

---

## L1 · Shadow DOM 内的媒体事件永远到不了 document

**现象**：`SeekFeedbackManager` 改用 `document.addEventListener('seeking'/'seeked', fn, true)` 后，所有跳转 Toast 完全静默，且无任何报错。

**根因**：`play` / `pause` / `seeking` / `seeked` / `timeupdate` / `waiting` 等原生媒体事件的 `composed` 为 `false`，**不会跨越 Shadow 边界**。捕获阶段也只在同一棵树内传播，`document` 永远收不到。

- `FORBIDDEN`: 在 `document` / `window` 上监听媒体事件来观察 Shadow DOM 内的 `<video>`（包括"捕获阶段兜底"这种想法）
- `USE`: 直接把监听器绑在 `playerCore.targetVideo` 上；元素可能晚到，用重试 `_attach()`（本项目 800ms）等待接管，接管后自动解绑重绑
- `USE`: 若确需同时覆盖宿主浅层视频，才额外保留 document 捕获监听，且明确它只是补充通道

**判据**：任何"监听不到但也不报错"的媒体事件问题，先怀疑 Shadow DOM 隔离，而不是先怀疑时机或选择器。

## L2 · 用外部可变状态做门控 = 埋一个永久静默开关

**现象**：所有跳转 Toast 集体消失。

**根因**：`_announce()` 里写了 `if (progressManager.isDraggingProgress) return;`。`ProgressManager` 在拖动开始置 `true`（第 270 行）、拖动结束置 `false`（第 421 行）；松手落在进度条外、手势被系统取消时 `false` 永不执行 → 标志永久卡 `true` → 此后每一次播报都被吞掉。

- `FORBIDDEN`: 读取其它模块的瞬时布尔状态来决定"这次要不要反馈"，尤其是由成对 `true/false` 赋值维护的 UI 标志
- `USE`: 由本模块自己可自愈的信号推导，例如**事件密度**——1.2s 窗口内第 2 次 `seeking` 即视为连续位移，窗口滑出自动清零，无泄漏可能

**推广**：任何 `isXxx = true ... isXxx = false` 的成对标志，只要 `false` 分支依赖用户手势终点（`pointerup` / `touchend` / `blur`），就必须假设它会泄漏。

## L3 · 凭记忆引用不存在的属性 = 永远为假的无用判断

**现象**：`if (this.controlManager?.loopManager?._isSeekingCapsule) return;` 看起来合理，实则 `LoopManager` 里根本没有 `_isSeekingCapsule` 这个属性（`grep` 零匹配），判断永远为 `undefined` → 静默失效；更糟的是它给了"已处理该场景"的错觉。

- `FORBIDDEN`: 不 `grep` 就写 `obj.xxxProperty`（可选链 `?.` 会让拼写错误完全不报错）
- `USE`: 引用跨模块状态前先 `grep -rn "属性名" src/` 确认存在；确需可选依赖时，至少在一处断言其类型

## L4 · 视频之上的浮层在 iOS 需要显式合成层与 z-index

**现象**：字幕层 DOM 正确、时间轴正确，真机上却看不见。

**根因**：视频元素自身形成合成层，普通绝对定位浮层可能被压在下面。

- `USE`: 覆盖层同时给 `z-index`（引用 `--z-*` 标尺）与 `transform: translateZ(0)`；Toast 的位移 `transform` 必须把 `translateZ(0)` 拼进每一条规则（含 `.visible` 态），否则 transition 会把它覆盖掉
- `FORBIDDEN`: 只改 `z-index` 就宣称"层级已修复"

## L5 · 字幕文本清洗必须收敛到唯一入口

**需求**：删除每条字幕末尾的标点。

**做法**：在 `sanitizeCueText()` 的逐行 `map` 内执行一次 `TRAILING_PUNCTUATION` 替换，SRT / ASS / VTT 三条解析路径与歌词列表全部继承，无需在多处重复。

```js
const TRAILING_PUNCTUATION = /[。．.，,、；;：:！!？?…⋯~～·\-—"'“”‘’）)】」』》〉\]]+$/;
```

- `FORBIDDEN`: 在渲染层（`SubtitleManager._setOverlayText`）或歌词行构造函数里各自 `replace`
- `USE`: 清洗放在 `SubtitleFormat.sanitizeCueText()` 单点，解析即洁净
- 边界：仅剔**行尾**，句中逗号与小数点（`12.5`）必须保留；多行逐行处理，空行过滤

## L6 · i18n 批量插入脚本必须幂等

**历史复发**：同一批 key 被插入两次（每语言 2 份），因脚本无存在性判断。

- `FORBIDDEN`: 直接 `str.replace(anchor, block + anchor)` 批量插 key
- `USE`: 插入前 `if 'keyName' in section` 判定；完成后 `grep -c "keyName:"` 必须等于语言数（5）
- 语言块锚点行号会漂移，一律用锚点文本而非行号定位

---

## L7 · 长上下文压缩服务不可用时不要反复重试

**现象**：`compress` 连续 18 次返回 `all configured external summary candidates failed` / `timeout (target-timeout 25000ms)`，小范围同样失败。

- `FORBIDDEN`: 失败后缩小范围/拆分批次反复重试（每次白耗 25–50s）
- `USE`: 连续 2 次失败即判定当轮服务不可用，跳过继续业务；待后续轮次再试（本轮后续确实恢复正常）

---

## L8 · 交付说明必须区分「已验证」与「假设」

本次字幕功能的真机渲染问题连续三轮才收敛（合成层 → 番号源 → 事件通道）。教训：**CI 全绿 + 单测通过 ≠ 真机可用**，尤其在 Shadow DOM + 视频合成层 + 移动端 Safari 三者叠加时。

- `FORBIDDEN`: 以"构建通过 / 单测通过"作为"用户可见问题已解决"的结论
- `USE`: 交付时明确列出「已通过自动化验证」与「未在真机验证」两类，并给出下一步二分定位方法
