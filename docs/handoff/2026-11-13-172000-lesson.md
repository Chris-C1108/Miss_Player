# Lessons Learned: 移动端时间戳收藏免长按、几何判重与正式落盘反模式避坑总账

- **日期时间**: 2026-11-13 17:20:00
- **关联版本**: `v5.7.118-beta.022`
- **主题**: 移动端时间戳收藏交互设计、Hit-Testing 几何碰撞防御、草稿态与落盘态生命周期

---

## 🚫 反模式与避坑总账

### 1. 行内富文本使用负 Inset 伪元素导致触控热区碰撞 (WebKit Hit-Testing Collision)
- **错误做法 (FORBIDDEN)**:
  为了让行内小按钮容易点击，在 `span.jc-time-star-btn::after` 使用 `position: absolute; inset: -10px -12px;` 强行外扩触控热区。
- **踩坑后果**:
  评论区中经常出现连续排布的时间戳（如 `01:20 01:45 02:10`）。外扩的透明伪元素在 WebKit Hit-Testing 层树上会发生大面积不可见重叠，导致用户点击第二个时间戳的文字时，实际上命中了前一个时间戳外溢的伪元素，引发严重误触。
- **正确做法 (USE)**:
  采用**绝对盒模型约束的内联微裂变胶囊**：外层容器统一开启 `box-sizing: border-box; overflow: hidden;`，胶囊内部左侧承载文字跳转，右侧留出紧凑的微型按钮空间，触控点完全在自身几何尺寸内部，杜绝任何外部碰撞。

---

### 2. 未收藏态常驻高对比度空心星引发视觉杂讯撕裂 (Visual Noise & Punctuation Break)
- **错误做法 (FORBIDDEN)**:
  在移动端对所有未收藏时间戳常驻展示高透明度或亮色的空心星，或者在外部展示多余文本。
- **踩坑后果**:
  严重破坏评论阅读心智，在连续排布的时间戳中产生强烈的视觉杂音与折行撕裂，违背 `AGENTS.md`“涉及UI，避免不必要的次要标签和说明，让布局本身来解释”的铁律。
- **正确做法 (USE)**:
  移动端未收藏态采用低透明度（`opacity: 0.45`）与轻量尺寸内嵌，融于时间胶囊内部；已收藏态（`.is-favorited`）才采用高对比度琥珀金和实心星 (★) 点亮；桌面端保持悬停展现。

---

### 3. 时间戳收藏误调用草稿态接口导致“假收藏、刷新即失” (Draft State vs Persisted Tabs)
- **错误做法 (FORBIDDEN)**:
  点击收藏按钮直接调用 `LoopManager.setDraftTabFromTime(secs)`。
- **踩坑后果**:
  `setDraftTabFromTime` 仅仅是设置控制栏底部的临时草稿胶囊（未按保存键前不会存入 `this.tabs`，也不会写入 IndexedDB/WebDAV）。导致用户在评论区点击了收藏，下次刷新页面或换个标签页时该收藏完全丢失，且根本无法进行后续的“已收藏”比对。
- **正确做法 (USE)**:
  评论区收藏属于明确的用户持久化意图，必须调用正式入库方法 `LoopManager.addTabFromTime(secs, commentExcerpt)`，自动分配莫兰迪色彩并执行 `saveTabs()` 落盘，同时直接进行乐观 UI 变色。

---

### 4. 几何判重遗漏“区间与点”交叉场景 (Geometric Intersection Completeness)
- **错误做法 (FORBIDDEN)**:
  仅对 `|startTime - sec| <= 5` 进行点与点比对，或者直接使用粗暴的全等判断。
- **踩坑后果**:
  用户在播放器中保存了一个 2 分钟的高光片段（如 `[01:00, 03:00]`），评论中有人提到了 `02:00 精彩`。若仅做点比对，`02:00` 无法被识别为已收藏；反之，若评论给出了 `00:50 ~ 01:20` 区间，也无法与已有的 `01:00` 高光点形成匹配。
- **正确做法 (USE)**:
  实现包含 `[点 vs 点]`、`[点 vs 区间]`、`[区间 vs 单点]`、`[区间 vs 区间]` 的全几何相交与边界判定引擎 `checkIsTimestampFavorited`，在两端均赋予 `±5s` 宽容度。

---

### 5. 遍历时间戳更新徽标使用非通用选择器导致静默失败 (Zombie QuerySelector Guard)
- **错误做法 (FORBIDDEN)**:
  `timeLinks.forEach(link => { const badge = link.querySelector('.jc-time-add-badge'); if (!badge) return; ... })`。
- **踩坑后果**:
  历史版本曾使用 `.jc-time-add-badge`，重构为微裂变胶囊后内部元素类名为 `.jc-time-star-btn`。若保留历史属性检查，整个函数在第一行就 `return`，导致无论怎么刷新都无法点亮已收藏时间戳。
- **正确做法 (USE)**:
  直接遍历所有的 `.jc-time-link` 并直接操作其自身的 class（`classList.add('is-favorited')`），内部星星通过 `.jc-time-star-btn` 更新 `title`。
