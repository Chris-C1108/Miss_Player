## 1. 深度排查定位到的四大架构级病灶 (Root Causes)

1. **假阴性异常吞噬反模式 (`checkDirectoryExists`)**：
   - **病灶**：原 `checkDirectoryExists()` 在 `try/catch` 中遇到网络超时、连接拒绝、甚至 `401/403` 认证错误时，竟然全部吞噬并 `return false`。
   - **后果**：上层 `_ensureDirectoryInternal` 误以为目录不存在，继续调用 `MKCOL`，最后以业务错误 `目录无法自动创建` 抛出。由于该错误文案未匹配 `_isNetworkError()`，故障转移引擎判定为非网络错误并直接终止，**第二候选地址 (`lanUrl`) 从始至终一次都没有尝试过**！
2. **iOS / macOS Stay `GM_xmlhttpRequest` 超时悬空挂死**：
   - **病灶**：移动端 Stay / Safari 沙箱下，连接受阻（如无 NAT 回流时的内网请求公网域名）时 `GM_xmlhttpRequest` 的原生 `ontimeout` 回调存在概率性不触发问题，且部分异常返回 `status: 0`。
   - **后果**：测试连接转圈假死，Promise 永远处于 pending 状态。
3. **私网 IP 协议智能推导缺失**：
   - **病灶**：原规则简单粗暴对所有未带协议的地址默认拼接 `https://`。当用户输入局域网纯 IP `192.168.2.250:5005` 时被误拼为 `https://192.168.2.250:5005`，导致 SSL 握手直接失败。
4. **全项目 15 处孤岛判定与功能遗漏**：
   - 全代码库共 15 处散落的 `if (!config.url)` 校验逻辑，导致仅配置备用地址时各业务模块（热度图、评论、STRM、疯狂采集、调试日志等）全部跳过。
   - Peach 模式 C（独立 WebDAV 配置）也缺失对应的 `webdavStandaloneLanUrl` 字段与 UI。

## 2. 本阶段全局性架构重构与核心变更

### 2.1 `src/sync/WebDavClient.js` (唯一权威网路中枢)
* **真异常透明上抛**：重构 `checkDirectoryExists()`，仅将明确响应的 `404/409/410` 视为不存在，所有超时、网络断开、CORS 及 `401/403` 一律透明抛出，由外层 `executeWithFailover` 精准接管与调度切换。
* **全局唯一有效端点判定**：新增 `WebDavClient.hasValidEndpoint(config)`，彻底替换全库分散的 `config.url` 判空。
* **JS 硬熔断防卡死与 `status === 0` 捕获**：为 `GM_xmlhttpRequest` 增加 `timeout + 400ms` 强制熔断定时器；`status === 0` 且无成功头时明确抛 `网络连接被拒绝或无响应 (status: 0)` 纳入故障转移白名单。
* **私网协议智能补全**：新增 `isPrivateNetworkHost` 与 `sanitizeEndpointUrl`，自动为 `192.168.*` / `10.*` / `172.16-31.*` / `localhost` / `.local` 补全 `http://`，为公网域名补全 `https://`。
* **跨刷新 2 小时持久化租约**：新增 `mp_active_webdav_lease` 双写持久化租约（TTL 2 小时），切换至内网后刷新页面、新建标签页均 0ms 直连已验证断点。
* **端到端生效端点透明提示**：`testConnection` 返回生效实际访问的端点地址，方便真机确认当前处于内网还是公网通道。

### 2.2 全项目 15 处 WebDAV 校验全局收口
将以下模块中所有的 `config.url` 检查统一替换为 `WebDavClient.hasValidEndpoint(...)`：

* `src/player/ui/UIManager.js` (1 处)

* `src/player/comments/CommentDebugCollector.js` (1 处)
* `src/player/managers/settings/sections/CloudSyncSection.js` (1 处)

### 2.3 Peach 模式 C (独立 WebDAV) 对齐支持
* `src/services/PeachService.js`：新增 `PEACH_KEY_WEBDAV_STANDALONE_LAN_URL` 存储与读取，`getEffectiveWebDavConfig()` 输出带 `lanUrl` 的标准配置对象，且 `hasSync` 同步使用 `WebDavClient.hasValidEndpoint`。
* `src/player/managers/settings/sections/PeachSection.js`：独立模式卡片同步渲染「局域网备用地址」输入框与保存绑定。
