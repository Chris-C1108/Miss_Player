# Session Lessons & Anti-Patterns: 番号解析裂变、Shadow DOM 视频脱靶与双写删除复活陷阱 (v5.7.120-beta.004)

- Date & Time: 2026-11-24 17:17:00
- Focus Module: `src/utils/videoCode.js`, `src/player/core/PlayerCore.js`, `src/utils/storage.js`, `src/sync/WebDavClient.js`, `src/services/AvCodeMigrationService.js`

## 1. PROBLEMS ENCOUNTERED (遇到的核心问题与故障)
- **现象表现**：
  1. `https://missav.ai/dm84/cn/miaa-490` 页面中，字幕编号被识别为 `DM-84`，而评论解析为 `MIAA-490`。
  2. `https://missav.ai/dm84/cn/miaa-490` 与 `https://missav.ai/dm84/cn/miaa-490-uncensored-leak` 同一部影片的时间胶囊（`tabs_*`）没有同步。
- **触发条件**：MissAV 路由包含 `/dm84/` 路由分片与 `/cn/` 语言前缀，且播放器创建 UI 时会将 `<video>` 迁移至 `<miss-player-root>` 的 Shadow DOM 内部。

## 2. ROOT CAUSE ANALYSIS (根本原因剖析)
- **L1 · 语言前缀混入非视频黑名单 + 路由分片抢占**：`NON_AV_SLUGS` 混入了 `cn`/`en`/`ja` 等语言路径段，导致所有本地化 URL（`/dm84/cn/miaa-490`）跳过末尾分段提取并退化为整条 `pathname` 扫描；同时 `PARSER_RULES` 将紧凑 `DM` 规则排在 `STANDARD_HYPHEN` 之前，整条路径优先匹配到 `/dm84/` 产出 `DM-84`。
- **L2 · 多子系统在 Shadow DOM 迁移前后各自解析番号，导致单页内分裂**：`UIManager.createVideoWrapper()` 将 `<video>` 移入 Shadow DOM 后，`document.querySelector('.tm-video-wrapper video')` 失效。各模块（`CommentPanel`、`LoopManager`、`SubtitleManager`、`HeatmapManager`、`UIManager`）各自调用 `getVideoCodeFromUrl()` 或 `getVideoCodeFromUrl(this.targetVideo)` 且回退顺序不一致，传入与不传 `<video>` 的两条调用链给出了不同番号，破坏“单一权威来源”。
- **L3 · 双写存储的 `deleteValue` 漏删镜像导致删除复活**：`setValue()` 双写 `GM_setValue` 与 `localStorage`（`mp_` 前缀），但 `deleteValue()` 在 `GM_deleteValue` 后直接 `return`，未清除 `localStorage` 镜像；下一次 `getValue()` 命中兜底并自动回写 `GM_setValue`，导致已迁移或已清空的 `tabs_*` 键重新复活。
- **L4 · `WebDavClient` 读写删接口路径基准不一致**：`downloadFile` / `uploadFile` 会自动拼接 `config.path`（如 `/MissPlayer/`），而 `deleteFile` 直接将入参拼在 host 根路径下。传入相对路径 `heatmaps/DM-84.json` 或 `media/MIAA-490/xxx.srt` 会请求到根路径而无法真正删除远端文件。

## 3. PROVEN SOLUTION (验证有效的解决方案)
- 拆分 `LANGUAGE_SLUGS` 与 `NON_AV_ROUTE_SLUGS`，在路径分段与 `sanitizeInput` 中剥离前置 `/dm\d+/` 分片，并将 `STANDARD_HYPHEN` 置于紧凑 `DM` 规则之前；`getVideoCodeFromUrl()` 穿透 `<miss-player-root>.shadowRoot` 定位视频。
- 在 `PlayerCore` 建立全播放器唯一权威入口 `resolveVideoCode()` / `getVideoCode()`，于 `PlayerCore.init()` 移入 Shadow DOM 前即锁定番号，全部子系统统一读取该入口。
- 修复 `storage.js:deleteValue` 双端清理与 `WebDavClient.deleteFile` 相对路径拼接 `config.path`，并构建 `AvCodeMigrationService` + `SyncManager` 别名归并 + Supabase SQL 迁移，完成本地、WebDAV、STRM 与云端全链路数据自愈。

## 4. PITFALLS & ANTI-PATTERNS (避坑指南与反模式禁令)
- FORBIDDEN (禁止做法)：将语言代码（`cn`/`en`/`ja`）混入非视频路由黑名单，或让子模块在 `<video>` 移入 Shadow DOM 后各自零散调用 `getVideoCodeFromUrl()` 拼凑优先级。
- USE (正规做法)：语言前缀与列表/分类黑名单严格分离，全播放器由 `PlayerCore.getVideoCode()` 在初始化期统一裁决并分发。
- FORBIDDEN (禁止做法)：双写存储（GM + localStorage）的删除函数在主存储删除后提前 `return`，或在 WebDAV 客户端中让 `uploadFile` 与 `deleteFile` 使用不同的路径基准语义。
- USE (正规做法)：双写存储必须对称双删；同一服务客户端的读/写/删对相对路径与绝对路径保持完全一致的解析约定。

## 5. SCALING TO AGENTS.MD (全局规则提炼)
- 提炼原子规则：`RULE: All subsystems must resolve videoCode exclusively via PlayerCore.getVideoCode(), and dual-write storage / WebDAV delete APIs must maintain symmetric path & cleanup semantics (FORBIDDEN: ad-hoc getVideoCodeFromUrl() per manager or early return in deleteValue -> USE: PlayerCore single-source resolver + symmetric dual-store delete & relative-path normalization).`
