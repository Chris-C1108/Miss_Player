## 🎯 需求出发点与设计初衷 (Origin & Motivation)

在上一阶段（Phase 17）完成 Peach 联动与前端 `GMHlsLoader` 切片加载管道后，真机实测暴露了 4 个深水区致命瓶颈：
1. **客户端直连遭遇 Cloudflare 403 盾牌**：
   - 手机或局域网浏览器访问外部源站（如 JAVVerse）的 HTML 搜索页时，频繁触发 Cloudflare Managed Challenge（403 挑战页），导致客户端无法获取作品数字 ID（`workId`）；
2. **切片加载 15 秒死等卡顿**：
   - 上游 BunnyCDN（Jable/mushroomtrack）由于油猴扩展跨域沙箱挂起，每个切片均死等 15 秒超时才触发原生 fetch 逃逸，导致播放 3 秒停顿 15 秒，缓冲区持续饿死；
3. **Hls.js 内部测速与状态机崩溃**：
   - 切片虽然通过原生 fetch 下载成功，但由于自定义 Loader 实例未在构造函数初始化 `this.stats`，Hls.js 触发 `FRAG_LOADED` 测速时访问 `undefined.first` 崩溃，抛出 `internalException`；
4. **源站生态迷信（Jable 并非最佳源）**：
   - 过于依赖 Jable 这一单一源，而 Jable 不仅需要 AES-128 解密（消耗端侧 CPU），且封杀香港节点；而 123AV 与 JAVVerse 实际上拥有海量**纯明文（无加密）、直连免盾、且包含独家【无码流出/泄露】**的优质片源。

## 1. COMPLETED OBJECTIVES (已完成工作)

- [x] **Go 语言外部流解析服务研发 (`services/miss-resolver/main.go`)**：
  - 基于 Go 官方标准 `net/http` 研发，零第三方臃肿框架依赖，单一静态二进制仅 7.1MB，常驻内存仅 8~12MB；
  - 集成 123AV、Jable、JAVVerse 三大主流源站解析器，支持 `GET /api/resolve`、`/resolve` 与带 `?code=` 的泛根路径 `/`；
  - 修复 123AV 嵌入页多集与三层转义反斜杠（`\\\/`）漏匹配缺陷，增加 `/cn/search?keyword=...` 搜索兜底；
  - 服务端预嗅探 M3U8 `#EXT-X-KEY` 标签，直接将 16 字节 AES-128 密钥提取为 Hex（`keyHex`）与 IV（`keyIv`）直出。
- [x] **动态加权并发竞速模型 (Goroutine Priority-Weighted Arbitration)**：
  - 彻底颠覆单一串行轮询模式，采用基于优先权重的并发竞速调度：
    - **权重 100（T0 级首选）**：123AV（纯明文免解密、优先无码泄露版）；
    - **权重 90（T0 级同航道）**：JAVVerse（纯明文免解密、无码流出版）；
    - **权重 50（T1 级备选兜底）**：Jable（带 AES-128 加密，延后 400ms 错峰启动）；
  - 只要高权重纯明文源命中，立即通过 `context.CancelFunc` 熔断取消其余协程，实测 `STARS-256` 776ms、`SDMU-958` 1168ms 极速出货。
- [x] **NAS Docker 容器化实机部署与 Mihomo 代理分流 (`chen@192.168.2.250`)**：
  - 交叉编译 Linux AMD64 静态二进制 (`CGO_ENABLED=0 GOOS=linux GOARCH=amd64`)；
  - 解决内网 Alpine 构建断网问题，从宿主机复制 `/etc/ssl/certs/ca-certificates.crt` 打造自包含独立 Docker 镜像；
  - 启动 Docker 容器 `miss-resolver`，映射端口 `8765:8765`，配置 `PROXY_URL=http://192.168.2.250:7890`（Mihomo 主机端口）；
  - 实测验证健康接口 `GET /health` 与多番号解析接口 100% 成功。
- [x] **消灭 15 秒死等卡顿：GMHlsLoader 域名级记忆失效锁 (`PeachWebBridge.js`)**：
  - 在 `GMHlsLoader` 引入静态 `failedDomains` 缓存；
  - 针对 BunnyCDN（`mushroomtrack.com`）等在油猴沙箱中跨域受限的域名，首次 0B 逃逸后永久标记；
  - 后续所有切片（1~1762 个）**零等待（0ms）直接走原生 fetch**，超时上限由 15s 降至 3.5s；
  - 切片拉取耗时从 15,000ms 暴降至 **350ms ~ 500ms**，彻底消灭 `video: waiting` 缓冲停滞！
- [x] **根治 Hls.js 切片下载 `internalException` 崩溃 (`PeachWebBridge.js`)**：
  - 在 `GMHlsLoader` 的 `constructor` 中完整初始化 Hls.js 官方规范的 `LoaderStats` 实例（包含 `loading`, `parsing`, `buffering`）；
