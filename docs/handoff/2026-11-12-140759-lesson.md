# Miss Player 经验教训与陷阱总结 (Lesson Learned)

- **归档时间戳**：`2026-11-12-140759`
- **关联版本**：`v5.7.118-beta.014`
- **主题**：多设备新装默认值覆写显式偏好陷阱、分段器左右认知方向原则与同步事件响应式刷新

---

## 🚫 踩坑反模式与标准范式 (Anti-Patterns & Best Practices)

### 1. 冷启动默认设置时间戳覆写其他设备显式操作配置
* **反模式 (FORBIDDEN)**：
  - 在多设备配置合并（`SyncManager.mergeData`）中，当本地键在 `settingTimestamps[key]` 中缺失时，直接回退使用整个本地 JSON 的 `lastModified` 作为对比基准；
  - 若设备 B 刚安装脚本、初始化写过一次其他字段使 `lastModified` 较新，但从未触碰过 `dataMode`（保留默认值 `'local'` 且无独立时间戳），与设备 A 上早先显式开启的 `'shared'` 合并时，设备 B 的未操作默认值就会反杀覆盖掉设备 A 的真实意图。
* **标准范式 (USE)**：
  - **显式操作时间戳优先于全局默认值**：分别检测 `hasLocalTs` 与 `hasRemoteTs`；当一方拥有明确的用户交互时间戳 `settingTimestamps[key]` 而另一方缺失时，缺失方的该字段比较基准强制视为 `0`，确保“真实点击过的意图”永远胜过“冷启动默认值”。

### 2. 二元安全开关分段器顺序与日常直觉反向
* **反模式 (FORBIDDEN)**：
  - 将二元安全/共享模式分段选择器左置为激活/共享态（`社区共享`）、右置为保守/关闭态（`本地私有`）；
  - 违反人类从左到右“关 → 开”、“私有 → 共享”以及拨动开关（Toggle）从左往右激活的心智模型。
* **标准范式 (USE)**：
  - **左保守安全默认、右主动授权开启**：`[{ label: '本地私有', value: 'local' }, { label: '社区共享', value: 'shared' }]`，与开关从左往右点亮的肌肉记忆完全同向。

### 3. 设置面板打开期间执行云端同步导致状态视图陈旧
* **反模式 (FORBIDDEN)**：
  - 用户在已打开的设置面板点击「智能合并同步」或「恢复备份」后，仅更新底层 `PlayerState` 数据模型，未刷新当前展开的面板 DOM 与挂接管理器状态；
  - 用户眼前的开关依然停留在同步前的旧位置，播放器模块（如 `HeatmapManager`）也要等到下次刷新页面才生效。
* **标准范式 (USE)**：
  - **事件总线 + 局部视图热重绘**：`SyncManager.applyDataToLocal` 派发 `mp_sync_applied` 全局事件驱动 `HeatmapManager.onSyncApplied()` 实时切换波形；`SettingsManager` 在手动同步成功分支后立即调用 `createSettingsPanel()`（自动保留 `scrollTop`），确保眼见即所得。
