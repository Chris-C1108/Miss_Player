## 1. PROBLEMS ENCOUNTERED (遇到的核心故障与排错过程)

在本阶段推进 **外部流解析微服务研发、Go 语言架构选型与切片卡顿彻底根除** 的攻坚中，我们遭遇了 5 项极具破坏性、但极具深度的底层技术故障：

1. **切片加载时 Hls.js 抛出 `fatal error: internalException` 崩溃**：
   - *现象*：切片已成功由原生 fetch 下载完毕（`原生 fetch 成功接力 697680B`），但下一毫秒 Hls.js 立即报出致命错误 `internalException`，导致播放直接中断；
   - *根因*：在 Hls.js 的 `FragmentLoader` 机制中，当切片加载完毕触发 `FRAG_LOADED` 事件时，其内置的测速引擎（`bwEstimator`）会立即执行 `stats.loading.first - stats.loading.start` 来采样网络首包时间。由于自定义 Loader 类（`GMHlsLoader`）未在 `constructor` 中初始化 `this.stats`，Hls.js 将 `undefined` 赋给了 `frag.stats`，导致其在访问 `stats.loading` 时触发原生的 `TypeError: Cannot read properties of undefined (reading 'first')`，被 Hls 顶层事件循环捕获后包装为 `internalException` 抛出。
2. **切片下载 15 秒超时死等惩罚导致持续性卡顿 (`video: waiting`)**：
   - *现象*：视频起播后每放 3 秒就停滞卡顿，探针日志显示每个切片都要经历长达 `14679ms`、`12954ms`、`15830ms` 的 GM 请求，随后才触发原生 fetch 逃逸；
   - *根因*：上游 BunnyCDN 节点因油猴扩展内部跨域沙箱受限，`GM_xmlhttpRequest` 挂起直至 15 秒超时才返回 0B。虽然代码具备原生 fetch 逃逸能力，但**每一个新切片都在盲目重复“死等 15 秒 ➔ 超时 0B ➔ 逃逸 50ms”的愚蠢循环**。生产 4 秒切片需要等 15 秒，导致播放器缓冲区被持续饿死。
3. **HTML 内嵌 JSON 多重反斜杠转义阻断 123AV 正则匹配**：
   - *现象*：`STARS-256` 和 `SDMU-958` 在 123AV 上明确收录并可正常播放，但解析器一直报 404；
   - *根因*：123AV 页面上的播放器地址被编码在 HTML 属性的 JSON 字符串中，斜杠经过了多重转义，呈现为 `https:\\\/\\\/sadie-shop.site\\\/e\\\/ZKG10YMK`。简单的正向正则表达式（`https?://`）因反斜杠阻断无法匹配，导致 123AV 优质流全部被当作“未收录”跳过。
4. **外部解析服务 URL 路径未归一化导致 Go 路由秒报 404 (106ms / 526ms)**：
   - *现象*：命令行 curl 访问 `http://192.168.2.250:8765/api/resolve?code=...` 极速返回 200，但 Miss Player 探针中却显示 `外部解析服务 (NAS) 失败 (404 耗时 106ms)`；
   - *根因*：Go 标准库 `net/http` 仅注册了精确路径 `/api/resolve`。而用户在设置菜单习惯只粘贴根地址（`http://192.168.2.250:8765`），前端发出的请求命中了根路由 `/`，Go 的默认多路复用器在 9 毫秒内直接返回了 404 响应。
5. **片源站认知误区：迷信 Jable 为第一源**：
   - *现象*：Jable 检索较快，导致系统频繁命中 Jable；但 Jable 切片受 AES-128 加密，需要额外请求 Key、消耗客户端 CPU 进行实时软解，且严格封杀香港 IP；
   - *根因*：未从架构上对源站属性进行分级。**123AV 与 JAVVerse 是纯明文（NONE）、无任何加密、且包含独家【无码流出/泄露】的高清源**，无论在画质、解码开销还是直连稳定性上均全面碾压 Jable。

## 2. PROVEN SOLUTIONS (验证有效的解决方案)

针对上述 5 大核心问题，已实施经严格测试验证的闭环解法：

### 1. 构造函数级 `this.stats` 完整初始化与测速数据同步
在 `GMHlsLoader` 的 `constructor` 中严格对齐 Hls.js 官方规范初始化 `LoaderStats`，并在数据交付时同步更新 `this.stats.loading`：
```javascript
class GMHlsLoader {
    constructor(config) {
        this.config = config;
        this.request = null;
        this.abortController = null;
        // 必须在构造函数完整初始化 LoaderStats，供 frag.stats 与 bwEstimator 消费
        this.stats = {
            trequest: 0,
            tfirst: 0,
            tload: 0,
            loaded: 0,
            total: 0,
            retry: 0,
            chunkCount: 0,
            bwEstimate: 0,
            loading: { start: 0, first: 0, end: 0 },
            parsing: { start: 0, end: 0 },
            buffering: { start: 0, first: 0, end: 0 }
        };
    }
}
```
*效果*：彻底消灭 `undefined is not an object (evaluating 'stats.loading.first')`，`internalException` 归零。

### 2. 域名级失效记忆锁 (`failedDomains`) 0ms 直连原生 fetch
```javascript
// 静态记忆集，全播放生命周期共享
static failedDomains = new Set();

// load 入口检查：若当前 CDN 域名已发生过逃逸，绝不再等 15 秒，直接 0ms 走原生 fetch！
if (urlHost && GMHlsLoader.failedDomains.has(urlHost)) {
    tryNativeFetchFallback('记忆失效域极速直连');
    return;
}
```
*效果*：后续所有 1700+ 切片不再受 GM 挂起影响，直接通过浏览器原生网络栈下载，耗时由 15,000ms 暴降至 **350ms ~ 500ms**，彻底终结缓冲卡顿！

### 3. 三层转义清洗与 123AV 双通道检索
在 Go 解析器提取前彻底清洗反斜杠，并增加搜索兜底：
```go
cleanBody := strings.ReplaceAll(string(bodyBytes), `\`, "")
re := regexp.MustCompile(`https?://([a-zA-Z0-9_\-\.]+)/e/([a-zA-Z0-9_\-]+)`)
```
*效果*：`STARS-256`（多集）与 `SDMU-958`（普通版）均成功秒级提取出纯明文视频直链。

### 4. Go 服务端多路由泛兼容与客户端路径自动补全
```go
// Go 服务端全面兼容：
http.HandleFunc("/api/resolve", handleResolve)
http.HandleFunc("/resolve", handleResolve)
http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
    if r.URL.Query().Get("code") != "" {
        handleResolve(w, r)
    } else {
        handleHealth(w, r)
    }

```
```javascript
// 前端客户端自动归一化补全：

if (!cleanEndpoint.includes('/api/resolve') && !cleanEndpoint.includes('/resolve')) {
    cleanEndpoint += '/api/resolve';
```

*效果*：用户无论输入纯 IP、带端口、带斜杠或标准 API 路径，均 100% 自动对齐命中。

### 5. 动态加权优先级竞速仲裁架构 (Goroutine Priority-Weighted Arbitration)
在 Go 外部解析服务中引入加权竟态模型：
- **123AV (权重 100)**：纯明文、无加密、无码泄露版优先，一旦命中立即取消其余协程秒级返回；
- **JAVVerse (权重 90)**：纯明文、无加密、无码流出版优先；
- **Jable (权重 50)**：带 AES-128 加密，延后 400ms 错峰启动，仅在明文源未收录时兜底；
*效果*：从源头上杜绝不必要的 AES-128 软解消耗，优先享受更高清的无码纯明文流。

## 3. ANTI-PATTERNS & BANNED PRACTICES (避坑禁令与反模式)

- **FORBIDDEN: 在自定义 Hls.js Loader 中传递不完整的 `stats` 对象**
  -> **USE: 必须在构造函数与每次回调中完整初始化 `trequest, loading, parsing, buffering` 等规范字段，避免 Hls 内部事件监听器抛出 `internalException`**。
- **FORBIDDEN: 针对已知挂起的跨域 CDN，在每一个切片上盲目重复等待 15 秒 GM 超时**
  -> **USE: 必须建立域名级失效记忆锁 (`failedDomains`)，首次逃逸后永久标记该 Host，后续所有切片 0ms 直连原生 fetch**。
- **FORBIDDEN: 默认将带有 AES-128 加密且封锁 IP 的源（如 Jable）设为第一优先级**
  -> **USE: 必须优先调度纯明文（NONE）、无解密开销且支持无码流出的高画质源（123AV / JAVVerse），加密源仅作为延迟兜底**。
- **FORBIDDEN: 解析服务器仅注册单一深层 URL 路径并假设用户输入完全标准**
  -> **USE: 服务端必须注册 `/`, `/resolve`, `/api/resolve` 泛兼容路由，且客户端在发起请求前必须执行自动路径归一化**。
- **FORBIDDEN: 直接用标准正则匹配经过 HTML JSON 转义的嵌入页 URL**
  -> **USE: 必须先执行 `strings.ReplaceAll(html, `\`, "")` 消除转义反斜杠干扰后再执行正则匹配**。

```markdown
### 外部流解析与 HLS 加载器弹性自愈准则 (Stream Loader Resilience & Priority Protocol)
1. **Hls.js Loader 规范约束**：自定义 Loader 必须在 constructor 中完整初始化符合 Hls.js 官方规范的 `LoaderStats` 实例（包含 `loading, parsing, buffering` 子对象），并在数据返回时同步更新首包与完成时间戳，杜绝 `frag.stats` 为空导致的 `internalException` 崩溃；
```
